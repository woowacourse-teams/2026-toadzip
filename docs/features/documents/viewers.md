# 공고 문서 미리보기

브라우저에서 PDF·HWP·HWPX를 표시하는 기능과 자원 정리 기준이다. 백엔드의 원본 제공 계약은 [첨부파일 API](attachments.md)를 따른다.

아래 소스·설정·자산 경로는 `frontend/` 기준이다.

## 화면과 상호작용

### 파일 선택과 다운로드

- 하단 `공고문 보기`는 미리보기 모달을 연다. 버튼 옆에 공고문 제목·파일 개수를 중복 표시하지 않는다. 파일 하나면 즉시 표시하고, 여러 개면 파일명과 공고문·참고자료 구분을 보고 사용자가 선택한다. 원공고와 정정공고 중 임의로 하나를 열지 않는다.
- 상세 하단의 첨부파일 목록은 개수와 함께 기본 접힘으로 표시한다. 펼친 목록의 동작은 `다운로드`로 명시한다. 파일이 하나여도 다운로드 경로를 제공한다.
- `첨부파일 연결됨`, `원문 연결됨` 같은 내부 연결 상태는 표시하지 않는다. 사용할 수 없는 버튼의 비활성과 파일 오류 안내는 유지한다.
- 미리보기 모달의 `파일 목록`과 `다운로드`에는 [디자인 시스템의 채움 Button](../../development/frontend/design-system.md#button과-iconbutton)을 사용한다.
- PDF에는 `PDF 새 창에서 보기`도 제공한다. 미지원 형식은 다운로드를 안내하고 자동으로 내려받지 않는다.

### 문서 표시와 검색

- PDF·HWP·HWPX는 페이지를 세로로 이어 표시하고 크기 조절과 화면 주변 페이지 우선 렌더링을 제공한다. PDF는 너비 맞춤과 텍스트 선택을, HWP·HWPX는 현재 쪽수와 접힌 영역의 현재 페이지 일반 텍스트 확인·복사를 제공한다.
- `검색` 또는 모달 안의 `⌘F`/`Ctrl+F`로 전체 문서를 검색하고 결과와 현재 위치를 강조한다. Enter/Shift+Enter는 다음/이전 결과로 이동하고 검색 중 Escape는 검색창만 닫는다. 검색 단축키는 현재 모달에만 적용한다.
- 텍스트가 없는 스캔 PDF는 검색할 수 없다. HWP·HWPX의 검색 범위와 원본 재현 한계는 아래 [HWP·HWPX 미리보기](#hwphwpx-미리보기)의 조건을 따른다.

### 스크롤과 목차

- PDF·HWP·HWPX 본문의 스크롤바는 스크롤하는 동안 표시하고, 마지막 움직임 이후 잠시 기다렸다가 숨긴다. 목차 막대는 그보다 안쪽에 둔다.
- PDF 내장 목차와 HWP·HWPX 개요 메타데이터가 있는 문서는 오른쪽 스크롤바 왼쪽에 약 12px 간격을 두고 배경·테두리 없는 목차 막대를 표시하며 현재 항목은 짙은 막대로 구분한다. 하위 제목의 막대는 짧게 표시한다. 마우스를 올리거나 키보드로 포커스하면 막대가 사라지고 같은 위치에서 왼쪽으로 제목 목록이 부드럽게 펼쳐진다. 목록을 닫으면 막대가 다시 나타나며, 터치와 키보드로도 열 수 있다. 모션 줄이기 설정에서는 전환을 생략한다. 닫힌 목록은 키보드 탐색과 스크린 리더에서 제외한다. 화면이 좁아져도 같은 막대 모양을 유지하며 터치로 목록을 열 수 있다. 항목을 누르면 문서 위치로 이동하고 현재 구간을 강조한다. 목차에서 Escape는 목록만 닫는다. 목차가 없거나 추출하지 못하면 표시와 여백을 추가하지 않으며, 본문 분석으로 제목을 추정하지 않는다.

## PDF 미리보기

공고 첨부파일은 브라우저 내장 PDF 플러그인 없이 확인할 수 있도록 `pdfjs-dist` legacy 빌드를 모달을 열 때 지연 로딩한다. native iframe은 앱 내 브라우저에서 빈 화면이 확인되어 채택하지 않았다. 라이선스는 Apache-2.0이며 버전은 package.json/lock에 고정한다.

PDF를 선택하면 원본 파일 요청과 동시에 뷰어 컴포넌트·코어를 불러오고 코어 초기화 후 web viewer 모듈을 미리 준비한다. 같은 동적 import를 재사용해 초기 화면이나 한글 문서에는 PDF 코드를 추가하지 않는다. 사전 로딩 실패는 원본 수신을 막지 않으며 렌더링 시 다시 로딩을 시도한다. worker 생성·문서 해석은 원본 Blob 수신 후 시작하므로 기존 파일 전환·닫기 정리를 유지한다. 이 최적화는 첫 열람의 코드 로딩 대기를 겹치며 파일 전송 시간 자체를 줄이지 않는다.

`npm run dev`와 `npm run build`의 pre 스크립트가 `scripts/prepare-pdf-assets.mjs`를 실행해 설치 버전의 CMap, 표준 폰트, WASM 및 라이선스를 `public/pdfjs-{version}/`에 준비한다. 생성 디렉터리는 Git에서 제외되지만 dist에는 포함된다. PDF.js 교체·제거 경계는 PdfDocumentPreview 컴포넌트와 이 자산 준비 스크립트다.

배포 Nginx는 [`nginx/`](../../../frontend/nginx/)의 HTTP·HTTPS 설정에서 `.mjs`를 `application/javascript`로 제공해야 한다. PDF worker가 `application/octet-stream`으로 응답하면 첨부 API가 성공해도 브라우저의 모듈 MIME 검사에서 미리보기가 실패한다. 설정 변경은 프론트 이미지를 다시 빌드하고 컨테이너를 재생성해 반영한다. `/assets/`의 기존 잘못된 MIME 응답도 장기 캐시되므로 worker URL에 `mime=javascript` 쿼리를 붙여 이전 캐시를 우회한다. 이 쿼리는 캐시 키를 바꾸는 용도이며 응답 형식은 Nginx의 MIME 매핑이 결정한다. 배포 후 페이지를 새로고침하고 worker 요청의 `Content-Type`을 확인한다.

`usePdfViewer`는 PDFViewer의 연속 스크롤·렌더 버퍼와 PDFFindController의 전체 문서 검색·텍스트 강조를 연결한다. build 모듈 초기화 후 web viewer를 읽고, 문서 해제·AbortSignal·지역화 객체·worker를 함께 정리한다. SDK 스타일은 `@scope` 안에 두어 전역 색상과 다른 화면에 영향을 주지 않는다. PDF 스크립트와 폼 편집은 활성화하지 않는다.

## HWP·HWPX 미리보기

`@rhwp/core` 0.8.6(MIT)을 사용한다. 브라우저에서 한글 원본을 해석하며 외부 변환 서비스로 업로드하지 않는다. HwpDocumentPreview를 지연 로딩하고 별도 worker에서 WASM을 초기화한다. 약 9.94 MB의 WASM은 한글 문서를 처음 열 때만 내려받고 Vite 해시 자산으로 캐시한다. 라이선스는 pre 스크립트가 `public/rhwp-{version}/LICENSE`로 복사한다. SDK를 제거하거나 교체하는 경계는 이 컴포넌트, worker와 자산 준비 스크립트다.

기존 원본 다운로드 API(`download=true`)를 이용하며 PDF 전용 미리보기 API의 형식 검증은 유지한다. 페이지별 SVG는 Blob 이미지로 표시하고 문서의 마크업을 DOM에 삽입하지 않는다. 쪽 크기에 맞춘 자리 표시자를 세로로 배치하고 화면에 보이는 쪽과 앞뒤 한 쪽만 SVG 이미지로 유지한다. 현재 쪽은 스크롤 위치를 기준으로 표시한다. 멀어진 이미지 URL은 즉시 해제하며 파일 전환·닫기·실패 시 worker, URL과 타이머를 정리한다. 문서 해석·전체 검색은 60초, 한 쪽 렌더링은 30초 제한을 둔다.

worker가 페이지별 텍스트 위치를 읽어 표 안의 텍스트와 같은 문단의 서식 run을 검색하고 좌표를 반환한다. 대소문자와 연속 공백은 정규화하며 서로 다른 표 셀은 합치지 않는다. 결과 수를 표시하고 다음/이전 결과 이동은 순환한다. 한글 IME 조합 중에는 검색하지 않으며 200ms 입력 지연 처리와 검색 ID로 오래된 결과를 배제한다. worker는 쪽마다 실행을 양보해 새 검색과 화면 렌더링을 처리한다. 이미지 속 글자(OCR), 페이지 경계를 가로지르는 검색어는 검색 대상이 아니다.

실제 부산문현 LH HWPX 공고문과 관세청 공개 HWP에서 한글·표·이미지와 페이지 이동을 확인했다. 원본 글꼴이나 페이지 나눔은 달라질 수 있으며 이 한계를 사용자에게 안내한다(동일 LH 공고 PDF 53쪽, HWPX 뷰어 55쪽). 암호·손상·지원되지 않는 HWP 구조 및 구형 브라우저에서는 다운로드로 안내한다. ZIP·DOCX·XLSX 등은 미리보기 대상이 아니다. 검증한 버전은 고정하며 라이브러리 교체 시 실제 문서 검증을 다시 수행한다.

첨부 API 대기 시간은 서버 외부 다운로드 제한 120초를 포함하도록 150초다. 파일 한도의 기본값은 100 MiB이며 백엔드 `ANNOUNCEMENT_ATTACHMENT_MAX_SIZE`로 조절한다.

PDF·HWP·HWPX 미리보기를 위해 받은 원본 Blob은 선택한 첨부파일이 소유하며 다운로드에도 그대로 재사용한다. 렌더링 결과를 저장하거나 원본 바이트를 변환하지 않고, 첨부파일의 원래 파일명을 사용한다. Blob이 아직 없거나 미리보기 요청이 실패한 경우에만 기존 다운로드 API를 호출한다. 미리보기 로딩 중에는 별도 다운로드 요청이 발생할 수 있다.

파일 전환·모달 닫기 시 미리보기 요청과 URL, 선택 상태의 Blob 참조를 정리한다. 사용자가 시작한 다운로드 API 요청은 닫기와 무관하게 기존 150초 제한까지 계속 진행한다. 다운로드는 미리보기와 별도의 객체 URL을 사용하므로 미리보기 정리가 다운로드를 무효화하지 않는다. 다운로드 완료 이벤트는 제공되지 않으므로 브라우저가 읽기를 시작할 여유를 두고 60초 후 해당 URL을 해제한다. 이미 시작된 읽기는 URL 해제로 중단되지 않는다.
