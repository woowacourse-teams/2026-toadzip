# 관리자 사용 가이드

## 작업공간과 수집 도구

관리자 기본 진입은 `운영 홈`이다. 왼쪽 메뉴의 매일 하는 작업에서 검토·단지·공고·누락 대조를 연다.
수집·원천 도구와 회원·알림 메뉴는 펼쳐서 사용하며, 해당 경로로 직접 접근하면 소속 그룹이 열린다.
모바일에서는 `메뉴`로 탐색을 열고 Escape 또는 다른 페이지 이동으로 닫는다.

### 데이터를 확인하고 수정하기

- 검토 작업실에서 확인할 대상을 찾는다. 빠른 조건·이름·대상·사유 필터는 URL에 남는다.
- 목록의 결과 수는 현재 검색 조건의 총 개수다. 현재 페이지 항목으로 전체 통계를 추정하지 않는다.
- 단지·공고 일반 상세는 읽기로 진입한다. `수정`으로 입력을 열고 저장·취소 후 읽기로 돌아온다.
- `데이터 검증`은 공식 원천 비교, 공고의 `공고문·첨부파일`은 연결된 원문 확인이다.
- `section=verification`, `documents` 등 상세 링크의 작업 위치를 직접 열 수 있다.
- `출처·수정 이력`에서 처리자·시각·근거와 변경 전후를 확인한다. 충돌·미저장 입력 보호와 원천 확인 기준은 유지한다.

### 공고문과 JSON

공고의 `공고문·첨부파일`에서 기존 첨부파일을 미리보기·다운로드한다.
PDF 추출·OCR·작업 초안·폴더 에이전트 연동은 제공하지 않는다.
`공고 추가 → JSON 가져오기`와 기존 공고의 `JSON으로 갱신`은 같은 `admin-announcement-import/v1` 형식이다.
기존 공고에서는 기본정보·접수처·일정·첨부·공급정보의 현재값과 추출값을 비교해 선택 적용한다.
null·누락·미확인과 선택하지 않은 기존 항목은 유지한다. `section=json` 링크로 바로 열 수 있다.
공급정보만 입력하는 보정 전용 형식은 `공급정보·단지 연결`에 별도로 안내한다.
전체 예제·필드 형식·단위·미확인 값 처리와 복사 가능한 Codex 요청문을 제공하며 자동 전송·저장은 없다.

### 수집·정제

`공고 수집`(`/admin/ingest/announcements`)과 `단지 수집`(`/admin/ingest/complexes`)을 독립 메뉴로 제공한다.
기존 `/admin/ingest`와 `/admin/ingest-v2` 주소는 도메인에 맞는 화면으로 이동한다.
공고 수집은 마이홈·SH 카드에서 최근 실행과 결과를 확인한다. 마이홈 다건 갱신은 LH 정보 보강을 포함하며,
SH 수집은 제목·본문·첨부 원천을 저장한다. SH의 서비스 공고 등록·정제는 포함하지 않는다.

마이홈 다건 갱신은 API 키 입력 → 실행 접수 확인 → 실행 중 단계 → 결과 순서다.
접수 확인과 서버 실행 중 상태를 구분하며 화면을 나갔다 들어와도 서버의 실행 상태를 다시 조회한다.
LH 품질과 공급 감소 보류 정보는 공고 수집의 보조 영역에서 펼쳐 확인한다.
이 지표는 LH 대상이며 전체 기관의 품질이나 이번 실행의 성공률을 뜻하지 않는다.

단지는 원천 수집 → 필요한 좌표 ZIP 적재 → 단지 정제 순서로 준비한다.
공고 한 건의 마이홈 URL·ID 가져오기는 `공고 추가 → 마이홈 공고 가져오기`에서 수행한다.
직접 주소는 `/admin/announcements/new?mode=myhome`이다.
화면은 분리되어도 수집·정제·단건 가져오기의 한 작업 실행 잠금은 공유한다.

디자인은 기존 사용자용 화면의 토큰·Button을 사용한다. 관리자 스타일은 관리자 영역에만 적용한다.

## 검토 절차

변경·검토 이력에서 실제 처리한 관리자와 시각을 확인한다.

### 1. 검토할 대상을 찾기

`검토할 데이터`에서 단지·공고와 검토 사유를 선택한다. 빠진 항목을 보고 `비교·검토`를 누른다.
빠른 조건으로 원천 변경·정보 누락·보류를 좁힐 수 있다. 상세 조건에서 원천 식별자·공고 ID·단지 ID·기관·모집상태로 찾는다. 조건과 페이지는 상세에서 복귀할 때 유지한다.
일반 단지·공고 목록에서 연 상세는 읽기 화면으로 시작하며 `수정`을 눌러 편집한다.
검토 목록의 `비교·검토`와 문제 항목 링크는 사유에 맞는 상세 탭으로 바로 이동한다.
상세 탭은 URL의 `section`에 남으며 원천 변경 사유에서도 해당 비교 위치로 이동할 수 있다.
0·미설치는 빠진 값으로 간주하지 않는다. 원천에 없는 값은 추정해 채우지 않는다.

### 2. DB 원천과 비교·수정

- 단지 기본정보: 기존 `데이터 검증`에서 바로 비교한다.
- 주택형: 같은 화면의 `주택형 원천 비교·수정`을 펼친다.
- 공고: `데이터 검증`에서 공고 기본정보·공급행·공급대상 임대조건을 선택한다.
- 자동 연결된 원천을 확인하고 필요한 자료는 `원천 검색·연결`에서 근거를 적어 연결한다.
- `이 원천값 사용` 또는 직접 입력 후 변경 전후·근거를 확인해 저장한다.
- 공고의 공급행·임대조건은 여기서 비교·원천 확인만 하고, 값 수정은 `공급정보·단지 연결`로 이동해 미리보기·일괄 적용·범위 검토를 거친다.
- 금액 문자열의 단위와 적용 범위는 직접 확인한다. 단지 전체 세대수를 주택형 세대수에 적용하지 않는다.
- 충돌하면 입력은 남고 저장은 잠긴다. 필요한 입력을 보관한 뒤 다시 조회해 대조한다.

### 3. 공식 목록과 단지 누락 조사

`단지 누락 대조`의 `공식 API 자료로 목록 준비하기`를 연다.
필요하면 공식 단지 API 수집을 요청하고 상태를 확인한다. 서버 API 키 설정은 기존 수집 운영 화면을 따른다.
`저장 자료 불러오기`에서 기관·이름·주소를 확인하고 현재 페이지를 대조 목록으로 가져온다.
기존 수기·JSON 입력과 같은 대조를 실행해 미등록·동일성 검토·휴지통·조회 실패 후보를 조사한다.

마이홈 단지 API의 이름·도로명주소가 있는 자료를 지원한다. 같은 페이지의 주택형 중복은 제거한다.
목록 기준일은 마지막 수집일이며 공식 문서의 유효일을 의미하지 않는다.
`검색 범위 전체 가져오기`는 최대 250쪽·5,000행을 두 번 조회해 페이지 간 중복과 조회 중 변경을 확인한다.
전체 가져오기 결과는 50개를 넘어도 순차 대조한다. 검색 조건은 유지하며 주소·시각 미확인 제외 건수를 표시한다.
조회 실패·중지·한도 초과·조회 중 변경이면 불완전한 목록을 전달하지 않는다. DB 저장 범위의 조회이며 기관의 공식 전체 목록 완전성을 보증하지 않는다.
LH 공고 상세와 LH 임대 단지 목록도 선택할 수 있다. 이름이 있는 주소 미제공 행은 후보 조사 대상으로 보존한다.
도로명주소가 없으면 이름으로 검색하되 일치나 미등록으로 확정하지 않는다. 지번주소·접수처 주소를 도로명주소로 자동 변환하지 않는다.
결과의 `이 단지 주소 보완 후 다시 대조`에서 공식 원문의 도로명주소를 보완한다.
다른 기관 홈페이지에서 내려받은 UTF-8 CSV·TSV나 표 붙여넣기도 지원한다. 출처 URL·기준일·기관을 입력하고 제목 행을 포함한다.
`단지명`(또는 아파트명·주택명·name·hsmp_nm·complex_name·complex_label), `도로명주소`(또는 소재지도로명주소·roadAddress·rn_adres)를 읽는다.
일반 `주소`·지번주소 열은 도로명주소로 추정하지 않는다. CSV·TSV는 최대 5,000행·1MB이며 잘못된 열 수·따옴표·중복은 오류로 표시한다.
공고 홈페이지 수집은 `수집·정제`에서 지원하는 기관 경로를 사용한다.

### 4. 공고문 확인과 JSON 입력

공고 상세의 `공고문·첨부파일`에서 공식 원문 링크와 이미 연결된 첨부파일을 연다.
공개 상세와 같은 PDF·HWP 미리보기를 사용한다. 별도 업로드·텍스트 추출·OCR·폴더 에이전트 설정은 없다.
이 기능을 통해 PDF 원본이나 작업 초안을 서버에 추가 보관하지 않는다.

Codex에 공식 자료와 화면의 요청문을 직접 전달해 JSON을 작성할 수 있다. 복사 버튼은 클립보드만 사용하며
Codex를 실행하거나 파일을 자동 전송하지 않는다. 자동 생성 결과는 원문과 대조한다.

- 신규 원공고: `공고 추가 → JSON 가져오기`의 전체 예제·필수 항목·유형 코드 안내를 따른다.
  계약은 [신규 공고 JSON 등록](announcement-import.md)을 참고한다.
- 기존 공고 전체: `공고 상세 → JSON으로 갱신`에서 신규 등록과 같은 v1 JSON을 사용한다. 기본정보·접수처·일정·첨부·공급정보를 비교해 선택 갱신한다. 미확인·null·누락 값은 기존값을 유지하며 원천 식별자를 교체하지 않는다. 공급행·조건의 대응 확인 후 변경안에 가져오고, 근거·전체 미리보기 확인을 거쳐 적용한다. 미리보기 후 수정이 있으면 최신값으로 다시 비교한다.
- 기존 공고 공급정보만 입력: `공급정보·단지 연결 → 구조화한 공급정보를 변경안으로 가져오기`의 보정용 예제를 사용한다.
  금액은 원 단위 숫자 문자열, 면적은 ㎡ 숫자다. 생략은 기존값 유지, null은 미확인으로 변경, 0은 확인된 0이다.
  기존 조건은 화면에 표시된 조건 ID로 수정하며 ID를 생략하면 새 조건을 추가한다.
  입력행의 적용 대상을 직접 선택하고 변경 미리보기·근거 확인 후 최종 적용해야 저장된다.

공고 전체 v1 형식과 공급정보 보정 전용 형식은 필드 이름이 다르므로 각 입력 화면의 예제를 사용한다.

### 5. 다음 수집의 변경 확인

원천을 확인하고 수정할 값이 없으면 근거를 적어 `현재 원천 확인 기록`을 누른다.
다음 수집 이후 확인했던 원천의 값이 바뀌거나 사라지면 `검토할 데이터 → 원천 변경·소실`에 나타난다.
현재값을 유지할지 수정할지 검토하고 새 원천 확인 기록을 남긴다. 값 수정·등록값 검토 기록은 별개다.

서버 계약은 [관리자 데이터 검토 흐름](review-api.md),
기존 흐름은 [DB 단지 비교](guide.md#단지-기본정보-비교)을 참고한다.

### 6. 공급정보를 공고 단위로 보정

공고 상세의 `공급정보·단지 연결`에서 행과 대상별 조건을 함께 수정한다.
행 추가·제외·복원, 단지·주택형 연결, 공고별 명칭·면적·모집수와 순서를 변경할 수 있다.
공통 주택형이 없으면 `이 단지의 주택형 확인 → 누락된 주택형 만들기`로 생성과 연결을 함께 요청한다.
공고 모집수는 단지·주택형 전체 세대수에 반영하지 않는다. 빈 수량·금액은 미확인, 숫자 0은 확인된 0이다.
대상 모집수가 중복 없이 행 모집수와 같은 범위일 때만 수량 합계 확인을 선택한다.

공식 근거 URL·페이지·이유를 적고 `변경 미리보기 → 확인한 보정 일괄 적용`을 진행한다.
원천·연결 후보·등록값이 달라지면 적용을 거절한다. `입력을 유지하고 최신값 비교`에서 겹치는 항목을 선택한다.
응답 유실 시 같은 작업으로 결과를 확인한다. 이 탭의 새로고침 후에도 작업을 복원하며,
브라우저 저장 공간에 재확인 정보를 보관하지 못하면 적용을 시작하지 않는다.
일반 작성 중 입력을 자동 저장하는 기능은 아니므로 이동·새로고침 경고를 확인한다.

`구조화한 공급정보를 변경안으로 가져오기`는 각 입력행의 대응을 직접 지정한다.
면적 단위는 `m2`, 금액 단위는 `KRW`이며 금액은 원 단위 정수 문자열이다.
생략한 행·항목·조건은 유지하고 `null`은 미확인으로 변경한다. 가져온 뒤에도 같은 미리보기·근거 확인을 거친다.

저장 후 사용자 공고 화면과 남은 문제를 확인한다. 적용으로 바뀐 행·조건은 표시 순서대로 검토한다.
공급행에 대응하는 마이홈·LH 공급 원천을 확인하며, 대응 근거가 부족하면 임의로 연결하지 않는다.
`저장된 공급정보 검토·보류`에서
확인한 행·조건과 필드만 선택하고 판단·근거를 기록한다. 선택한 원천 필드는 실제 값 변경·소실을 추적하며,
선택하지 않은 원천이나 외부 원문 자체의 변경을 자동 판정하지 않는다.
기록은 누적하고 같은 대상의 최신 기록을 현재 판단으로 사용한다. 보정 저장은 전체 검토 완료가 아니다.

보정한 행의 원천이 사라지거나 비활성화되면 값을 유지하고 검토 목록과 작업실에서 재확인을 안내한다.
공통 주택형 수정은 별도 화면에서 영향을 받는 공고를 확인한다. 이미 면적을 검토한 공고가 있으면
그 공고의 당시 면적을 별도로 보호한 다음 공통 면적을 수정한다.
조건부 보정 되돌리기, 전체 보정 보호 해제·원천값 채택, 일반적인 행 합치기·조건 이동은 아직 제공하지 않는다.

### 7. 운영 홈·의견·알림 조사

로그인 후 운영 홈에서 수집·정제 실패, 데이터 검토, 접수 의견과 알림 발송 문제로 이동한다.
일부 집계가 실패하면 0건으로 표시하지 않고 해당 영역에서 다시 확인하도록 안내한다.
오류·검토 목록에서 상세로 들어갈 때 검색조건·페이지와 선택 대상을 유지한다.

사용자 의견은 상태·관련 단지/공고·처리 결과를 기록하고 실제 처리한 관리자와 시각을 자동으로 남긴다. 보류와 처리 완료에는 이유가 필요하다.
내부 처리 기록이며 사용자에게 메시지를 발송하지 않는다. 동시 변경은 입력을 유지하고 최신 기록과 비교한다.

알림 발송 내역은 회원·공고·상태로 조회한다. 공급자 수락, 사용자 읽음, 발송 내역 없음은 서로 다른 상태다.
실패 코드·시도 횟수·다음 재시도 시각을 확인하며 이 화면에서 알림을 재발송하지 않는다.

## 단지 기본정보 비교

1. 관리자 단지 목록에서 대상을 연 뒤 `데이터 검증` 탭을 선택한다. 검토 목록의 비교 링크는 해당 탭으로 바로 진입할 수 있다.
2. 자동 정제에 연결된 마이홈 원천이 있으면 현재 등록값 옆에 바로 표시한다.
3. 추가 자료는 `원천 검색·연결`에서 마이홈 단지 또는 LH 임대 단지를 검색한다.
   `연결 전 원천 확인`으로 이름·주소·공급 범위를 살펴보고 근거를 적어 연결한다.
4. `값이 다른 항목`으로 좁히고 `이 원천값 사용` 또는 항목별 `수정`을 누른다.
   여러 원천이 다르면 각각 표시하며 대표값을 자동으로 선택하지 않는다.
5. 저장할 변경 전후와 수정 근거·메모를 확인하고 `수정사항 저장`을 누른다.
6. `출처·수정 이력`에서 바뀐 값과 당시 DB 원천을 확인한다.

조회·비교에는 파일이나 수기 값 입력이 필요하지 않다. 원천 연결·수정·검토 기록을
저장할 때에는 관리자가 확인한 근거를 남긴다. DB 원천은 수집 당시 자료이며 실시간 공식 정보는 아니다.

### 범위와 보호

- 비교: 단지명·기관·공급유형·준공일·세대수·주차대수·난방·건물·복도 유형·엘리베이터.
- 원천에 없는 최근 퇴거자 수·이미지·좌표 등은 미제공으로 표시하고 직접 수정할 수 있다.
- LH 단지 전체 세대수와 주택형 세대수를 구분한다. 단위·공급 범위는 사람이 확인한다.
- 주소·PNU·지역 코드·좌표는 접힌 주소 영역에서 함께 확인·수정한다.
- 직접 연결은 비교용이며 자동 정제의 단지 연결이나 통합을 바꾸지 않는다.
- 원천이 재수집으로 사라지면 연결을 유지한 채 현재 원천 없음으로 표시한다.
- 저장 충돌은 수정값을 유지한다. 필요한 값을 메모한 뒤 `비교 데이터 다시 조회`로 재검토한다.
- 수정과 확인 범위·검토 기록은 동시에 작성하지 않도록 잠근다. 저장 또는 취소하면 다른 작업이 열린다.
- 값 수정만으로 검토 완료가 되지 않는다. `확인 범위·검토 기록`에서 실제 확인한 항목만 기록한다.
- 공고문은 공고 상세의 `공고문·첨부파일`에서 확인하고 필요한 값을 편집 화면에 입력한다.

이 문서는 단지 기본정보 비교를 설명한다. 공고·주택형·임대조건 비교와 재수집 대비 원천 확인은
[관리자 데이터 검토 흐름](guide.md#검토-절차)을 참고한다.
서버 계약과 마이그레이션은 [단지 원천 비교](review-api.md#단지-기본정보-비교와-수정)를 참고한다.
