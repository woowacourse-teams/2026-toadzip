# 사용자 의견 접수

- 의견은 앱 안에서 서술형 한 칸으로 받는다. 의견 보내기는 탐색·마이페이지 위의 모달로 열고, 이용 중 불편했던 점이나 더 나아졌으면 하는 점을 자유롭게 적게 한다. 객관식 설문은 두지 않는다.
- 의견 내용은 필수이며 2,000자까지 입력할 수 있다. 빈 의견·공백만 담긴 의견은 보내지 않고 입력칸으로 초점을 옮긴다. 전송 중에는 중복 제출과 닫기를 막고, 실패하면 작성한 내용을 보존한다. 접수되면 완료 안내를 보인다.
- 닫기와 Escape는 원래 화면으로 돌아간다. 데스크톱은 배경 클릭으로도 닫히며 모바일은 배경 클릭으로 닫히지 않는다. `/feedback` 직접 접근도 지원한다.
- 탐색 화면에 머문 뒤 10초가 지나면 작은 의견 요청을 띄운다. 레일이 보이는 넓은 화면은 레일의 의견 보내기 옆에, 모바일 배치는 오른쪽 아래에 둔다. 안내를 닫거나 선택하거나 의견 창을 열면 같은 브라우저 세션에서 다시 띄우지 않는다. 숨은 탭에는 새 안내를 띄우지 않는다.

## 의견 접수 API

- `POST /api/v1/feedback`: 로그인 없이 `{ "content": "의견 내용" }` 제출
- `GET /api/auth/csrf`에서 받은 토큰을 요청 헤더에 전달한다. 기존 CSRF 보호를 유지한다.
- 의견 내용은 필수이며 양끝 공백을 제거한 UTF-16 기준 1~2,000자다. 내부 줄바꿈은 보존한다.
- NBSP·좁은 NBSP·BOM을 포함한 양끝 공백도 제거하며, 누락·null·공백만 담긴 의견은 `400`으로 거절한다.
- 객관식 설문은 받지 않는다. 요청에 `surveyAnswer`가 있어도 무시한다.
- 성공은 `201`과 `{ "data": { "id": 1 } }`, 검증 실패는 기존 `VALIDATION_FAILED` 오류 계약이다.
- 본문과 UTC 접수 시각을 저장한다. 회원 ID, 이메일, IP, 화면 URL을 별도로 수집하지 않는다.
- 공개 조회 API는 제공하지 않는다. 화면에서는 개인정보 입력을 피하도록 안내한다.

## 배포와 복구

- `V20261007_01__create_feedback.sql`은 새 테이블과 최신순 조회 인덱스만 추가한다.
- Flyway 적용 후 Hibernate validate와 애플리케이션 시작이 진행된다.
- `V20261104_05__feedback_survey.sql`이 추가한 `survey_answer` 컬럼과 이미 수집한 설문 값은 DB에 보존한다. 애플리케이션은 더 이상 이 컬럼을 읽거나 쓰지 않으며, 새 의견은 본문이 필수라 `ck_feedback_response` 제약을 항상 만족한다.
- 설문 제거는 마이그레이션 없이 백엔드 → 프론트엔드 순서로 배포한다. 이전 서버로 복구하면 설문이 필수라 새 화면의 제출이 `400`으로 거절되므로 프론트엔드도 함께 복구한다.
- 운영 DB에 수동 SQL을 실행하거나 접수된 의견을 삭제하는 작업은 이번 구현 범위에 포함하지 않는다.

## 관리자 조회

- `GET /api/admin/feedback?keyword=검색&page=0&size=20`은 ADMIN 세션만 접근할 수 있다.
- 검색어는 최대 200자, page는 0 이상, size는 1~100이며 기본값은 20이다.
- 본문을 대소문자 구분 없이 검색한다. `%`, `_`, `!`는 와일드카드가 아닌 입력 문자로 취급한다.
- `createdAt DESC, id DESC`로 정렬한다. `createdAt`은 UTC ISO 8601 시각이며 관리자 화면은 한국 시각으로 표시한다.
- 응답은 `data` 안에 `items`, `page`, `hasNext`, `totalElements`, `totalPages`를 포함한다.
- 각 항목은 `id`, 전체 `content`, `createdAt`과 기존 처리 기록을 포함한다. 설문 답변은 응답에 포함하지 않는다. 범위 밖 페이지도 전체 검색 건수를 보존한다.
- 검색 건수를 먼저 확인하므로 매우 큰 범위 밖 페이지도 JPA offset 제한에 걸리지 않고 빈 목록을 반환한다.
- `GET /api/admin/feedback/counts?keyword=검색`은 같은 검색 조건(ADMIN 전용, 최대 200자, 같은 매칭 규칙)에 맞는 의견의 상태별 건수를 한 번에 반환한다. `data`에 `OPEN`, `IN_PROGRESS`, `ON_HOLD`, `DONE`을 항상 포함하고 없는 상태는 0이며 `total`은 네 건수의 합이다.
