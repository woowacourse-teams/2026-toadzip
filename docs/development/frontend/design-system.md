# 프런트엔드 디자인 시스템

현재 공공주택 복덕방의 사용자용 공고·단지 검색 화면을 기준으로, 새 화면에 같은 토큰과 컴포넌트를 적용하기 위한 문서다.
UI 작업 전에 이 문서에서 기존 사용처를 찾고, 해당 코드와 가까운 테스트를 함께 읽는다.

## 원본과 적용 범위

| 대상 | 원본 |
|---|---|
| 색·글자·간격·컨트롤 크기 | [tokens.css](../../../frontend/src/design-system/tokens.css) |
| 주 행동 버튼 | [Button](../../../frontend/src/design-system/components/Button.tsx), [스타일](../../../frontend/src/design-system/components/Button.module.css), [테스트](../../../frontend/src/design-system/components/Button.test.tsx) |
| 아이콘 버튼 | [IconButton](../../../frontend/src/design-system/components/IconButton.tsx), [스타일](../../../frontend/src/design-system/components/IconButton.module.css), [테스트](../../../frontend/src/design-system/components/IconButton.test.tsx) |
| 앱·지도·목록 레이아웃 | [index.css](../../../frontend/src/index.css) |
| 기능별 UI와 업무 표시 규칙 | 아래 서비스 패턴의 코드·테스트 |

토큰은 `index.css`에서 한 번 로드한다. 실제 값을 문서나 별도 JSON에 복제하지 않는다.
컴포넌트별 CSS Modules에서 토큰을 사용하고, 화면 상태는 가장 가까운 기능 컴포넌트가 소유한다.
현재 버전은 같은 프런트엔드 저장소에서 관리하며 Storybook, Figma 동기화, 별도 견본 사이트는 포함하지 않는다.
관리자 페이지의 디자인은 이 시스템의 참고 기준이나 공통 UI 추출 대상에 포함하지 않는다.
관리자 화면의 스타일을 사용자용 화면에 가져오지 않는다. 지도 SDK 구현도 이번 추출 범위에서 제외한다.

## 토큰 선택

| 역할 | 사용할 토큰 |
|---|---|
| 밝은 브랜드 채움·그 위의 글자 | `--ds-color-brand`, `--ds-color-on-brand` |
| 링크·초점·작은 강조 | `--ds-color-action` |
| hover·선택한 목록 배경 | `--ds-color-action-soft`, `--ds-color-action-selected` |
| 본문·항목 이름·보조 글자 | `--ds-color-text`, `--ds-color-label`, `--ds-color-muted` |
| 표면·보조 표면·구분선 | `--ds-color-surface`, `--ds-color-surface-subtle`, `--ds-color-divider` |
| 접수 상태·기관·마감 표시 | `--ds-color-status-*`, `--ds-color-agency-*`, `--ds-color-deadline` |
| 기관 약칭의 글자색 | `--ds-color-agency-{lh,sh,gh}` |
| 목록·필터 글꼴과 제목·본문·설명·금액 | `--ds-font-family-ui`, `--ds-text-*`, `--ds-line-height-*` |
| 반복 간격·버튼 모서리·컨트롤 크기 | `--ds-space-*`, `--ds-radius-*`, `--ds-control-*`, `--ds-icon-*` |
| 페이지 배경·전역 기본 글자·기본 테두리 | `--ds-color-page`, `--ds-color-text-base`, `--ds-color-muted-base`, `--ds-color-border-base` |
| 아이콘 버튼 hover·브랜드 채움 hover | `--ds-color-control-hover`, `--ds-color-brand-hover` |
| 상세 섹션 구분·표 머리·표 선 | `--ds-color-section-divider`, `--ds-color-table-heading`, `--ds-color-table-line` |
| 접수 상태 배지 크기·여백·모서리 | `--ds-status-badge-*` |
| 공개 지도 화면의 패널 폭·여백 | `.app-shell`의 `--explorer-*` (tokens.css에서 정의) |

`--ds-color-text`·`--ds-color-muted`는 탐색 화면용, `--ds-color-text-base`·`--ds-color-muted-base`는
`:root` 기본값과 랜딩·정책 페이지용으로 값이 다르다. 한 화면 안에서 두 계열을 섞지 않는다.

현재 초록색 브랜드, 앰버색 공고중 배지, 파란색 접수중 배지는 서로 다른 역할이다. 같은 색상값을 쓰는 경우에도
역할이 다른 토큰을 임의로 합치지 않는다. 기관색을 행동 버튼이나 접수 상태에 사용하지 않는다.
공고·단지 목록, 상세, 최근 본 단지의 기관 약칭은 배경 없이 기존 기관 원색(`--ds-color-agency-*`)으로 표시한다.
지도 마커도 같은 기관색을 사용하며 별도의 어두운 글자색이나 연한 배지 바탕을 추가하지 않는다.
밝은 브랜드색을 작은 글자나 포커스에 직접 쓰지 않고 읽기 쉬운 action 색을 사용한다.

```css
.summary {
  padding: var(--ds-space-4);
  background: var(--ds-color-surface);
  color: var(--ds-color-text);
  font-family: var(--ds-font-family-ui);
  font-size: var(--ds-text-body);
  line-height: var(--ds-line-height-body);
}
```

기존 전역 `--brand`, `--focus`, `--surface`와 목록의 `--list-*`는 호환 별칭이다.
새 공통 표현에는 `--ds-*`를 사용하되, 목록 여백처럼 부모가 좁은 폭에 맞춰 바꾸는 값은
`--list-inset`을 계속 소비한다. 위치 계산, 이미지 비율, 한 화면에만 쓰는 치수까지 전부 토큰화하지 않는다.

## 타이포그래피

사용자·관리자 화면과 거리뷰 페이지의 글꼴은 Pretendard GOV Variable 하나다. KRDS 기본 글꼴과 같은 계열이다.

| 항목 | 기준 |
|---|---|
| 로드 | [tokens.css](../../../frontend/src/design-system/tokens.css)가 npm `pretendard-gov`(OFL-1.1)의 variable dynamic-subset CSS를 import한다. Vite가 woff2 조각을 `/assets/`에 해시 파일로 내보내며 외부 글꼴 CDN을 사용하지 않는다. |
| 토큰 | `--ds-font-family-base`는 `"Pretendard GOV Variable"`, `"Pretendard GOV"`, 시스템 글꼴 순서다. `--ds-font-family-ui`는 같은 값을 가리키는 호환 이름이다. 새 코드에서 글꼴 이름을 직접 선언하지 않는다. |
| 전송량 | 조각마다 `unicode-range`가 있어 화면에 나온 글자의 조각만 내려받는다. |
| 예외 | 코드·원문 텍스트는 `ui-monospace` 계열을 쓴다. [map-data-credits.html](../../../frontend/public/map-data-credits.html)과 SVG 브랜드 자산은 번들을 거치지 않아 시스템 글꼴로 렌더링된다. |

- variable 글꼴이라 45~920 사이 웨이트를 그대로 렌더링한다. 이전 정적 글꼴(400·500·700)에서 700으로 뭉개지던 600·650은 이제 실제 굵기로 보인다.
- 새 화면은 웨이트를 400(본문)·500(라벨·보조 강조)·600(목록 제목·탭 등 중간 강조)·700(`--ds-weight-strong`, 제목·금액·주 행동) 중에서 고른다. 550·650·730·750·780·800·900 같은 기존 값은 해당 파일을 수정할 때 이 단계로 옮긴다.
- `font-synthesis: none`을 유지한다. 없는 굵기·기울임을 브라우저가 합성하지 않는다.
- 글자 크기는 `--ds-text-*`를 먼저 사용한다. 금액·날짜·개수처럼 세로로 비교하는 숫자는 `font-variant-numeric: tabular-nums`를 사용한다.
- Pretendard는 Noto Sans KR보다 자폭이 약간 좁다. 2026-10-15 전환 때 데스크톱(1440px)과 모바일(375px)에서 마커(92·150px), 필터 칩, 목록 카드, 하단 내비게이션의 줄바꿈·잘림이 늘지 않음을 확인했다.

### 글꼴 통일 전 관찰 (2026-10-15)

아래는 글꼴 통일 이전의 관찰과 당시 기준이다. 현재 글꼴과 웨이트 기준은 위 내용을 따른다.

당시 글꼴 토큰과 실제 렌더링 결과는 달랐다. 2026-10-15 로컬 브라우저(macOS)에서 확인한 상태다.

| 적용 범위 | 선언 | 실제 로드·렌더링 |
|---|---|---|
| `:root`·랜딩·정책 (`--ds-font-family-base`) | `"Pretendard GOV", Pretendard, -apple-system, …` | Pretendard 계열은 로드하지 않는다. macOS는 시스템 글꼴(Apple SD Gothic Neo), Windows는 `system-ui`로 맑은 고딕이 선택될 수 있다. |
| 공개 지도 화면 `.app-shell` (`--ds-font-family-ui`) | `"Noto Sans KR", "Apple SD Gothic Neo", sans-serif` | [index.html](../../../frontend/index.html)의 Google Fonts에서 Noto Sans KR 400·500·700을 로드한다. |
| 지도 마커 `.housing-map-marker` | `Pretendard, -apple-system, …`를 직접 선언 | Pretendard를 로드하지 않아 OS 시스템 글꼴로 대체된다. |
| 코드·원문 텍스트 | `ui-monospace, …` | 시스템 고정폭 글꼴 |

- 정적 웨이트는 400·500·700만 로드한다. 사용자 화면 CSS의 550·600·650·730·750·780·800·900은
  `font-synthesis: none`이라 가장 가까운 로드 웨이트로 렌더링되며 의도한 굵기 차이가 나타나지 않는다.
- 새 화면은 웨이트를 400(본문)·500(라벨·보조 강조)·700(`--ds-weight-strong`, 제목·금액·주 행동) 중에서 고른다.
- 글자 크기는 `--ds-text-*`를 먼저 사용한다. 현재 토큰 밖의 고정 px은 9~28px에 걸쳐 남아 있으며
  12px(배지·마커·작은 라벨)과 10·11px(모바일 하단 내비게이션)이 가장 많다.
- 금액·날짜·개수처럼 세로로 비교하는 숫자는 `font-variant-numeric: tabular-nums`를 사용한다.
- 한글 제목의 자간은 기존 사용처에 맞춰 `-0.025em`을 기본으로 하고, 랜딩 히어로처럼 큰 제목에서만 더 좁힌다.

## Button과 IconButton

`Button`은 주 행동용이다. `md`가 기본이며, 모바일 하단의 주 행동에는 `lg`를 사용한다.
기본 `type`은 `button`이고 폼을 제출할 때만 `submit`을 명시한다.
disabled, ref, aria 속성과 native button 이벤트를 전달할 수 있다. async 요청·로딩·라우팅은 호출자가 처리한다.

```tsx
// frontend/src 아래 화면에서의 import 예시
import { Button } from '../design-system/components/Button'
import { IconButton } from '../design-system/components/IconButton'

<Button type="submit">조건 적용</Button>
<Button size="lg" disabled={isSubmitting} type="submit">결과 보기</Button>
<IconButton label="필터 닫기" onClick={closeFilter}>
  <svg viewBox="0 0 24 24" fill="none" stroke="currentColor"
    strokeWidth="1.8" aria-hidden="true" focusable="false">
    <path d="m5 5 14 14M19 5 5 19" />
  </svg>
</IconButton>
```

`IconButton`의 `label`에는 화면에서 수행할 동작을 넣는다. 아이콘은 장식 처리한다.
`md`는 데스크톱 필터 닫기, `lg`는 모바일 필터 닫기에 사용한다.
닫은 뒤 포커스를 돌릴 위치는 필터가 관리하며 `ref`를 실제 버튼까지 전달한다.
각 컴포넌트는 기본·hover·focus-visible·disabled 표현을 제공한다.

폭·배치는 호출자의 `className`으로 지정한다. 색·모서리·포커스 규칙을 사용처에서 덮어쓰지 않는다.
내비게이션은 실제 링크를 사용하고, 링크를 버튼으로 위장하거나 버튼 안에 또 버튼을 넣지 않는다.
텍스트 닫기 버튼, 보조 동작, 탭, 상태 배지는 주 행동 Button으로 일괄 교체하지 않는다.

실제 적용 예시는 [공고 필터](../../../frontend/src/public-housing/filters/AnnouncementFilterPanel.tsx)와
[단지 필터](../../../frontend/src/public-housing/filters/ComplexFilterToolbar.tsx)다.

## 서비스 패턴

`BEFORE_APPLICATION`의 사용자 표시명은 **공고중**이다. 공고가 게시되었지만 접수 시작 전인
상태를 의미한다. 목록·상세·필터·통합 검색에서 같은 이름을 사용하며, 접수가 진행 중인
`APPLYING`은 **접수중**으로 구분한다.

단지 검색은 모집상태 선택 패널 대신 도구모음의 **모집중** 스위치를 사용한다. 기본은 해제이며,
켜면 공고중·접수중 공고가 있는 단지를 함께 조회한다. 데스크톱과 모바일 모두 필터 칩 줄 바로 아래
오른쪽에 지도 확대·축소와 같은 `--ds-icon-control-lg` 크기의 네모 버튼을 둔다. 버튼에는 모집중만 표시하고 켜짐 배경색과
`role="switch"`·`aria-checked`로 상태를 전달한다. 필터 묶음은 실제 버튼 너비로 오른쪽에 정렬하고 모집중 버튼과 오른쪽 끝선을 맞춘다. 각 버튼은 기존 높이와 내용에 맞는 폭을 유지하며, 데스크톱 버튼 사이 간격은 항상 8px로 둔다. 선택을 해제하면 원래 폭과 위치로 돌아온다. 지역명은 말줄임하며, 임대유형의 `외 N`과 면적 요약은 모두 표시한다. 가격 범위가 가용 폭을 넘을 때만 가격을 말줄임한다. 바로 노출하는 필터는 지역·임대유형·가격·전용면적·전체 순서이며, 전체 버튼은 필터 줄 맨 오른쪽에 둔다.
준공년도·공급기관·모집유형은 전체에서 선택한다. 가용 폭이 줄면 전용면적·가격·임대유형·지역 순서로 숨기고
전체에서 계속 선택할 수 있게 한다. 필터 줄에는 가로 스크롤과 좌우 화살표를 두지 않는다.
데스크톱 필터 팝업의 너비는 지역 필터와 같은 320px로 통일하며, 가용 폭이 더 좁으면 그 안으로 줄인다.
필터창을 연 동안에는 선택값이나 지역 이름이 바뀌어도 위치를 유지하고, 다시 열거나 화면 크기가 바뀌면 버튼 위치에 맞춘다.
단지 지역 필터는 시·도 → 시·군·구 → 읍·면·동의 단계별 목록에서 선택한다. 선택 경로와 현재 지역을 표시하고, 이전 단계로 돌아가면 그 아래 지역 조건을 해제한다. 각 단계의 전체 선택과 지역 변경은 다른 필터를 보존하며 즉시 적용한다. 데스크톱 개별·전체 필터와 모바일에서 같은 지역 선택 화면을 사용한다.
지역명 조회 전이나 실패 시에도 내장 지역 목록으로 선택 이름을 표시하고, 이름을 확인할 수 없으면 코드 대신 `지역 선택됨`을 표시한다. 전용면적은 10평 단위 빠른 선택과 1평 단위 슬라이더로 60평까지 선택하며, 마지막 기준은 모두 `60평 이상`이다. 눈금은 가독성을 위해 20평 간격으로 표시한다. 면적 선택 버튼은 최소 16px, 가격·면적 슬라이더의 눈금은 최소 14px로 표시한다.

연속 필터 변경은 앞선 적용값이 늦게 반영되어도 열린 패널과 최신 입력을 유지한다. 뒤로가기 등 외부 탐색으로 바뀐 조건에는 기존 패널 복원 규칙을 적용한다. 지도 조회는 마지막 필터 변경 후 100ms 동안 추가 변경이 없을 때 실행하며, 대기 중인 이전 요청은 취소한다.
모바일 현재 위치 버튼은 우측 하단 정보 버튼 위에 둔다.
다른 필터 변경은 모집중 조건을 유지하고 전체 초기화는 해제한다. 기존 단지 공유 주소의
공고중·접수중 단독 조건은 두 상태를 포함한 모집중으로 복원하며, 접수마감만 있는 조건은
해제한다. 공고 검색의 상태 선택은 별도로 유지한다.

단지 마커가 `applicationStatus`를 전달받으면 공고중은 앰버, 접수중은 파랑으로 상단과 외곽을 표시한다.
선택 시 브랜드 초록색을 우선하며, hover·키보드 포커스·목록 연동 강조는 현재 색을 유지하고
마커를 확장한다. 확장 시 기관·임대유형·금액과 함께 단지명·전용면적 범위를 표시하고,
공고중·접수중인 경우에만 상태 배지를 표시한다. 면적 결측은 공고문 확인으로 안내한다.
상태와 면적은 접근성 이름에도 포함하며, 중복되는 브라우저 기본 툴팁은 사용하지 않는다.
지도 API의 대표 공고 상태를 사용하며 필드가 없는 이전 응답도 허용한다.
지도 결과 밖의 선택 단지는 상세 데이터로 마커를 보완하되, 대표 상태를 확인할 수 없으면 배지를 생략한다.
지역 집계 마커는 꼬리 없는 사각형이며, 단지 마커 확장은 지도상 기준점을 유지한다.
지도 탐색 중 최근 20개 조회 결과를 수신 후 5분간 보관한다. 범위·확대 수준·필터와 이전 집계
단계가 일치하는 결과로 돌아오면 재조회와 등장 효과 없이 복원한다. 새 응답의 집계 정책이나
지역 데이터 버전이 바뀌면 이전 결과를 버린다. 조회 중에도 기존 집계 마커의 투명도는 유지한다.
단지 마커는 기본 92px 너비·54px 높이와 12px 글자를 사용하며, 긴 금액에 필요한 너비는 보존한다.
기관·임대유형 칸은 글자 길이에 맞춰 배분해 세 글자 유형도 생략 없이 표시한다.
확장 너비는 기본 150px이며, 배경·테두리와 내용이 보이는 영역이 실제 기본 크기에서 150ms 동안 확대된다.
이탈 시에는 배경·그림자·내용 영역을 동시에 즉시 기본 크기로 복귀시켜 축소 잔상을 남기지 않는다.
글자는 각 상태의 최종 너비와 좌표로 즉시 배치하고, 커지는 영역 밖은 가린다.
글자 자체의 이동·페이드·확대나 표시 지연은 사용하지 않는다. 보·월 라벨은 왼쪽, 금액은 오른쪽에 정렬한다.
동작 줄이기 설정에서는 크기와 내용 영역도 즉시 전환한다.
확장 중 카드의 왼쪽·아래쪽과 꼬리 위치를 고정하고 위·오른쪽으로 펼친다.
꼬리 중심은 마커 왼쪽에서 16px에 두며, 지도 좌표의 anchor도 같은 위치로 맞춘다.
확장된 색상 띠에는 단지명만 두고, 흰색 본문에 기관·임대유형과 상태 배지,
전용면적, 보증금·월 임대료 순서로 표시한다. 금액은 공통 `housingMoney`의 원·만원·억 규칙을 유지한다.
확장된 본문의 SH·LH·GH 기관 약칭에는 기존 `--ds-color-agency-*` 색상을 적용한다.
기본 마커의 기관 약칭과 임대유형 글자색은 유지한다.
단지명은 확장 너비 기준으로 최대 두 줄을 표시하고 전체 이름은 접근성 이름에 유지한다.

공고중의 디데이는 접수 시작일 기준 `접수 시작 D-N`으로 표시한다. 접수중은 마감일 기준을
유지한다. 서버의 `dDay`도 이 상태별 기준을 사용한다. 조건부 일정에는 확정 디데이를 붙이지 않는다.

공고 상세의 주택형 비교는 단지별 카드와 각 단지의 모든 주택형을 세로로 이어서 표시한다. 단지명과 세대수는 초록 머리줄에 두며 선택 탭은 사용하지 않는다. 접수 일정에 검토된
`applicationSchedules`가 있으면 전체 단지 공통 및 단지별로 묶어 공급 순위, 확정·조건부 여부,
진행 조건, 공식 날짜·시각과 공고문 쪽수를 표시한다. 공식 시각이 없으면 날짜만 표시한다.
새 일정이 없는 공고는 기존 접수 일정을 날짜순으로 표시하고 대상 구분이 없으면 공고문 확인으로 안내한다.
기존 일정의 종류·이름·시작·종료 일시가 모두 같으면 대상 단지명을 모아 한 번만 표시하며 원본은 변경하지 않는다.
각 묶음은 좌상단 단지명 제목과 날짜순 타임라인으로 표시하며, 섹션 블록 안에서 상자 없이 묶음 사이 1px 선으로 구분한다. 시작·종료 날짜와 시각은
일정명 아래에 배치하고 좁은 화면에서는 세로로 전환한다. 동일 일정이 여러 단지에 해당하면
`공통 일정` 카드에 단지 수와 개별 단지명을 표시한다. 대상이 4개 이상이면 먼저 2개 단지를 보여 주고
나머지는 펼침 버튼으로 확인한다. 날짜가 다르면 해당 단지의 별도 카드로 유지한다. 단지명 미제공은
`대상 단지: 공고문 확인`으로 분리하며 전체 공통으로 추정하지 않는다. 검토된 일정도 같은 방식으로
묶지만 순위·확정 상태·조건·시각·출처가 다른 항목은 합치지 않는다. 명시적인 전체 단지 공통 일정은
특정 단지 일정과 구분한다. 당첨자 발표·서류제출 등은 별도의 **후속 일정** 영역에 모아 표시한다.
상세 섹션 제목 아래 일반 안내문은 사용하지 않는다.
단지·공고 상세는 같은 머리를 쓴다. 머리에 분류 줄(단지: 기관 약칭·임대유형, 공고: 임대유형·접수 상태), 제목(h2, 열 때 포커스), 닫기를 두고, 공고 상세만 그 아래 구역 탭을 붙인다. 제목은 머리에만 두고 본문에 반복하지 않는다.
문의 전화번호의 연속 숫자는 하이픈으로 구분하고 복수 번호와 설명 문구는 보존한다.

공고 상세 상단의 공사·지역·모집유형은 항목명 접두어 없이 값을 표시한다. 요약 단지명은 굵게,
모집유형은 본문색으로 표시한다. 비교 영역에서 항목명이 없는 누락 값은 `공급 세대수: 공고문 확인`,
`단지 정보: 공고문 확인`처럼 짧게 구분하고, 긴 설명 문장을 추가하지 않는다.

각 기능의 행동 테스트는 같은 디렉터리의 `*.test.tsx`다. 기본 컴포넌트가 API 요청·모집 상태 판단·
금액 계산·URL 상태·지도 SDK를 소유하지 않도록 한다. 위 서비스 패턴은 기능 폴더에 유지한다.

단지 목록의 보증금·월 임대료는 마커와 같은 `mapMarkerAmount`의 COMPACT 표기를 사용한다.
1천만원 미만은 만, 1억원 미만은 천, 그 이상은 억으로 표시하고 정책에 따라 버림 처리한다.
금액 누락은 `-`, 실제 0원은 `0원`으로 표시하며 원본 금액과 범위 판단은 보존한다.
단지 상세의 금액은 `formatHousingMoneyReadable`로 `1억 2,000만원`, `42만 5,000원`처럼 억·만 단위를 읽는 순서대로 표시하고 버리지 않는다.
공고 상세의 금액도 같은 `formatHousingMoneyReadable` 표기를 쓴다.
단지 상세의 미제공 정보는 항목명을 유지하고 값을 빈칸으로 표시한다. 실제 0과 false는 보존한다.
필터의 기존 금액 표기는 유지한다.

단지 상세의 주택형별 비교표는 마이홈 `기본 임대조건`과 공고의 `현재 공급` 조건을 별도 행으로 표시한다.
선택 주택형 상세에는 기본 보증금·월 임대료와 안전한 출처 링크, 한국 시간 기준 수집일을 표시한다.
기본 조건과 공고 조건의 누락 금액을 서로 채우지 않으며, 이전 응답에 기본 조건이 없으면 빈값을 유지한다.

상세 면적은 기본 ㎡이며 `AreaUnitToggle`로 평과 양방향 전환한다. 단지 상세의 임대조건 표와
선택 주택형 상세, 공고 상세의 단지 비교와 주택형 비교에 각각 버튼을 둔다. 버튼과 면적은
`useAreaUnit`의 브라우저 설정을 공유하며 주택형 탭, 다른 단지·공고 상세로 이동하거나
새로고침해도 마지막 선택을 유지한다. 저장된 값은 `sqm`과 `pyeong`만 허용하며 잘못된 값은
㎡로 표시한다. 저장소를 사용할 수 없으면 현재 페이지에서 선택한 단위를 메모리에 유지한다.
`housingArea`는 원본 ㎡에서 평을 계산하고 소수점 둘째 자리까지 표시하므로 왕복 전환에
반올림 오차가 누적되지 않는다.
`DetailSection`의 `actions`는 제목 우측에 배치하며 보조 설명은 그 아래에 둔다.

단지·공고 상세의 흰 섹션 블록은 패널 폭을 채운다. 좌우 회색 여백과 블록 모서리 라운드 없이 안쪽 여백은 `--ds-space-4`, 블록 사이 회색 구분 간격은 `--ds-space-2`를 쓴다.
공고 상세는 요약(기관 약칭·지역·대표 단지·모집유형)과 `알림 받기`를 첫 블록으로 묶고, 핵심 정보·일정·접수 방법·단지 비교·주택형 비교·첨부파일을 각각 블록으로 둔다. 요약의 기관과 지역은 한 문장처럼 이어져 줄바꿈하며 구분점만 따로 남기지 않는다.
접수·후속 일정은 기존 타임라인 배치를 유지한다. 일정명 아래에 시작·종료 또는 단일 일정의 날짜와 시각을 표시한다.
단지 비교는 단지명과 `단지 상세` 버튼, 주소·조감도·총 세대수·공급 세대수를 표시하고 전용면적·보증금·월 임대료를 항목 표로 묶는다. 연결되지 않은 단지는 상세 버튼을 표시하지 않는다.
주택형 비교는 단지마다 초록 머리줄에 단지명·세대수를 두고, 그 아래 모든 주택형의 공급 구분·전용면적·공급 세대수·입주 예정 표를 이어서 표시한다. 공급면적이 있으면 별도 행으로 표시한다. 여러 단지도 선택 없이 카드 전체를 세로로 나열한다. 대상별 조건도 항목 표를 유지하며, 대상·순위·신청 조건을 임의로 채우지 않는다.
단지 상세의 첫 블록은 대표 사진, 주소와 `알림 받기`·`거리뷰` 한 쌍으로 구성한다. 한 쌍은 같은 높이(48px)·모서리를 쓰고 거리뷰만 2px action 테두리와 굵은 글자로 강조한다.
거리뷰를 제공하지 않는 화면에서는 알림 버튼이 전체 폭을 쓴다. 현재 공고가 없으면 배경 없이 `지금 모집 중인 공고가 없어요.`와 알림 안내 두 줄만 둔다.

주택형별 임대조건, 공고 단지별 공급 정보와 주택형 공급 정보는 표로 비교한다. 공통 표는 바깥 테두리·세로선 없이 얇은 가로선으로 행을 나누고, 열 제목에만 연한 회색 바탕과 보조 글자 크기를 적용한다. 본문은 보통 굵기이며 단지명·보증금처럼 필요한 항목만 중간 굵기로 강조한다. 단지 기본 정보·현재 공고의 접수 기간처럼
단순한 항목 나열에는 `DetailFacts appearance="list"`를 쓴다.
공고의 주택형 공급 정보는 항목명 칸에 회색 배경과 세로 구분선을 둔다. 단지 상세의 주택형별 임대조건은 `주택형 / 전용면적 / 보증금 / 월 임대료` 4열이며
한 행에 한 조건을 둔다. 주택형 이름은 같은 주택형의 행을 묶고, 전용면적 아래 공급 대상(또는 `기본 임대조건`)을 보조 글자로 둔다.
같은 주택형에 기본 임대조건 행이 함께 있으면 현재 공급 행에 `현재 공급`을 함께 쓴다. 좁은 화면에서는 주택형 열을 고정하고 표 안에서 가로로 스크롤한다.
금액은 줄바꿈하지 않고 오른쪽 정렬한다. 선택 주택형의 기본 정보와 임대조건은 항목 표로 표시한다.
단지 상세의 주택형 탭은 위쪽 모서리가 둥근 회색 바탕이며 선택 항목은 초록 바탕으로 표시한다. 탭 줄은 가로로 스크롤하며 키보드로 선택한 탭도 화면 안에 드러낸다. 선택 주택형 본문은 탭 아래 초록 테두리 상자 안에 둔다. 기본 임대조건은 보증금과 월 임대료를 각각 한 행으로 표시한다.

금액은 [housingMoney](../../../frontend/src/public-housing/presentation/housingMoney.ts), 누락 표시는
[missingData](../../../frontend/src/public-housing/presentation/missingData.ts), 상세 데이터 변환은
[complexDetailPresentation](../../../frontend/src/public-housing/presentation/complexDetailPresentation.ts)와
[announcementDetailPresentation](../../../frontend/src/public-housing/presentation/announcementDetailPresentation.ts)를 따른다.
0과 false를 누락으로 바꾸지 않고, 기존 단위·날짜·마감 계산을 시각 컴포넌트에서 다시 구현하지 않는다.
미확인 자격이나 공급 규모를 추정하지 않으며 실제 공식 출처와 기준 시점을 유지한다.

사용자 화면의 안내·오류 문구는 해요체(`없어요`, `불러오지 못했어요`)로 쓴다. 개인정보 동의 안내처럼 버전으로 관리하는 고지문은 해당 절차 없이 바꾸지 않는다.

## 반응형과 접근성

- 기준은 브라우저 전체 폭과 패널 폭을 구분한다. 지도 옆 패널은 데스크톱에서도 좁아질 수 있다.
- 검색창과 단지·공고 상세는 `--explorer-panel-width`를 공유한다. 기본 글꼴 16px 기준으로 브라우저 표시 폭에 따라 340~452px 사이에서 연속적으로 조절하며, 1440px 화면에서는 380px, 1920px에서는 420px다. 목록 페이지는 같은 콘텐츠 폭에 좌우 여백을 더한다. 767px 이하 모바일은 검색창을 지도 위에 띄우고 상세를 화면 중앙의 독립 모달로 표시한다.
- 공개 지도 화면의 글자·여백은 `.app-shell`에 한정한 `--explorer-ui-unit`과 디자인 토큰으로 함께 조절한다. 기본 글꼴 기준 본문은 14~16px, 제목은 18~약 20.6px다. `rem` 기반 최소·최대값을 둬 작은 화면에서 가독성을 유지하며, 브라우저 확대와 글꼴 설정을 존중한다. 물리적 모니터 크기나 기기 픽셀 비율로 강제 확대하지 않는다. 지도 캔버스에 `zoom`이나 `transform: scale()`을 적용하지 않는다.
- 목록 컨테이너는 기존 400/340px 여백 규칙을 보존한다. 공고 카드의 접수기간은 라벨과 날짜를 같은 행에 두며, 긴 연도 범위처럼 공간이 부족한 경우에만 날짜 단위로 줄바꿈한다. 380px 이하에서는 지역·임대유형의 줄바꿈을 허용한다.
- 768px 이상에서 지역 단지 목록·공고 목록·통합 검색 결과가 열리면 검색창과 목록을 화면 높이의 단일 흰색 패널로 연결한다. 패널은 고정된 지도 위에서 움직이며 지도 캔버스 크기를 바꾸지 않는다. 탭 전환만으로 SDK 크기 재계산과 영역 재조회를 일으키지 않는다. 목록 자체에는 모서리 라운드나 그림자를 적용하지 않는다.
- 목록 헤더의 왼쪽 화살표로 패널을 접는다. 좌측에는 공고·최근 본 단지 메뉴를 제공하고 같은 메뉴를 다시 누르면 목록을 접는다. 단지 목록은 지역 검색이나 시·군·구 지도 마커 선택 후에 제공하며 검색창 아래 지역명 버튼으로 다시 연다. 검색 지역·조회 페이지·스크롤은 보존한다. 메뉴의 강조와 `aria-expanded`는 실제 목록의 열림 상태를 따른다. 목록 표면은 220ms 동안 좌우로 전환하며 검색창은 고정하고, 동작 줄이기 설정에서는 전환을 생략한다. 검색 중에는 숨긴 목록이 검색 결과 높이를 차지하지 않는다.
- 최근 본 단지는 지역 검색과 독립된 목록이며 브라우저에 최근 20개까지 저장한다. 다시 본 단지는 중복 없이 맨 앞으로 옮기고 20개를 넘으면 가장 오래된 기록을 제외한다. 목록에서 상세를 열거나 다른 메뉴로 전환해도 목록 상태와 스크롤을 보존한다.
- 좌측 메뉴 폭은 768px 이상에서 60px이며 공용 집·돋보기 로고와 20px 아이콘을 사용한다. 767px 이하에서는 로고를 숨기고 공고·최근 본 단지·로그인을 화면 하단의 3칸 내비게이션으로 배치한다. 로그인 아이콘과 글자는 가운데 정렬한다. 버튼 영역 64px 위에 8px, 아래에는 기기 안전 여백과 12px 중 큰 값을 확보한다. 좌우도 최소 12px과 기기 안전 여백을 확보하며 지도와 목록 시트는 하단바 위의 영역을 사용한다. 계정 메뉴는 하단 바 위로 열린다.
- 모바일 검색 입력은 최소 16px(사용자 기본 글꼴이 크면 1rem)로 표시해 초점 시 자동 확대를 예방하고, 브라우저의 핀치 확대는 허용한다. `viewport-fit=cover`와 안전 여백을 함께 적용해 검색창과 하단 메뉴가 기기 모서리에 가려지지 않게 한다. 검색창 위에는 안전 여백에 더해 20px 간격을 둔다. 홈 화면에 추가한 iOS 웹앱은 반투명 상태 표시줄 설정으로 지도 배경을 화면 끝까지 채운다. 일반 브라우저 탭의 상태 표시줄은 브라우저가 제어한다.
- 모바일 지도 확대·축소 버튼은 숨기며 핀치 제스처를 유지한다. 우측 하단에는 48px 정보 버튼, 그 위 8px 간격으로 현재 위치 버튼을 둔다. 정보의 펼침 메뉴는 왼쪽으로 열려 위치 버튼을 가리지 않는다. 데스크톱 지도 컨트롤은 기존 배치를 유지한다.
- 목록이 없는 기본 화면과 상세 화면에서는 브랜드색 테두리의 둥근 검색창을 지도 위에 띄운다. 목록이 접혀 있으면 단지·공고 상세는 검색창 아래에 표시한다. 데스크톱에서 목록을 열면 상세가 목록 오른쪽의 공통 간격 토큰(기본 8px)만큼 이동하고 지도 상단부터 펼쳐진다. 필터는 상세 오른쪽의 남은 지도 영역에 표시한다. 단지 필터는 폭에 맞춰 항목을 숨기고 전체 필터에서 계속 선택하도록 하며, 상세한 동작은 [서비스 패턴](#서비스-패턴)을 따른다. 목록을 접으면 상세가 220ms 동안 원래 위치로 돌아온다. 상세의 선택·스크롤·URL을 유지하며 지도 캔버스 크기는 바꾸지 않는다. 768~1023px에서는 지도 공간을 확보하기 위해 두 패널을 겹쳐 사용한다. 목록을 열면 상세를 화면 밖에 보존하고, 목록을 접거나 상세를 선택하면 상세를 다시 보여준다.
- 767px 이하의 기본 화면은 지도이며 검색창·필터를 그 위에 띄운다. 지역 단지·공고·최근 본 목록은 절반 높이의 하단 시트로 열린다. 높이 28px 손잡이 줄 전체와 제목 영역에서 드래그하며, 절반 이상에서는 놓은 높이를 그대로 유지한다. 절반 아래로 내리면 손잡이까지 완전히 닫힌다. 12px 미만의 움직임과 취소는 기존 높이를 유지한다. 최대 높이는 하단 메뉴와 상단 안전 여백(최소 8px)을 제외한 영역이며 검색창 위로 올라온다. 크게 보기·절반 보기 버튼은 두지 않는다. 방향키로 화면 높이의 10%씩 조절하고 End는 최대 높이, Home·Escape·접기 버튼은 완전 닫기다. 목록 DOM과 스크롤을 보존하며 드래그로 닫은 뒤 재열면 절반 높이를 사용한다. 상세는 배경 입력을 차단하는 native 모달로 표시하고 닫으면 이전 목록 높이·스크롤·포커스를 복원한다. 알림·첨부파일은 상세 위에서 열며 안쪽 창만 닫는다. 검색 결과는 검색창에 연결된 스크롤 패널로 표시한다. 지도 캔버스는 목록 높이에 따라 다시 배치하지 않는다.
- 현재 위치 조회에 성공하면 해당 좌표에 파란 점·흰 테두리·잔잔한 펄스를 표시한다. 지도 중심이나 검색 위치를 사용자 위치로 표시하지 않는다. 동작 줄이기 설정에서는 펄스를 멈춘다. 권한이 거부된 경우 안내의 `설정 방법`에서 Safari·Chrome 위치 허용 경로와 재시도를 제공한다. 웹에서 휴대폰 설정으로 이동한다고 오인하게 하는 링크는 사용하지 않는다.
- 767px 이하에서는 지도 위 안내를 한 번에 하나만 보인다. 목록 시트가 열렸거나 위치 안내가 떠 있으면 알림 상태 오류 토스트는 숨기고, 둘 다 닫히면 다시 보인다. 위치 안내는 스스로 닫히지 않고 닫기 버튼으로 닫는다.
- 필터는 767px 이하의 모바일 시트·패널 동작을 유지한다. 지도 위 필터 칩은 높이 34px, 좌우 여백 10px, 간격 4px, 아이콘 16px로 표시하며 투명한 상하 영역을 포함해 44px 터치 높이를 확보한다. 모바일 단지·공고 필터에는 적용 버튼을 두지 않고 선택 즉시 반영한다. 패널은 열린 채 유지해 다중 선택을 이어가며 입력의 포커스·스크롤을 보존한다. 가격·면적 슬라이더는 조작을 마칠 때 반영하고 역전된 준공년도는 오류를 표시한 채 마지막 유효 조건을 유지한다. 초기화도 즉시 반영하며 닫기·Escape는 적용된 조건을 취소하지 않는다. 화면 회전과 낮은 높이에서도 초기화·닫기에 도달해야 한다.
- 상세는 기존 420/330/270px container 규칙을 각 컴포넌트에서 확인한다. media/container 조건에 CSS 변수를 넣지 않는다.
- 목록은 hover·selected·focus를 구분하며 상태를 색만으로 전달하지 않는다. 긴 제목은 전체 접근성 이름을 유지한다.
- Tab·Shift+Tab·Enter·Space·Escape와 닫은 후 포커스 복귀를 실제 브라우저에서 확인한다.
- reduced-motion·forced-colors 규칙과 원래 지도/필터/상세 레이어 순서를 유지한다.
- 로딩·빈 결과·오류·재시도를 구분한다. 오류를 빈 성공으로 표시하지 않는다.

## PC 단지 거리뷰

- 단지 상세의 `거리뷰`는 주소 아래 행동 한 쌍의 강조 버튼(`StreetViewEntry appearance="action"`)이다. 높이 48px, 2px action 테두리, 흰 표면, action 굵은 글자와 선 아이콘을 쓰고 주 행동 Button의 채움 스타일은 쓰지 않는다. 상세 내부 폭 330px 이하에서는 한 쌍을 세로로 쌓는다.
- 비활성 버튼은 포커스를 유지하며 600ms 뒤 사유를 표시한다. 열린 상태는 `aria-pressed`로 알리고 다시 눌러 닫는다. 버튼과 거리뷰 영역을 `aria-controls`로 연결한다.
- 768px 이상에서 상세 오른쪽 경계부터 남은 지도 영역에 거리뷰를 표시한다. 상단은 `단지 주변 거리뷰`와 `지도 보기`, 하단은 촬영일·상태 안내로 구성한다. 같은 단지명·주소를 큰 헤더로 반복하지 않는다.
- 거리뷰는 일반 영역으로 표시한다. 배경 dim·포커스 트랩을 추가하지 않고 상세를 계속 조작할 수 있게 한다. 목록은 표시만 접고 DOM·스크롤을 보존하며 GL 지도 크기와 카메라는 유지한다.
- 출입구 마커는 action 초록색 핀·흰 이름표·작은 그림자를 사용하고 핀 끝을 좌표에 맞춘다. `단지명 · 출입구`를 최대 두 줄로 표시하되 전체 접근성 이름을 유지한다. 클릭·드래그 동작이나 Tab 정지점을 추가하지 않는다.
- 핀은 등록된 출입구 위치 안내다. 시야 밖에서는 보이지 않을 수 있고 건물 외벽이나 정문 식별을 보장하지 않는다. 핀 오류는 영상을 가리지 않는 안내로 표시한다. 네이버 로고·출처·확대 컨트롤을 가리지 않는다.
- `지도 보기`·거리뷰 Escape는 상세를 유지하고 버튼으로 포커스를 돌린다. 내부 모달·툴팁의 Escape 처리를 먼저 적용한다. 767px 이하로 전환하면 거리뷰를 정리하고 모바일 상세를 유지한다.

상세 전환·검색·history와 결과 수집 규칙은 [단지 주변 거리뷰](../../features/search/street-view-ui.md)를 따른다.

## 새 화면과 변경 절차

1. 기존 서비스 패턴과 공통 UI를 찾고 코드·테스트를 읽는다.
2. 기존 토큰과 컴포넌트로 화면을 조합한다. 화면 레이아웃과 업무 상태는 해당 기능에 둔다.
3. 표현이 부족하면 같은 역할의 기존 변형으로 해결 가능한지 먼저 확인한다.
4. 새 변형은 실제 사용처를 제시한다. 별도 공통 컴포넌트는 두 번째 실제 사용처에서 추출을 검토한다.
5. 토큰 역할이나 컴포넌트 계약을 바꾸면 이 문서와 가까운 행동 테스트도 같은 변경에서 갱신한다.
6. [품질 게이트](testing.md)에 따라 검사와 실제 화면을 확인하고 의도된 시각 변화를 PR에 기록한다.

토큰·코드는 실행되는 기준이며 이 문서는 선택 이유와 사용법의 기준이다. 둘이 어긋나면 실제
사용처를 조사해 함께 갱신한다. 특정 에이전트의 개인 스킬·계획 파일·이전 대화에 의존하지 않는다.
AGENTS를 읽지 않는 도구에는 해당 도구의 저장소 진입 지침에서 이 문서를 연결한다.

## 보존한 차이와 현재 범위

- 글꼴은 [타이포그래피](#타이포그래피)의 단일 글꼴을 따른다. `--ds-font-family-ui`는 기존 사용처를 위한 호환 이름으로 남긴다.
- DetailCloseButton은 상세용 아이콘 크기·여백·포커스를 갖는다. 필터 IconButton과 역할을 구분한다.
- 오류·문서·이미지 등 기능별로만 사용되는 값은 가까운 CSS에 남는다. 새 공통 역할이 생길 때 추출한다.
- 모든 버튼을 같은 모양으로 바꾸거나 모든 값을 토큰으로 만드는 것을 완료 기준으로 삼지 않는다.
- 공통 적용 버튼의 좌우 여백은 기존 공고 필터 기준으로 맞췄다. 모바일 아이콘 버튼에도 공통 hover·focus·disabled 규칙을 제공한다.

### 지도 탐색

- 지역 검색·지역 클러스터 선택은 면적에 따른 경계 맞춤 대신 대표좌표에서 줌 12.6으로 이동한다. 대표좌표는 지역 코드로 복원하며, 대표좌표가 없는 하위 행정구역만 경계 중심을 사용한다. 대표좌표 원본은 백엔드 지도 정책이며 `node frontend/scripts/sync-region-representative-points.mjs`로 갱신한다. 목록에서 단지를 선택하면 주변 단지를 볼 수 있도록 최소 줌 12.7을 적용한다. 시군구 클러스터는 확대 시 12.5부터 개별 단지로 전환하고 축소 시 12.3 미만에서 다시 묶는다.

- 지도 필터는 768px 이상에서 검색창과 같은 상단 줄을 유지하고, 767px 이하에서 검색창 아래의 모바일 필터로 전환한다. 폭에 따른 항목 숨김·전체 필터 진입과 모집중 스위치 배치는 [서비스 패턴](#서비스-패턴)을 따른다. 필터 줄에는 가로 스크롤을 두지 않는다.

## 랜딩페이지와 공개 탐색

- `/`는 인증이나 지도 API 응답을 기다리지 않는 한 페이지 서비스 소개다. 기존 브랜드 로고, `--ds-*` 색상·글꼴·버튼 모서리를 사용한다. 소개, 실제 화면과 4단계 사용법(동네 찾기 → 조건 비교 → 공고 확인 → 알림 설정), 시작하기로 구성한다.
- 시작하기는 `/explore`의 공개 지도 탐색으로 이동한다. 랜딩 다음에 첫 방문 모달을 다시 표시하지 않는다. 이전 `/`의 단지·공고·지도·필터·로그인 쿼리는 `/explore`로 전달해 공유 주소를 보존한다.
- 탐색 주소의 대소문자·후행 슬래시·URL 인코딩 차이는 라우터와 같은 규칙으로 판별해 `/explore`로 정규화한다. 쿼리·앵커·이동 상태를 보존하고 동의·분석 경계는 정규화 후 실행한다. 로그인 성공은 서버가 `/explore`로 보내며 브라우저 저장소 표식에 의존하지 않는다. 기존 루트·`/login` 성공 설정도 서버에서 호환 처리한다.
- 데스크톱 사용법은 화면 사진을 고정하고 IntersectionObserver로 현재 단계의 사진을 전환한다. 모바일은 단계별 사진을 본문에 배치한다. 등장 전환과 CSS 스크롤 애니메이션은 `prefers-reduced-motion`에서 생략한다.
- 실제 화면은 검색창·가격 필터·접수 일정·알림 버튼을 중심으로 확대하고 초록 테두리로 핵심 위치를 표시한다. 2560×1440 고해상도 JPEG를 사용하고 1280×720 논리 좌표로 표시 영역을 조정한다. 모바일은 별도 확대 범위를 사용하며 지도 출처를 프레임 아래에 표시한다.
- 히어로의 이미지 주변에 옅은 도로·블록 모티프를 배치한다. 01–04 번호를 크게 표시하고 모든 단계의 활성 번호와 제목은 메인 브랜드 색인 `--ds-color-brand`로 강조한다. 시작하기 버튼은 톤다운한 `--ds-color-action` 배경에 흰 글자를 사용한다. 마우스 hover와 키보드 포커스에 화살표가 이동하며, 누르면 눌리는 반응을 제공한다. 동작 줄이기 설정에서는 위치·크기 변화를 생략한다.
- 첫 화면 하단에는 문구 없이 두 개의 아래 방향 꺾쇠로 스크롤을 유도하며, 링크의 접근성 이름은 `사용법으로 내려가기`다. 화살표는 `--ds-color-brand`로 표시하고 작은 상하 움직임을 반복한다. 화면 높이에 맞춰 여백과 사진 크기를 조절하며, 동작 줄이기 설정에서는 화살표를 정적으로 표시한다.
- 사용법의 4번째 단계에서 단지·공고 상세의 `알림 받기`로 로그인 후 관심 대상을 저장하는 흐름을 설명하고 로그인 후 설정할 수 있음을 안내한다.
- 헤더는 스크롤 중에도 고정한다. 지원 브라우저에서는 얇은 진행선이 읽은 위치를 표시한다. 제목·사용법 문구는 순서대로 등장하고 단계마다 실제 화면을 전환하며, 스크롤 유도 화살표 외에는 반복 재생을 사용하지 않는다. 스크롤 가로채기는 사용하지 않는다.
- 모바일은 공통 좌우 여백과 유동 글자 크기를 사용하고, 첫 화면 사진을 콘텐츠 폭에 맞춰 기울임 없이 표시한다. 번호 강조 시 이동을 생략해 본문 정렬을 유지한다.
- 화면 구성과 모션은 `src/landing/`의 CSS Module에 한정한다. 새 모션 라이브러리나 전역 토큰은 추가하지 않는다.

## 마이페이지와 사용자 오류 안내

- `/mypage/bookmarks`는 단지·공고 북마크를 분리해 보여준다. 분류 버튼은 56px 높이, 아이콘·이름·숫자 배지를 사용하고 선택 상태는 초록 밑줄과 테두리로 표시한다. 북마크와 단지·공고·지역 알림 신청 내역은 `ManagementTable`의 흰색 표로 통일하며, 관심 대상은 왼쪽, 관리 버튼은 오른쪽 셀 가운데에 정렬한다. 북마크는 이름과 관리 사이에 주소(단지)·접수 일정(공고) 열을 두며 세로 구분선 없이 여백과 가는 행 구분선으로 정리한다. 행의 상하 여백은 16px이고 중복된 종류 배지는 생략한다. 모바일에서는 주소·일정을 이름 아래에 놓고 관리 버튼을 세로로 배치해 가로 넘침을 만들지 않는다. 알림 관리 행에는 대상 이름과 해제 버튼만 표시한다. 단지·공고 이름은 해당 상세로 연결하며 닫으면 출발한 알림 분류로 복귀한다. 지역 이름은 일반 텍스트로 표시한다.
- 마이페이지는 북마크·알림 관리·계정 메뉴와 개인정보 공통 푸터를 제공한다. 데스크톱은 왼쪽 메뉴와 본문, 767px 이하에서는 상단 메뉴로 배치한다. 기존 받은 알림과 기기 설정은 유지한다.
- 지도 복귀는 `MapReturnLink`의 버튼 스타일 링크로 통일하며 저장한 지도 위치·필터를 복원한다. 화살표 없이 표시한다. 마이페이지에서 개인정보 문서·분석 설정·알림 보관함·의견 보내기로 이동하면 `location.state`의 허용된 출발 탭을 유지하고 명시적인 마이페이지 복귀를 제공한다. 직접 접근은 지도로 복귀한다. 단지·공고 상세에는 복귀 행이나 버튼을 추가하지 않고 기존 닫기 자리를 14px 문구와 화살표를 함께 쓰는 “마이페이지” 버튼으로 바꾼다. 버튼과 Escape는 출발한 마이페이지 분류에 복귀하고, 상세 내부 이동의 뒤로가기는 부모 상세로 이동한다. 지도·목록·검색에서 상세를 새로 고르면 마이페이지 복귀 맥락을 해제하고 기존 X로 상세를 닫는다.
- 지도 정보 메뉴의 개인정보처리방침·분석 설정·개인정보 문의 및 삭제 요청은 회원 마이페이지 공통 푸터와 비회원 로그인 모달/페이지 하단에서 접근한다.
- 사용자 화면은 서버 오류 원문, 경로, SQL과 SDK 오류를 표시하지 않는다. 목록·지도·검색은 `RequestError`로 제목·설명·공통 재시도 버튼을 구분하고 실패한 요청을 다시 실행한다. 오류를 빈 목록으로 처리하지 않는다.

- 지도 알림 보관함은 받은 알림만 제공하고, 관심 대상·기기 수신 설정은 마이페이지 알림 관리에서 제공한다. 마이페이지에서도 알림 보관함에 접근할 수 있다.
- 알림 종은 노란 계열로 표시하며 신청 여부는 채움과 버튼 문구로 함께 구분한다. 오류 안내와 재시도 버튼은 가운데 정렬하며, 모바일 목록 오류는 버튼을 가리지 않도록 목록 높이를 확보한다.

- 알림 관리의 단지·공고·지역은 개수와 선택 상태를 표시하는 분류 탭으로 나누고 선택한 분류만 흰색 표에 표시한다. 선택은 URL에 보존하며 방향키·Home·End로 이동할 수 있다. 개별 해제는 테두리가 있는 버튼으로 표시하고, 모든 분류에 적용되는 일괄 해제는 “모든 알림 해제”로 명시한다.
