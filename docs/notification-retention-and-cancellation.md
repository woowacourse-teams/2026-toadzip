# 알림 보관과 취소

알림 신청은 대상별로 12개월간 유효하다. 발송은 팀 담당자가 수동으로 처리한다.
브라우저 데이터를 지워 직접 취소할 수 없는 비로그인 사용자는 이메일 확인 코드로 신청을 취소한다.

## 보관 기간

| 데이터 | 기간·삭제 조건 |
|---|---|
| 알림 신청 | 신청·재활성화부터 12개월. 만료 즉시 조회·발송 대상 제외 |
| 비활성 회원 신청 | 최대 90일 후 삭제 |
| 알림용 이메일 | 마지막 신청 취소 시 삭제. 비로그인 신청 행도 함께 삭제 |
| 행동 이벤트 | 이메일 없이 보관하고 90일 후 삭제 |
| 완료된 취소 요청 | 요청 이메일·확인 코드 해시 삭제 |
| 미완료 취소 요청 | 30일 후 삭제 |

정리 작업은 15분마다 실행한다. 작업 사이에도 만료 신청은 발송 대상에서 제외한다.
회원 계정의 `users.email`은 알림 취소로 삭제하지 않는다. 만료 후 다시 받으려면 재신청한다.

## 비로그인 신청 취소

### 요청과 확인

1. 사용자가 `/notifications/cancel`에서 신청 이메일을 입력한다. 신청 여부와 관계없이 같은 접수 응답을 받는다.
2. 관리자가 `/admin/notification-cancellations`에서 코드를 발급하고 신청 주소로 수동 발송한다. 발송 후 완료 기록을 남긴다.
3. 사용자가 이메일·코드를 입력하면 같은 주소의 모든 비로그인 신청과 알림용 이메일을 삭제한다. 회원 신청에는 영향이 없다.

코드는 발급 시 한 번만 표시하고 DB에는 SHA-256 해시만 저장한다.
24시간 유효하며 성공 시 한 번만 사용한다. 잘못된 입력 5회 후에는 사용할 수 없다.

### 재발급

코드를 잃어버리거나 잘못 발송했다면 다시 발급한다. 이전 코드는 즉시 무효화되고 실패 횟수·발송 기록이 초기화된다.
다른 관리자가 재발급한 코드에 이전 발송 완료를 기록하면 서버가 거부한다.
신분증 등 별도의 신원 자료는 수집하지 않는다.

코드 확인 전에는 신청이 계속 유효할 수 있다. 일반적인 종 버튼 취소와 회원 취소에는 코드가 필요 없다.

## 수동 발송

### 담당과 확인 시간

서비스 주담당자가 처리하며, 부재 전 대체 담당자에게 기간·미발송 요청·관리자 주소를 인계한다.
갑작스러운 부재 시 팀원 한 명이 담당 사실을 알리고 당일 요청을 처리한다.

평일 10:00·17:00(Asia/Seoul)에 관리자 요청과 공용 Gmail을 확인한다.
휴일 접수는 다음 평일 10:00에 확인하고, 접수 후 다음 평일 17:00까지 코드 발송을 목표로 한다.

### 발송 절차

1. 발송 준비가 되면 코드를 발급하고 요청에 표시된 이메일로만 보낸다.
2. 관리자 화면에서 발송 완료를 기록한다. 시각·관리자 계정이 남지만 실제 전달 증명은 아니므로 Gmail 보낸 편지도 확인한다.
3. 코드 입력은 사이트에서 안내한다. 코드 원문을 티켓·메신저·로그에 남기거나 사용자에게 코드·신분증 회신을 요구하지 않는다.

발신 주소는 `toadzip.official@gmail.com`이다.
대체 담당자는 [Gmail 위임](https://support.google.com/mail/answer/138350?hl=ko)을 받고 각자 관리자 계정을 사용한다. 공식 Gmail은 2단계 인증을 설정한다.
운영 코드는 `bokduckbang.com`, 개발 테스트 코드는 `dev.bokduckbang.com`에서 입력한다.
재발급 시 사용자에게 이전 메일의 코드는 사용할 수 없다고 안내한다.

### 발송 문구

```text
제목: [공공주택 복덕방] 알림 취소 확인 코드

알림 취소를 요청하신 이메일인지 확인하기 위한 코드입니다.
확인 코드: <이번에 발급한 코드>
유효 기간: <관리자 화면의 만료 시각, 한국 시간>

https://bokduckbang.com/notifications/cancel 에서 신청 이메일과 코드를 입력해 주세요.
확인되면 이 이메일로 신청한 모든 비로그인 알림이 취소됩니다.
로그인 계정의 알림 신청은 별도로 종 버튼에서 취소할 수 있습니다.
새 코드를 받으셨다면 이전 코드는 사용할 수 없습니다.
직접 요청하지 않으셨다면 이 메일을 무시하셔도 됩니다.
```

## DB 배포와 복원

### 배포 확인

주 DB에 `expires_at`과 취소 요청·수동 발송 기록을 추가하고 이벤트의 이메일 열을 제거한다.
해당 Flyway 버전은 `20260930.07`·`20260930.08`·`20260930.09`다. 기존 요청의 발송 기록은 빈 값으로 시작한다.
[알림 DB 점검](NOTIFICATION_DATA.md#개발운영-db-확인)과 [보관 상태 SQL](queries/notification-retention-status.sql)을 각 환경에서 실행한다.

### 백업 복원

삭제 전 백업에는 이메일이 남을 수 있다. 백업 보관·삭제 정책을 확인한다. 저장소는 DB 백업 자동화를 제공하지 않는다.
Flyway와 만료 정리만 실행하면 백업 이후 취소한 신청이 되살아날 수 있다.
[복원 정리 SQL](../scripts/reset-restored-notifications.sql)은 격리된 복원 DB에서 신청·이메일 설정·취소 요청을 비운다.
서비스를 열기 전에 0건을 확인하고 사용자에게 재신청을 안내한다.
