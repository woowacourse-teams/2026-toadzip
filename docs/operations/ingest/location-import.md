# 단지 도로명주소 좌표 적재

## 입력 데이터

도로명주소 사이트에서 내려받은 `위치정보요약DB_전체분.zip`을 사용한다. 이 파일에는 전국 출입구의
GRS80 UTM-K 좌표가 들어 있다. 일변동 연계 API와 승인키는 사용하지 않는다.

전국 원본 전체를 서비스 DB에 복제하지 않는다. 마이홈 단지 원천 데이터의 고유 도로명주소를
메모리에 준비하고, 전체분 ZIP을 한 번 스트리밍하면서 주소가 일치하는 출입구 행만
`road_address_locations`에 저장한다. 따라서 상시 저장량은 전체 주소 규모가 아니라 단지 주소 규모에
비례한다.

ZIP 선별과 좌표 조회에서는 건물번호 끝의 부번 `-0`을 생략한 표기와 동일하게 취급한다. 예를 들어 `선수촌로 27-0`과
`선수촌로 27`은 같은 비교값을 사용하지만, `27-1`은 다른 주소다. 원천 주소와 관리자 보완값은 변경하지 않는다.
기존에 이 표기 차이로 누락된 행은 변경된 서버를 배포한 후 전체분 ZIP을 다시 적재해야 저장된다.

## 실행 순서

1. `POST /api/admin/ingest/myhome/complexes`로 마이홈 단지 원천 데이터를 먼저 수집한다.
2. `POST /api/admin/ingest/juso/location-summaries`에 월 전체분 ZIP을 multipart의 `file`로 전송한다.
3. 응답의 `targetRoadAddressCount`, `matchedRoadAddressCount`, `preparedRoadAddressCount`, `unmatchedRoadAddressCount`를 확인한다.
   주소 일치 수와 WGS84 변환까지 통과한 주소 수를 구분한다.
4. 2단계의 단지별 준비 현황에서 주소 없는 단지를 포함한 실패 목록을 확인하고 검색·직접 입력으로 보완한다.
   원천 수집·ZIP 업로드가 끝나면 준비 상태를 자동으로 갱신한다. 기능 배포 전에 수집한 원천이나
   저장된 데이터의 재비교가 필요할 때만 ‘주소·좌표 상태 확인’을 실행한다.
   저장 시 등록 준비 상태도 갱신한다. 보완 계약은 [단지 등록 현황](../../features/ingest/initial-registration.md#주소좌표-준비)을 따른다.
   기존 전체 단지 매핑(`POST /api/admin/ingest/myhome/complex-mappings`)은 [지원 종료](../../features/ingest/executions.md#실행-방법) 상태를 유지한다.

```bash
curl -X POST \
  -F 'file=@위치정보요약DB_전체분.zip;type=application/zip' \
  http://localhost:8080/api/admin/ingest/juso/location-summaries
```

## 적재 안전성

- ZIP 안에 명세의 16개 지역 TXT가 모두 있고, 각 파일이 비어 있지 않으며 예상 시도코드와 일치해야
  전국 전체분으로 인정한다.
- ZIP과 TXT는 실제 배포 형식에 맞춰 CP949를 지원하고, 행은 18개 컬럼이어야 한다.
- 전체 ZIP을 먼저 검증하고 일치 행만 메모리에 선별하므로 파일 스캔 중에는 DB 적재 트랜잭션을 열지 않는다.
- PostgreSQL `COPY`로 임시 테이블에 적재한 뒤 병합한다. 위치정보 병합과 대상 준비 상태 갱신은 같은 트랜잭션에서 실행한다.
- 같은 출입구의 기존 행은 새 좌표가 변환·검증을 통과한 경우에만 갱신한다. 일치하지 않은 기존 행도 삭제하지 않는다.
  좌표가 없거나 변환에 실패한 새 행도 원본 좌표·실패 진단을 위해 저장하되 기존 정상 행을 덮어쓰지 않는다.
- 변환 결과는 유한수·위도·경도 범위를 검사하고 UTM-K로 역변환했을 때 원본과 각 축 1m 이내인지 확인한다.
  투영 계산이 비정상 원본 좌표를 정상 범위의 위도·경도로 반환해도 역변환이 일치하지 않으면 변환 실패로 남긴다.
- 주소 일치가 0건이거나 모든 원천 주소가 누락되어도 정상 전국 ZIP이면 실패 목록·집계를 갱신하며 기존 좌표를 보존한다.
- 파일 오류, 지역 파일 누락 또는 DB 오류가 발생하면 전체 트랜잭션을 롤백해 기존 데이터를 유지한다.
- 단지 매핑과 선별 적재는 같은 실행 잠금을 사용하므로 동시에 실행되지 않는다.
- 관리자 보완값은 선별 좌표 테이블과 별도로 저장하므로 ZIP으로 덮어쓰지 않는다.
- 비공개·제한 건물은 원본에서 좌표가 비어 있을 수 있으며 해당 단지는 좌표 없음으로 기록된다.

전체분을 다시 받을 필요가 생긴 경우에만 같은 API로 병합한다. 정기 스케줄은 없다.
ZIP 적재에는 주소 API 승인키가 필요하지 않으며, 관리자 주소 검색은 기존 주소 검색 연동 설정을 사용한다.

## 스키마 배포

DB 초기화와 마이그레이션은 [Flyway 도입 절차](../database/flyway.md)를 따른다.
롤백 시에도 선별 좌표는 재사용 가능한 참조 데이터이므로 테이블을 보존한다. 테이블 삭제는 별도 승인 후 수행한다.
