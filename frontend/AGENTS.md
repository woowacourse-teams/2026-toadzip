# 프론트엔드 에이전트 지도

## 목적

- 이 파일은 `frontend/` 작업의 자동 발견 진입점이다.
- 사람의 기억 대신 저장소 설정, 가까운 테스트와 재실행한 검증 결과를 기준으로 판단한다.
- 바뀌기 쉬운 버전이나 명령을 복제하지 않고 원본 파일에 연결한다.

## 읽기 순서

1. 제품 목적과 용어는 루트 [SERVICE_OVERVIEW.md](../SERVICE_OVERVIEW.md)에서 확인한다.
2. 설치와 실행 명령은 [README.md](README.md)에서 확인한다.
3. 기술 역할과 구현 경계는 [development-standards.md](docs/development-standards.md)를 따른다.
4. 변경할 코드, 가장 가까운 테스트와 실제 설정 파일을 함께 읽는다.
5. 완료 전 [quality-gates.md](docs/quality-gates.md)의 검증과 보고 기준을 따른다.
6. 이슈, 브랜치, 커밋과 PR은 루트 [CONTRIBUTING.md](../CONTRIBUTING.md)를 따른다.

## 작업별 라우팅

| 작업 | 우선 확인 |
|---|---|
| 컴포넌트·상태·라우팅 | 개발 기준과 가까운 코드·테스트 |
| TypeScript·빌드·린트 | 개발 기준과 해당 설정 원본 |
| API·브라우저·외부 SDK·환경 변수 | 개발 기준의 외부 경계 |
| 버그·테스트·완료 판단 | 품질 게이트 |
| 의존성 추가·교체 | 개발 기준의 도입 조건과 현재 lock 파일 |

## 작업 계약

| 단계 | 필수 증거 |
|---|---|
| 시작 | Goal, 사용자에게 달라지는 결과, Constraints, Done |
| 탐색 | 관련 코드·테스트·설정 원본, 사실과 추론의 구분 |
| 변경 | 가장 작은 완성 변경, 동작 변경이면 가장 가까운 행동 테스트 |
| 완료 | 최종 작업 트리의 명령 결과, 브라우저 확인, 미검증과 위험 |

## 절대 경계

- 검사 설정을 끄거나 테스트를 약화해 통과시키지 않는다.
- 현재 요구가 없는 공통 계층, 추상화, 전역 상태와 의존성을 미리 추가하지 않는다.
- 브라우저에 비밀값을 넣지 않고 실제 인증정보를 코드, 문서와 테스트에 기록하지 않는다.
- 관련 없는 의존성 갱신, 생성 산출물과 사용자 변경을 작업에 섞지 않는다.
- jsdom 테스트나 빌드 성공을 실제 브라우저·외부 SDK 동작의 증거로 표현하지 않는다.
- 버전·명령·도구의 현재 상태가 문서와 설정에서 다르면 설정을 사실로 삼아 문서를 바로잡는다.
- 품질·보안 기준과 설정이 충돌하면 기준을 임의로 낮추지 않고 원인과 의도를 먼저 확인한다.
