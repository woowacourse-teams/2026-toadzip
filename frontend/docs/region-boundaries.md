## 연속수치지형도 대신 법정구역정보를 선택한 이유

[행정경계(시군구) 공식 페이지](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=MK&dsId=30252)의 2026-09-16 운영기관 답변에 따르면 당시 검수 중인 연속수치지형도는 2025년 기준이고, 전남광주·인천 개편 반영본은 2027년 수급 예정이다. 같은 답변이 최신 개편에는 법정구역정보 데이터셋을 이용하도록 안내한다. 따라서 페이지 갱신일만 보고 N3A_G0100000.zip을 최신 행정구역 경계로 취급하지 않는다.

## 확보한 스냅샷과 좌표계

- 원본: `AL_D001_00_20260909.zip`, 125,828,758 bytes. 저장소 밖에 보관한다.
- SHA-256: `3f8952dfda7763c2c594adb7a9f7ace1f40b996235fae6ef0d0f90f794dbce97`.
- 확보 시각 증거: 다운로드 파일 생성 시각 `2026-09-22T16:01:25+09:00`. 기준일/갱신일 `2026-09-09`와 별도로 기록한다.
- 사용한 중첩 파일: `AL_D001_00_20260909(SIG).zip`. EMD/LIO는 사용하지 않는다.
- DBF: CP949 (`.cpg` 값 949), `A0` 원본 행 ID, `A1`/`A4` 시군구 5자리 코드, `A2` 전체 이름, `A3` 레코드 날짜. 레코드 날짜를 전체 데이터 기준일로 대체하지 않는다.
- PRJ: `KGD2002_Central_Belt_2010`. GRS80, TM 위도 원점 38°, 중앙 경도 127°, 축척 1, false easting 200,000m, false northing 600,000m로 EPSG:5186의 수치와 일치한다. PROJ 9.3.0은 ESRI datum 이름 `D_Korea_Geodetic_Datum_2002`를 EPSG 별칭으로 인식하지 않으므로 `CRS.equals` 성공을 주장하지 않는다. 스크립트는 datum 선언·타원체·투영 파라미터·본초자오선·미터 단위를 명시 검증한다.
- `pyproj.Transformer.from_crs(5186, 4326, always_xy=True)`로 경도·위도 순서의 WGS84 좌표를 만든다. 변환 엔진 버전과 실제 변환 설명도 산출물에 기록한다.

## 코드 대조와 지원 범위

백엔드 `regions.csv`의 시군구 269개와 원본 256행(고유 코드 255개)을 대조한다. **266개 지역을 제공하고 3개는 명시적으로 미지원**한다. 253개는 검증한 시군구 도형이며 13개 부모 도시는 카탈로그 이름 계층의 모든 자식 구를 합쳐 내부 경계를 제거한다. 수원·성남·안양·부천·안산·고양·용인·화성·청주·천안·포항·창원·전주가 해당한다. 2자리 시도 경계는 이번 범위에 포함하지 않는다.

| 미지원 코드 | 이름 | 근거 |
| --- | --- | --- |
| 26290 | 부산광역시 남구 | 원본 A0 63과 76이 코드·이름·A4까지 같지만 약 80km 떨어진 서로 다른 도형이다. 어느 행도 임의 선택하거나 합치지 않는다. |
| 27200 | 대구광역시 남구 | 원본에 코드가 없다. 중복된 부산 남구 도형을 위치만 보고 대구 코드로 바꾸지 않는다. |
| 12790 | 전남광주통합특별시 해남군 | 점 수가 부족한 원본 도형이 있고 `make_valid` 결과에 MultiLineString 잔여물이 남는다. 잔여물을 버려 성공 도형으로 만들지 않는다. |

17개는 코드와 시군구 이름이 정확히 같고 시도 접두어만 잘못되어 명시적으로 표기를 교정한다. 52로 시작하는 15개 코드의 원본 `전북특별차지도`를 카탈로그의 `전북특별자치도`로, 제주 50110/50130의 `제주도`를 `제주특별자치도`로 고친다. 코드나 도형 위치는 바꾸지 않는다. 원본 이름·정규 이름·사유는 `sourceNameCorrections`에 모두 보존한다. 이 두 규칙 외에는 공백 정규화만 허용하고 다른 이름 불일치는 미지원한다.

## 도형 처리와 정확도

원본의 잘못된 도형 4개를 검사했다. GEOS `make_valid`로 강진(12780), 옹진(28720), 태안(44825)을 보정했다. 세 지역 모두 bbox와 모든 ring 경계를 유지하고, 이산 Hausdorff 경계 거리는 강진 약 1.53e-13m, 옹진·태안 0m이며, 면적 상대 변화는 각각 약 3.70e-15, 6.91e-16, 1.74e-9다. 태안은 중첩된 외곽선을 구멍으로 올바르게 해석하면서 polygon 개수가 3,200에서 3,198로 바뀐다. 원본 오류와 전후 polygon/hole/좌표 개수·면적 차이를 지역별로 기록한다. 해남은 위 이유로 제외한다.

화성 부모 도시는 EPSG:5186 union에서 생긴 극미세 틈 때문에 WGS84 변환 시 유효하지 않은 링이 생겼다. 화성 자식 4개에만 **1e-7m 고정 precision grid**를 적용한 뒤 union한다. 각 자식의 실제 polygon/hole 개수를 그대로 보존하며 최대 경계 이동은 약 6.97035e-8m(71nm 미만), 면적 상대 변화는 최대 7.61e-13이다. 합친 면적 상대 차이는 약 5.86e-13이다. 이 정규화로 부모의 34개 polygon은 그대로 두고 부동소수점 틈으로 생긴 hole은 51→12개가 되며 모든 WGS84 링이 유효해진다. 원본 자식에 있는 약 21.58km²의 실제 구멍은 보존한다. 남은 11개 작은 구멍(약 0.0022~2.289m²)은 원본 자식 도형 사이의 틈이므로 크기만으로 제거하지 않는다. 화성은 이후 단순화 없이 배포하고 자식별 전후 도형 수·이동 거리·면적 차이를 `projectionFallback`에 기록한다. 고정 grid가 실제 원본 섬/구멍을 없애면 변환기가 즉시 실패한다.

지도 표시용으로 EPSG:5186에서 5m 허용 오차, `preserve_topology=True` 단순화를 적용한다. 각 지역의 모든 섬과 구멍 개수를 보존한다. 단순화 도형이 잘못되거나 섬/구멍 개수가 바뀌면 그 지역 전체를 원본 정밀도로 유지한다. WGS84 변환 후 유효 도형, 닫힌 링, 유한한 좌표, 정확한 bbox를 재검사하고 반시계 외곽선/시계 구멍 방향으로 저장한다. 소수점 반올림으로 작은 섬이 무너지지 않도록 float 정밀도를 유지한다.

산출물 `provenance.json`의 각 지역에는 원본·단순화 좌표 수, polygon/hole 개수, 파일 bytes, 면적 상대 차이와 GEOS와 같은 정점→선분 정의의 **이산** Hausdorff 경계 거리를 기록한다. 공간 인덱스로 동일한 최소 선분 거리를 계산하며, 기존 GEOS 전체 265개 지역 결과와 최대 약 4.51e-11m 차이로 일치하는 것을 검증했다. 이는 경계 정점 기준 측정이며 연속 곡선 전체의 엄밀한 최대 거리를 주장하지 않는다. 법적 경계 확정이나 측량 자료가 아닌 서비스 지도 표시용 데이터다.

## 배포 크기와 측정 결과

- GeoJSON 266개 합계 25,691,716 bytes, 파일별 gzip 합계 9,958,055 bytes. 한 지역 파일 중앙값은 약 59.7KB다.
- 최대 파일: 신안 1,111,597 bytes(856개 polygon, 2개 hole, 28,367좌표), 태안 1,078,829 bytes(3,198개 polygon, 2개 hole, 27,289좌표). 태안처럼 작은 섬이 많은 지역의 SDK 객체 생성 비용을 별도로 확인한다.
- 앱에 포함하는 이름·코드·bbox 인덱스는 75,312 bytes이고 geometry는 포함하지 않는다.
- 부모 도시 합치기를 포함한 가공 전/후 좌표 수는 892,305 → 654,160이다. 전체 섬/구멍 보존을 위해 무리하게 크기를 줄이지 않는다.
- 최대 이산 Hausdorff 경계 거리 4.99997755m, 최대 면적 상대 변화 약 0.031905%(인천 제물포구 28125).
- 함평·옹진·보령·태안·군산은 단순화 유효성/개수 검사에서 원본 정밀도로 되돌렸고 화성은 위에 설명한 별도 투영/union fallback을 사용한다.

## 재생성과 검증

[변환 스크립트 안내](../scripts/region-boundaries/README.md)의 고정된 Python 도구 버전으로 오프라인 재생성한다. 실제 원본 SHA-256을 강제하며 코드 중복·이름 오기·도형 보정·누락 코드·부모 도시 합치기와 모든 지역 크기를 `provenance.json`에 기록한다. 원본이 없어도 `verify_assets.py`로 전체 산출물의 카탈로그 대응, geometry/bbox/속성, 섬/구멍 수, 지원 범위와 출처를 검증할 수 있다. 별도 단위 테스트는 이름 검증·중복 코드·부모 도시 내부 선 제거·자식 누락·섬과 구멍 보존·잘못된 단순화 fallback을 검사한다.

## 제공 방식

배포 버전은 `vworld-20260909-3f8952dfda77-p2`이다. 앞부분은 원본 기준일과 해시, `p2`는 가공 규칙 버전이다. 검증된 지역별 GeoJSON을 `/region-boundaries/<version>/<regionCode>.geojson`에 배포한다. 버전은 원본과 가공 결과를 구별해야 하며 같은 경로의 내용을 덮어쓰지 않는다. 기존 페이지가 참조하는 이전 버전 파일은 새 배포 직후 제거하지 않는다.

앱에는 가벼운 지역 이름·코드·bbox 인덱스만 포함한다. 검색 선택 시 인덱스로 지도 범위를 즉시 맞추고 상세 경계 파일은 비동기로 받는다. 상세 파일 응답은 카메라를 움직이지 않는다. 우리 정적 서버만 조회하므로 VWorld API 키는 필요 없다.

성공한 정적 파일은 HTTP 캐시를 사용한다. 메모리에는 최근 검증에 성공한 8개 지역만 보관하고 실패/취소 응답은 저장하지 않는다. 캐시는 브라우저가 삭제할 수 있으므로 서버 원본 파일이 항상 필요하다. 없는 경계 파일은 SPA HTML 대신 404로 응답한다.
