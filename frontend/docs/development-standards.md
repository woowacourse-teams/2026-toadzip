# 프론트엔드 개발 기준

## 설정 원본과 기술 역할

정확한 버전과 명령은 아래 파일만 원본으로 삼고 이 문서에 복제하지 않는다.

| 판단 대상 | 원본 또는 역할 |
|---|---|
| Node.js | [`.nvmrc`](../.nvmrc)와 [`package.json`](../package.json)의 `engines.node` |
| npm | `package.json`의 `packageManager` |
| 명령·직접 의존성 | `package.json` |
| 재현할 전체 의존성 그래프 | [`package-lock.json`](../package-lock.json) |
| TypeScript 검사 | [`tsconfig.json`](../tsconfig.json)과 참조 설정 |
| 정적 검사 | [`.oxlintrc.json`](../.oxlintrc.json) |
| 개발·테스트·프로덕션 빌드 | [`vite.config.ts`](../vite.config.ts) |
| 설치·실행 방법 | [`README.md`](../README.md) |

Node.js 계약을 변경할 때는 같은 행의 두 정의를 함께 갱신한다.

- React는 화면과 상호작용을, React Router는 URL과 탐색을 소유한다.
- TypeScript는 정적 계약이며 외부 데이터의 런타임 안전을 대신하지 않는다.
- Vitest와 React Testing Library는 jsdom에서 사용자 행동을 검증한다.
- Vite 빌드 결과는 정적 `dist/`이며 AWS·Nginx 배포 구성은 별도 인프라 결정이다.
- 지도는 NAVER Maps JavaScript SDK 직접 연동을 기준으로 하며 React 래퍼를 미리 도입하지 않는다.
- 전역 상태, 서버 캐시, UI·CSS와 E2E 도구는 실제 문제가 생기기 전에 선정하지 않는다.

## 코드와 상태

- 기능 변경은 사용자에게 관찰 가능한 동작 하나를 완성한다.
- `main.tsx` 같은 진입점에는 부트스트랩만 두고 제품 규칙을 넣지 않는다.
- 컴포넌트는 PascalCase, 함수·변수는 camelCase, 훅은 `use`로 시작하고 테스트는 `*.test.ts(x)`로 둔다.
- 상태는 사용하는 가장 가까운 곳에 두고 계산 가능한 값이나 외부 데이터의 복사본을 중복 저장하지 않는다.
- 공유 가능한 비민감 검색·탐색 상태는 URL에 두고 일시적이거나 민감한 상태는 로컬에 둔다.
- 재사용을 예상한다는 이유만으로 공통화하지 않고 두 번째 실제 사용처에서 추출을 검토한다.
- UI·스타일은 [디자인 시스템](design-system.md)의 기존 토큰·컴포넌트를 우선 사용한다. 공통 역할이나 사용 계약을 바꾸면 문서와 가까운 테스트를 함께 갱신한다.
- 비동기 화면은 실제 가능한 로딩, 빈 결과, 오류와 성공을 구분하며 실패를 빈 성공으로 위장하지 않는다.
- 버튼과 입력은 의미 있는 HTML 요소와 접근 가능한 이름을 사용하고 키보드 동작을 보존한다.

## TypeScript와 외부 경계

- `strict`와 기존 lint·build 검사를 유지한다.
- URL, storage, 네트워크 응답과 SDK 값은 신뢰하지 않고 `unknown`에서 검증해 좁힌다.
- 오류를 숨기기 위한 `any`, `@ts-ignore`, 무근거 non-null assertion을 사용하지 않는다.
- 외부 타입 보완이 불가피하면 API·SDK 경계 한 곳에 격리하고 이유와 검증을 남긴다.
- 브라우저·네트워크·SDK 부수효과는 렌더링과 분리하고 등록한 이벤트와 리소스를 정리한다.
- SDK 로딩, 초기화, 실패 처리와 해제의 소유자를 하나로 두어 컴포넌트에 흩뜨리지 않는다.
- 브라우저에 전달되는 `VITE_*` 값은 모두 공개 정보로 취급한다.
- Client Secret, 서버 토큰과 비공개 키가 필요한 호출은 프론트엔드에서 직접 수행하지 않는다.
- 필수 설정이 없으면 명시적으로 실패하고 실제 Client ID를 저장소나 fixture에 기록하지 않는다.
- 환경 변수를 추가하면 `frontend/.env.example`에 실제 값 없이 이름, 용도, 필수 여부와 누락 동작을 남긴다.
- 외부 문자열을 `dangerouslySetInnerHTML`로 직접 렌더링하지 않고 불가피하면 경계에서 검증·정제한다.
- 외부 입력으로 URL을 만들 때 허용할 프로토콜과 호스트를 검증한다.

## 의존성 변경 기준

새 의존성은 다음을 모두 확인한 뒤 최소 범위로 추가한다.

1. 현재 브라우저 API와 설치된 의존성으로 해결할 수 없는 구체적 문제인가.
2. 유지보수 상태, 보안·라이선스와 번들 영향이 수용 가능한가.
3. 테스트 방법과 제거 가능한 경계가 있는가.
4. 도입 근거와 대안을 이슈 또는 PR에 남겼는가.

lock 파일을 직접 편집하거나 현재 작업과 무관한 버전 갱신을 함께 넣지 않는다.

## PDF 미리보기

공고 첨부파일은 브라우저 내장 PDF 플러그인 없이 확인할 수 있도록 `pdfjs-dist` legacy 빌드를 모달을 열 때 지연 로딩한다. native iframe은 앱 내 브라우저에서 빈 화면이 확인되어 채택하지 않았다. 라이선스는 Apache-2.0이며 버전은 package.json/lock에 고정한다. 설치 시점 npm audit 결과 취약점 0건이었다.

`npm run dev`와 `npm run build`의 pre 스크립트가 `scripts/prepare-pdf-assets.mjs`를 실행해 설치 버전의 CMap, 표준 폰트, WASM 및 라이선스를 `public/pdfjs-{version}/`에 준비한다. 생성 디렉터리는 Git에서 제외되지만 dist에는 포함된다. PDF.js 교체·제거 경계는 PdfDocumentPreview 컴포넌트와 이 자산 준비 스크립트다.

배포 Nginx는 `nginx.conf`에서 `.mjs`를 `application/javascript`로 제공해야 한다. PDF worker가 `application/octet-stream`으로 응답하면 첨부 API가 성공해도 브라우저의 모듈 MIME 검사에서 미리보기가 실패한다. 설정 변경은 프론트 이미지를 다시 빌드하고 컨테이너를 재생성해 반영한다. `/assets/`의 기존 잘못된 MIME 응답도 장기 캐시되므로 worker URL에 `mime=javascript` 쿼리를 붙여 이전 캐시를 우회한다. 이 쿼리는 캐시 키를 바꾸는 용도이며 응답 형식은 Nginx의 MIME 매핑이 결정한다. 배포 후 페이지를 새로고침하고 worker 요청의 `Content-Type`을 확인한다.

`usePdfViewer`는 PDFViewer의 연속 스크롤·렌더 버퍼와 PDFFindController의 전체 문서 검색·텍스트 강조를 연결한다. build 모듈 초기화 후 web viewer를 읽고, 문서 해제·AbortSignal·지역화 객체·worker를 함께 정리한다. SDK 스타일은 `@scope` 안에 두어 전역 색상과 다른 화면에 영향을 주지 않는다. 검색 단축키는 현재 모달에만 등록하며 PDF 스크립트와 폼 편집은 활성화하지 않는다.


## HWP·HWPX 미리보기

`@rhwp/core` 0.8.6(MIT)을 사용한다. 브라우저에서 한글 원본을 해석하며 외부 변환 서비스로 업로드하지 않는다. HwpDocumentPreview를 지연 로딩하고 별도 worker에서 WASM을 초기화한다. 약 9.94 MB의 WASM은 한글 문서를 처음 열 때만 내려받고 Vite 해시 자산으로 캐시한다. 라이선스는 pre 스크립트가 `public/rhwp-{version}/LICENSE`로 복사한다. SDK를 제거하거나 교체하는 경계는 이 컴포넌트, worker와 자산 준비 스크립트다.

기존 원본 다운로드 API(`download=true`)를 이용하며 PDF 전용 미리보기 API의 형식 검증은 유지한다. 페이지별 SVG는 Blob 이미지로 표시하고 문서의 마크업을 DOM에 삽입하지 않는다. 쪽 크기에 맞춘 자리 표시자를 세로로 배치하고 화면에 보이는 쪽과 앞뒤 한 쪽만 SVG 이미지로 유지한다. 현재 쪽은 스크롤 위치를 기준으로 표시한다. 멀어진 이미지 URL은 즉시 해제하며 파일 전환·닫기·실패 시 worker, URL과 타이머를 정리한다. 문서 해석·전체 검색은 60초, 한 쪽 렌더링은 30초 제한을 둔다.

`검색` 또는 모달 내부 `⌘F`/`Ctrl+F`로 문서 전체를 검색한다. worker가 페이지별 텍스트 위치를 읽어 표 안의 텍스트와 같은 문단의 서식 run을 검색하고 좌표를 반환한다. 대소문자와 연속 공백은 정규화하며 서로 다른 표 셀은 합치지 않는다. 결과 수·현재 위치·강조를 표시하고 Enter/Shift+Enter로 다음/이전 결과를 순환한다. Escape는 검색창만 닫는다. 한글 IME 조합 중에는 검색하지 않으며 200ms 입력 지연 처리와 검색 ID로 오래된 결과를 배제한다. worker는 쪽마다 실행을 양보해 새 검색과 화면 렌더링을 처리한다. 현재 쪽의 추출 텍스트는 접힌 일반 텍스트 영역에서 읽고 복사할 수 있다. 이미지 속 글자(OCR), 페이지 경계를 가로지르는 검색어는 검색 대상이 아니다.

실제 부산문현 LH HWPX 공고문과 관세청 공개 HWP에서 한글·표·이미지와 페이지 이동을 확인했다. 원본 글꼴이나 페이지 나눔은 달라질 수 있다(동일 LH 공고 PDF 53쪽, HWPX 뷰어 55쪽). 암호·손상·지원되지 않는 HWP 구조 및 구형 브라우저에서는 다운로드로 안내한다. ZIP·DOCX·XLSX 등은 미리보기 대상이 아니다. 검증한 버전은 고정하며 라이브러리 교체 시 실제 문서 검증을 다시 수행한다.

첨부 API 대기 시간은 서버 외부 다운로드 제한 120초를 포함하도록 150초다. 파일 한도의 기본값은 100 MiB이며 백엔드 `ANNOUNCEMENT_ATTACHMENT_MAX_SIZE`로 조절한다.

PDF·HWP·HWPX 미리보기를 위해 받은 원본 Blob은 선택한 첨부파일이 소유하며 다운로드에도 그대로 재사용한다. 렌더링 결과를 저장하거나 원본 바이트를 변환하지 않고, 첨부파일의 원래 파일명을 사용한다. Blob이 아직 없거나 미리보기 요청이 실패한 경우에만 기존 다운로드 API를 호출한다. 미리보기 로딩 중에는 별도 다운로드 요청이 발생할 수 있다.

파일 전환·모달 닫기 시 미리보기 요청과 URL, 선택 상태의 Blob 참조를 정리한다. 사용자가 시작한 다운로드 API 요청은 닫기와 무관하게 기존 150초 제한까지 계속 진행한다. 다운로드는 미리보기와 별도의 객체 URL을 사용하므로 미리보기 정리가 다운로드를 무효화하지 않는다. 다운로드 완료 이벤트는 제공되지 않으므로 브라우저가 읽기를 시작할 여유를 두고 60초 후 해당 URL을 해제한다. 이미 시작된 읽기는 URL 해제로 중단되지 않는다.
