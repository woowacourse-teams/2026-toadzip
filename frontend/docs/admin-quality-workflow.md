# 관리자 데이터 검토 사용법

담당자·기한과 화면 알림은 [검토 업무 관리](admin-review-tasks.md)를 참고한다.

## 1. 검토할 대상을 찾기

`검토할 데이터`에서 단지·공고와 검토 사유를 선택한다. 빠진 항목을 보고 `비교·검토`를 누른다.
빠른 조건으로 원천 변경·정보 누락·보류를 좁힐 수 있다. `내 담당 업무`는 별도 화면에서 확인한다.
일반 단지·공고 목록에서 연 상세는 읽기 화면으로 시작하며 `수정`을 눌러 편집한다.
검토 목록의 `비교·검토`는 해당 대상의 `데이터 검증` 탭으로 바로 이동한다.
0·미설치는 빠진 값으로 간주하지 않는다. 원천에 없는 값은 추정해 채우지 않는다.

## 2. DB 원천과 비교·수정

- 단지 기본정보: 기존 `데이터 검증`에서 바로 비교한다.
- 주택형: 같은 화면의 `주택형 원천 비교·수정`을 펼친다.
- 공고: `데이터 검증`에서 공고 기본정보·공급행·공급대상 임대조건을 선택한다.
- 자동 연결된 원천을 확인하고 필요한 자료는 `원천 검색·연결`에서 근거를 적어 연결한다.
- `이 원천값 사용` 또는 직접 입력 후 변경 전후·근거를 확인해 저장한다.
- 금액 문자열의 단위와 적용 범위는 직접 확인한다. 단지 전체 세대수를 주택형 세대수에 적용하지 않는다.
- 충돌하면 입력은 남고 저장은 잠긴다. 필요한 입력을 보관한 뒤 다시 조회해 대조한다.

## 3. 공식 목록과 단지 누락 조사

`단지 누락 대조`의 `공식 API 자료로 목록 준비하기`를 연다.
필요하면 공식 단지 API 수집을 요청하고 상태를 확인한다. 서버 API 키 설정은 기존 수집 운영 화면을 따른다.
`저장 자료 불러오기`에서 기관·이름·주소를 확인하고 현재 페이지를 대조 목록으로 가져온다.
기존 수기·JSON 입력과 같은 대조를 실행해 미등록·동일성 검토·휴지통·조회 실패 후보를 조사한다.

마이홈 단지 API의 이름·도로명주소가 있는 자료를 지원한다. 같은 페이지의 주택형 중복은 제거한다.
목록 기준일은 마지막 수집일이며 공식 문서의 유효일을 의미하지 않는다.
`검색 범위 전체 가져오기`는 최대 250쪽·5,000행을 두 번 조회해 페이지 간 중복과 조회 중 변경을 확인한다.
전체 가져오기 결과는 50개를 넘어도 순차 대조한다. 검색 조건은 유지하며 주소·시각 미확인 제외 건수를 표시한다.
조회 실패·중지·한도 초과·조회 중 변경이면 불완전한 목록을 전달하지 않는다. DB 저장 범위의 조회이며 기관의 공식 전체 목록 완전성을 보증하지 않는다.
LH 공고 상세와 LH 임대 단지 목록도 선택할 수 있다. 이름이 있는 주소 미제공 행은 후보 조사 대상으로 보존한다.
도로명주소가 없으면 이름으로 검색하되 일치나 미등록으로 확정하지 않는다. 지번주소·접수처 주소를 도로명주소로 자동 변환하지 않는다.
결과의 `이 단지 주소 보완 후 다시 대조`에서 공식 원문의 도로명주소를 보완한다.
다른 기관 홈페이지에서 내려받은 UTF-8 CSV·TSV나 표 붙여넣기도 지원한다. 출처 URL·기준일·기관을 입력하고 제목 행을 포함한다.
`단지명`(또는 아파트명·주택명·name·hsmp_nm·complex_name·complex_label), `도로명주소`(또는 소재지도로명주소·roadAddress·rn_adres)를 읽는다.
일반 `주소`·지번주소 열은 도로명주소로 추정하지 않는다. CSV·TSV는 최대 5,000행·1MB이며 잘못된 열 수·따옴표·중복은 오류로 표시한다.
공고 홈페이지 수집은 기존 `공고 수집·검토`에서 지원하는 기관 경로를 사용한다.

## 4. PDF·에이전트 작업

- `PDF로 보완`에서 PDF와 필요한 페이지를 선택한다.
- 텍스트 없는 페이지는 `OCR`로 읽는다. 한 번에 최대 5쪽·5분이며 한국어·영어 모델을 사용한다.
- OCR은 브라우저 worker에서 처리한다. worker·WASM·언어 데이터는 같은 서버에서 제공하며 PDF를 외부 OCR·AI 서비스로 보내지 않는다.
- OCR 결과는 추정 텍스트다. 인식 점수는 정확성 보장이 아니며 숫자·단위·각주를 원문과 대조한다.
- `에이전트 요청 복사` 또는 기존 자료 다운로드로 사용하는 에이전트에 전달하고 결과 JSON을 가져와 검증한다.
- `로컬 폴더로 에이전트 자동 연결`은 요청·결과 파일을 자동 교환한다. 설치·제한은 [로컬 폴더 연결](admin-agent-exchange.md)을 따른다.
- `원본과 작업 보관`은 현재 브라우저에 PDF·페이지 선택·추가된 수정안·메모를 보관한다(최대 5개·100MB).
- 같은 대상을 보관하면 이전 초안을 대체한다. 수기 입력은 먼저 수정안에 추가한다.
- 이어서 하기에서는 원본을 다시 열어 해시·대상을 확인하고 재추출한다. OCR은 다시 실행하며 선택 확인은 복원하지 않는다.
- DB 버전이 달라졌으면 최신 값으로 수정안을 다시 작성한다. 브라우저 초안은 다른 기기에 동기화하지 않는다.
- `관리자 공유 원본 보관함`의 서버 보관은 별도다. 25MB 이하 공식 원본을 서버 DB에 보관하고 다른 관리자도 내려받을 수 있다.
- 서버 원본은 해시로 중복을 제거하며 기존 원본을 덮어쓰지 않는다. 작업 초안 저장과 DB 값 반영은 별개다.
- `다른 관리자와 공유하는 작업 초안`은 PDF 원본과 페이지·추가된 수정안·메모를 서버에 보관한다.
- 다른 기기에서는 PDF를 선택하지 않고 `최신 공유 초안 확인 → 공유 초안 복원`으로 재개한다.
- 원본 해시를 확인해 재추출하고 수정안 검증·원문 확인을 다시 수행한다. OCR과 확인 체크는 복원하지 않는다.
- 다른 관리자의 저장과 충돌하면 현재 입력을 유지하고 저장을 잠근다. 최신 초안을 확인한 뒤 로컬 내용과 비교해 저장하거나 복원한다.
- DB 버전이 달라진 초안은 원본·입력만 복원하며 최신 값으로 수정안을 다시 작성해야 한다.
- 가져온 결과로 교체하거나 검증된 JSON을 편집하기 전 입력·메모는 브라우저 복구 기록에도 보관한다. 보관 실패는 화면에 표시하며 현재 입력은 유지한다.
- `새로고침 후에도 남는 입력 복구 기록`에서 직접 보관하거나 이전 기록을 선택 복원한다. 같은 대상·DB 버전·PDF의 최근 10개, 전체 최대 50개·텍스트 5MB다.
- 보관 한도에 도달하면 필요한 내용을 먼저 복원·다운로드하고 `선택한 복구 기록 삭제`에서 확인 후 해당 기록만 지울 수 있다. 현재 입력과 다른 PDF 기록은 유지한다.
- 복구 기록에는 원본 PDF·OCR 결과·원문 확인 선택을 넣지 않는다. 같은 PDF를 다시 열어 추출한 뒤 복원하고 검증·원문 확인을 다시 수행한다. 다른 브라우저·기기와 동기화하지 않는다.

실제 공개 문서 검증의 재현 방법과 범위는 [공식 PDF 검증](admin-public-pdf-verification.md)을 참고한다.

## 5. 다음 수집의 변경 확인

원천을 확인하고 수정할 값이 없으면 근거를 적어 `현재 원천 확인 기록`을 누른다.
다음 수집 이후 확인했던 원천의 값이 바뀌거나 사라지면 `검토할 데이터 → 원천 변경·소실`에 나타난다.
현재값을 유지할지 수정할지 검토하고 새 원천 확인 기록을 남긴다. 값 수정·등록값 검토 기록은 별개다.

서버 계약은 [관리자 데이터 검토 흐름](../../backend/docs/admin-quality-workflow.md),
기존 흐름은 [DB 단지 비교](complex-comparison.md)·[PDF 보완](pdf-data-review.md)을 참고한다.
