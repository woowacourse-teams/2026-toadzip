# 관리자 데이터 검토 사용법

변경·검토 이력에서 실제 처리한 관리자와 시각을 확인한다.

## 1. 검토할 대상을 찾기

`검토할 데이터`에서 단지·공고와 검토 사유를 선택한다. 빠진 항목을 보고 `비교·검토`를 누른다.
빠른 조건으로 원천 변경·정보 누락·보류를 좁힐 수 있다.
일반 단지·공고 목록에서 연 상세는 읽기 화면으로 시작하며 `수정`을 눌러 편집한다.
검토 목록의 `비교·검토`는 해당 대상의 `데이터 검증` 탭으로 바로 이동한다.
0·미설치는 빠진 값으로 간주하지 않는다. 원천에 없는 값은 추정해 채우지 않는다.

## 2. DB 원천과 비교·수정

- 단지 기본정보: 기존 `데이터 검증`에서 바로 비교한다.
- 주택형: 같은 화면의 `주택형 원천 비교·수정`을 펼친다.
- 공고: `데이터 검증`에서 공고 기본정보·공급행·공급대상 임대조건을 선택한다.
- 자동 연결된 원천을 확인하고 필요한 자료는 `원천 검색·연결`에서 근거를 적어 연결한다.
- `이 원천값 사용` 또는 직접 입력 후 변경 전후·근거를 확인해 저장한다.
- 금액 문자열의 단위와 적용 범위는 직접 확인한다. 단지 전체 세대수를 주택형 세대수에 적용하지 않는다.
- 충돌하면 입력은 남고 저장은 잠긴다. 필요한 입력을 보관한 뒤 다시 조회해 대조한다.

## 3. 공식 목록과 단지 누락 조사

`단지 누락 대조`의 `공식 API 자료로 목록 준비하기`를 연다.
필요하면 공식 단지 API 수집을 요청하고 상태를 확인한다. 서버 API 키 설정은 기존 수집 운영 화면을 따른다.
`저장 자료 불러오기`에서 기관·이름·주소를 확인하고 현재 페이지를 대조 목록으로 가져온다.
기존 수기·JSON 입력과 같은 대조를 실행해 미등록·동일성 검토·휴지통·조회 실패 후보를 조사한다.

마이홈 단지 API의 이름·도로명주소가 있는 자료를 지원한다. 같은 페이지의 주택형 중복은 제거한다.
목록 기준일은 마지막 수집일이며 공식 문서의 유효일을 의미하지 않는다.
`검색 범위 전체 가져오기`는 최대 250쪽·5,000행을 두 번 조회해 페이지 간 중복과 조회 중 변경을 확인한다.
전체 가져오기 결과는 50개를 넘어도 순차 대조한다. 검색 조건은 유지하며 주소·시각 미확인 제외 건수를 표시한다.
조회 실패·중지·한도 초과·조회 중 변경이면 불완전한 목록을 전달하지 않는다. DB 저장 범위의 조회이며 기관의 공식 전체 목록 완전성을 보증하지 않는다.
LH 공고 상세와 LH 임대 단지 목록도 선택할 수 있다. 이름이 있는 주소 미제공 행은 후보 조사 대상으로 보존한다.
도로명주소가 없으면 이름으로 검색하되 일치나 미등록으로 확정하지 않는다. 지번주소·접수처 주소를 도로명주소로 자동 변환하지 않는다.
결과의 `이 단지 주소 보완 후 다시 대조`에서 공식 원문의 도로명주소를 보완한다.
다른 기관 홈페이지에서 내려받은 UTF-8 CSV·TSV나 표 붙여넣기도 지원한다. 출처 URL·기준일·기관을 입력하고 제목 행을 포함한다.
`단지명`(또는 아파트명·주택명·name·hsmp_nm·complex_name·complex_label), `도로명주소`(또는 소재지도로명주소·roadAddress·rn_adres)를 읽는다.
일반 `주소`·지번주소 열은 도로명주소로 추정하지 않는다. CSV·TSV는 최대 5,000행·1MB이며 잘못된 열 수·따옴표·중복은 오류로 표시한다.
공고 홈페이지 수집은 기존 `공고 수집·검토`에서 지원하는 기관 경로를 사용한다.

## 4. 공고문 확인과 JSON 입력

공고 상세의 `공고문·첨부파일`에서 공식 원문 링크와 이미 연결된 첨부파일을 연다.
공개 상세와 같은 PDF·HWP 미리보기를 사용한다. 별도 업로드·텍스트 추출·OCR·폴더 에이전트 설정은 없다.
이 기능을 통해 PDF 원본이나 작업 초안을 서버에 추가 보관하지 않는다.

신규 원공고 JSON 등록 계약은 [신규 공고 JSON 등록](../../docs/ADMIN_ANNOUNCEMENT_IMPORT.md)을 참고한다.
기존 공급정보의 구조화 자료는 공고의 `공급정보·단지 연결`에서 가져와 미리보기 후 적용한다.
두 형식은 필드 이름과 용도가 다르며 서로 대체할 수 없다.

## 5. 다음 수집의 변경 확인

원천을 확인하고 수정할 값이 없으면 근거를 적어 `현재 원천 확인 기록`을 누른다.
다음 수집 이후 확인했던 원천의 값이 바뀌거나 사라지면 `검토할 데이터 → 원천 변경·소실`에 나타난다.
현재값을 유지할지 수정할지 검토하고 새 원천 확인 기록을 남긴다. 값 수정·등록값 검토 기록은 별개다.

서버 계약은 [관리자 데이터 검토 흐름](../../backend/docs/admin-quality-workflow.md),
기존 흐름은 [DB 단지 비교](complex-comparison.md)을 참고한다.

## 6. 공급정보를 공고 단위로 보정

공고 상세의 `공급정보·단지 연결`에서 행과 대상별 조건을 함께 수정한다.
행 추가·제외·복원, 단지·주택형 연결, 공고별 명칭·면적·모집수와 순서를 변경할 수 있다.
공통 주택형이 없으면 `이 단지의 주택형 확인 → 누락된 주택형 만들기`로 생성과 연결을 함께 요청한다.
공고 모집수는 단지·주택형 전체 세대수에 반영하지 않는다. 빈 수량·금액은 미확인, 숫자 0은 확인된 0이다.
대상 모집수가 중복 없이 행 모집수와 같은 범위일 때만 수량 합계 확인을 선택한다.

공식 근거 URL·페이지·이유를 적고 `변경 미리보기 → 확인한 보정 일괄 적용`을 진행한다.
원천·연결 후보·등록값이 달라지면 적용을 거절한다. `입력을 유지하고 최신값 비교`에서 겹치는 항목을 선택한다.
응답 유실 시 같은 작업으로 결과를 확인한다. 이 탭의 새로고침 후에도 작업을 복원하며,
브라우저 저장 공간에 재확인 정보를 보관하지 못하면 적용을 시작하지 않는다.
일반 작성 중 입력을 자동 저장하는 기능은 아니므로 이동·새로고침 경고를 확인한다.

`구조화한 공급정보를 변경안으로 가져오기`는 각 입력행의 대응을 직접 지정한다.
면적 단위는 `m2`, 금액 단위는 `KRW`이며 금액은 원 단위 정수 문자열이다.
생략한 행·항목·조건은 유지하고 `null`은 미확인으로 변경한다. 가져온 뒤에도 같은 미리보기·근거 확인을 거친다.

저장 후 사용자 공고 화면과 남은 문제를 확인한다. `저장된 공급정보 검토·보류`에서
확인한 행·조건과 필드만 선택하고 판단·근거를 기록한다. 선택한 원천 필드는 실제 값 변경·소실을 추적하며,
선택하지 않은 원천이나 외부 원문 자체의 변경을 자동 판정하지 않는다.
기록은 누적하고 같은 대상의 최신 기록을 현재 판단으로 사용한다. 보정 저장은 전체 검토 완료가 아니다.

보정한 행의 원천이 사라지거나 비활성화되면 값을 유지하고 검토 목록과 작업실에서 재확인을 안내한다.
공통 주택형 수정은 별도 화면에서 영향을 받는 공고를 확인한다. 이미 면적을 검토한 공고가 있으면
그 공고의 당시 면적을 별도로 보호한 다음 공통 면적을 수정한다.
조건부 보정 되돌리기, 전체 보정 보호 해제·원천값 채택, 일반적인 행 합치기·조건 이동은 아직 제공하지 않는다.

## 7. 운영 홈·의견·알림 조사

로그인 후 운영 홈에서 수집·정제 실패, 데이터 검토, 접수 의견과 알림 발송 문제로 이동한다.
일부 집계가 실패하면 0건으로 표시하지 않고 해당 영역에서 다시 확인하도록 안내한다.
오류·검토 목록에서 상세로 들어갈 때 검색조건·페이지와 선택 대상을 유지한다.

사용자 의견은 상태·관련 단지/공고·처리 결과를 기록하고 실제 처리한 관리자와 시각을 자동으로 남긴다. 보류와 처리 완료에는 이유가 필요하다.
내부 처리 기록이며 사용자에게 메시지를 발송하지 않는다. 동시 변경은 입력을 유지하고 최신 기록과 비교한다.

알림 발송 내역은 회원·공고·상태로 조회한다. 공급자 수락, 사용자 읽음, 발송 내역 없음은 서로 다른 상태다.
실패 코드·시도 횟수·다음 재시도 시각을 확인하며 이 화면에서 알림을 재발송하지 않는다.
