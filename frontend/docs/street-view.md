# 단지 주변 거리뷰

PC 단지 상세의 주소 옆 `거리뷰` 버튼으로 주변 영상을 확인한다. 기존 GL 지도 위에
거리뷰 모달을 열고, 닫으면 지도·목록·단지 상세의 탐색 상태를 유지한다.
화면 너비 768px 미만에서는 버튼과 실행 정보 요청, SDK 로딩을 만들지 않는다.
로컬 snapshot 모드도 거리뷰를 제공하지 않는다. 가상 단지 ID로 실제 BE를 조회하지 않으며,
거리뷰 연동은 실제 API가 연결된 환경에서 검증한다.

## 화면과 실행 정보

`src/street-view/StreetViewEntry.tsx`가 이용 가능 여부, 실행 정보 조회와 모달 상태를 소유한다.
단지 상세 진입 시 확인한 뒤, 열기와 재시도 직전에 다시 조회한다. 요청은 10초로 제한하고
대상이 바뀌면 취소한다. 늦게 도착한 응답이 새 단지나 닫힌 모달을 다시 열지 않게 한다.

| 상태 | 표시와 동작 |
| --- | --- |
| 확인 중 | 거리뷰 버튼 비활성 |
| 실행 허용 | 버튼 활성; 누르면 재조회 후 초기화 |
| 정책 중단·좌표 부적합 | 버튼 비활성, 사유 안내 |
| 조회 실패 | 버튼 비활성, `다시 확인` 제공 |
| 초기화·탐색 실패 | 모달에서 실패 안내와 `다시 시도`, 닫기 제공 |

비활성 버튼은 `aria-disabled`로 포커스를 유지하고 실행을 차단한다. 사유는
`aria-describedby`로 연결하며, 마우스 오버나 포커스가 600ms 유지되면 표시한다.
Escape는 열린 사유 안내만 닫는다. 모달은 native dialog와 body portal을 사용하며
닫기·배경 클릭·iframe 내부 Escape로 종료한다. 직접 닫으면 현재 버튼으로 포커스를 돌린다.

## API와 데이터 경계

| API | 사용 목적 |
| --- | --- |
| `GET /api/v1/complexes/{complexId}/street-view` | 실행 여부, 정책 버전, 검색 위치·시선 대상·시야 설정 |
| `GET /api/auth/csrf` | 이벤트 POST에 필요한 토큰과 헤더 이름 |
| `POST /api/v1/street-view/events` | 최초 초기화의 시작과 종료 결과; 성공은 빈 `204` |

`api.ts`는 응답을 런타임 검증하고 `no-store`로 요청한다. 활성 응답의 canonical
`complexId`, `policyRevision`, `initialization`을 실행 시도에 묶는다. 상세 API 좌표를
대신 사용하거나 별도 주소 검색·좌표 저장·장기 캐시를 추가하지 않는다.
정책과 이벤트 필드, 오류 코드의 원본은 [BE 거리뷰 명세](../../backend/docs/street-view.md)다.

## GL 지도와 iframe 분리

메인 앱은 기존 GL SDK를 유지하고, 동일 출처 `/street-view.html`에서 `panorama` SDK만
로드한다. 이 문서의 `entry.ts`는 메인 앱 진입점을 import하지 않는다. 부모는 모달·API·
시간 제한·결과 보고를, 자식의 `runtime.ts`는 SDK·초기 방향·촬영일·크기 변경을 소유한다.

부모와 자식은 `protocol.ts`의 버전이 있는 메시지를 사용한다. 출처와 현재 상대 window,
메시지 형식을 검증하고, `BOOT_READY` 이후 `INIT`에서 시도 ID를 한 번 연결한다.
이후 메시지는 시도 ID도 확인한다. 좌표는 URL에 넣지 않으며, 유효한 부모 초기화 없이
직접 열린 문서는 SDK를 실행하지 않는다.

Vite는 `index.html`과 `street-view.html`을 각각 빌드한다. 배포 시 `dist/street-view.html`과
함께 생성된 해시 자산을 모두 제공해야 한다. [`nginx/app.conf`](../nginx/app.conf)는 거리뷰
HTML에 `no-store`, 동일 출처 iframe 제한을 적용하고, 파일이 없으면 SPA 대신 `404`를 반환한다.
SDK에는 기존 공개 설정 `VITE_NAVER_MAPS_CLIENT_ID`를 사용한다.

## 초기 방향과 시간 제한

BE의 `searchPosition`으로 파노라마를 조회하고 `init`과 `pano_status: OK`를 모두 기다린다.
이벤트 순서는 가정하지 않는다. `fromCoordToPov(lookAtPosition)`의 유효한 `pan`과 BE의
`tilt`, `fov`를 최초 한 번 적용한다. 거리 계산이나 최소 거리 조건은 두지 않는다.
변환 정보가 늦으면 최대 1초만 기다리고, 계산할 수 없으면 SDK 기본 방향으로 표시한다.
이 경우 직접 화면을 움직여 주변을 확인하도록 안내하며, 이후 이동에는 자동 정렬하지 않는다.

SDK 준비는 15초, iframe 실행부터 최초 표시까지는 전체 30초로 제한한다.
방향 준비 대기도 전체 제한에 포함하며, 같은 단계의 통지가 반복되어도 기한을 늘리지 않는다.
문서·SDK·파노라마 실패를 구분하지만 파노라마 `ERROR`를 촬영 데이터 없음으로 단정하지 않는다.
재시도는 실행 정보 재조회, 새 시도 ID와 새 iframe으로 수행한다.

거리뷰 이동·회전·확대·축소와 확대 컨트롤을 제공하고, 항공뷰 전환은 제외한다.
네이버 로고와 출처 표시는 유지한다. 촬영일은 위치 변경에 맞춰 갱신하며 없으면
`촬영일 미제공`으로 표시한다. 촬영일 누락 때문에 영상 표시를 지연하지 않는다.

## 관측과 제공 정책

`events.ts`는 실제 초기화마다 UUID를 생성해 `STARTED`와 최초 종료 결과 한 건만 보고한다.
종료는 `READY`, `FAILED`, 초기화 중 직접 닫기·대상 변경의 `CANCELLED` 중 하나다.
React effect 재등록은 새 시도나 취소로 취급하지 않는다. 정상 표시 이후의 탐색 오류는
화면에서 처리하고 초기화 결과를 변경하지 않는다. 화면 폭 변경·페이지 이탈은 BE에 정의된
취소 사유가 없으므로 결과를 추정해 전송하지 않는다.

수집은 모달과 별도 수명주기로 실행하며 CSRF 응답의 `headerName`을 사용한다.
동시에 필요한 CSRF 준비 요청을 공유하고, 수집은 3초 제한 안에서 시도하되 자동 재전송하지 않는다.
수집 실패가 거리뷰 표시를 막지 않는다. SDK 오류 원문·URL·좌표·회원 정보는 전송하지 않는다.
닫기·대상 변경·화면 폭 변경 시 SDK 이벤트, 타이머, 크기 관찰자와 iframe을 정리한다.

BE 정책의 초기값은 OFF다. FE 배포만으로 제공을 활성화하지 않는다. 대상 환경에서 SDK 인증,
영상·초기 방향·실패 안내·종료 후 지도와 상세 유지 등을 확인한 뒤 관리자 정책 API로 별도 활성화한다.
API 허용이나 `READY`는 외관 식별 성공을 보장하지 않는다. 실제 SDK·레이아웃은 브라우저에서
확인하고 자동 검사·빌드 결과와 구분한다. 검증 범위는 [품질 게이트](quality-gates.md)를 따른다.
