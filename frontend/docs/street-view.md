# 단지 주변 거리뷰

PC 단지 상세의 주소 옆 `거리뷰` 버튼을 누르면 상세 오른쪽의 지도 영역에서 주변 영상을
확인한다. 상세는 계속 조작할 수 있고, `지도 보기`로 기존 지도 탐색으로 돌아온다.
거리뷰 자체의 열기·닫기는 URL·방문 기록·지도 카메라를 변경하지 않는다.
화면 너비 768px 미만과 로컬 snapshot 모드에서는 버튼·실행 정보 요청·SDK 로딩을 만들지 않는다.
가상 단지 ID로 실제 BE를 조회하지 않으며, 연동은 실제 API가 연결된 환경에서 검증한다.

## 화면과 상태 소유권

`PublicHousingExplorer`가 기능 전용 `useStreetView` 훅으로 실행 정보와 세션을 소유한다.
`StreetViewEntry`는 버튼·설명·다시 확인을, `StreetViewPanel`은 지도 영역의 로딩·실패·영상·
촬영일을 표시한다. 거리뷰에는 native dialog, body portal, 배경 dim이나 포커스 트랩을 사용하지 않는다.

단지 상세와 GL 지도는 같은 DOM·크기로 유지한다. 덮인 지도 캔버스는 입력·포커스에서 제외하고
지도 전용 필터·컨트롤은 숨기며, 상세까지 포함하는 workspace 전체를 inert로 만들지 않는다.
상세와 거리뷰는 공통 패널 너비·간격 토큰을 사용한다. 목록은 거리뷰가 열린 동안 표시만 접고
DOM·탭·페이지·스크롤을 보존한다. 목록 모드를 덮어쓰거나 과거 값을 별도로 저장·복원하지 않는다.
거리뷰가 열린 동안 앱 외곽은 `overflow: clip`으로 유지해 키보드 포커스 이동으로 전체 화면이
밀리지 않게 한다. 상세·목록의 내부 스크롤은 그대로 둔다.

단지 상세 준비 시 이용 가능 여부를 조회하고, 열기·재시도 직전에 다시 조회한다. 요청은
10초로 제한하며, 대상 변경·닫기 뒤의 늦은 응답이 이전 거리뷰를 다시 열지 않게 한다.

| 상태 | 표시와 동작 |
| --- | --- |
| 확인 중 | 닫힌 거리뷰 버튼 비활성 |
| 실행 허용 | 버튼 활성; 누르면 재조회 후 초기화 |
| 정책 중단·좌표 부적합 | 닫힌 버튼 비활성, 사유 안내 |
| 조회 실패 | 닫힌 버튼 비활성, `다시 확인` 제공 |
| 초기화 실패 | 영역에서 실패 안내와 `다시 시도`, `지도 보기` 제공 |
| 거리뷰 열림 | 버튼은 `aria-pressed=true`; 재조회 결과와 무관하게 다시 눌러 닫을 수 있음 |

버튼과 영역은 `aria-controls`로 연결한다. 비활성 버튼은 `aria-disabled`로 포커스를 유지하고
실행을 차단한다. 사유는 `aria-describedby`로 연결하며, 마우스 오버나 포커스가 600ms
유지되면 표시한다. Escape는 열린 사유 안내만 닫는다.

## 탐색과 키보드

| 동작 | 결과 |
| --- | --- |
| `지도 보기`, 활성 거리뷰 버튼, 거리뷰 Escape | 거리뷰만 종료, 상세 유지, 현재 거리뷰 버튼으로 포커스 복귀 |
| 상세 X | 거리뷰와 상세 종료 후 기존 목록 복귀 |
| 다른 단지·공고, 상세 뒤로가기 | 거리뷰 종료 후 선택한 상세로 전환; 새 거리뷰 자동 실행 없음 |
| 공고·최근 본·지역 목록, 검색 결과, 지역 변경·초기화 | 거리뷰 종료 후 해당 탐색 수행 |
| 통합 검색 활성화 | 공백 제외 두 글자 이상 입력 시 종료; 검색창에 포커스만 주면 유지 |
| 브라우저 뒤로·앞으로, 상세 경로 변경 | 거리뷰 종료 후 경로 적용; 과거 거리뷰 자동 복원 없음 |
| 알림·로그인 등 내부 모달 | 거리뷰와 상세 유지, 해당 모달부터 닫기 |
| 767px 이하로 전환 | 거리뷰 정리, 모바일 상세 유지; PC 복귀 시 자동 실행 없음 |
| 페이지 이탈 | 요청·iframe·자원 정리 |

열린 내부 모달·툴팁, 거리뷰, 상세 순으로 Escape를 처리한다. 거리뷰가 전역 capture로 모든
Escape를 가로채지 않는다. iframe의 `CLOSE_REQUEST`도 거리뷰만 종료한다.
진입 시 `지도 보기`로 포커스를 이동하되, 이후 비동기 READY·실패는 상세를 읽는 사용자의
포커스를 빼앗지 않는다. 대상·검색·목록 전환으로 종료하면 이전 버튼으로 강제 복귀하지 않는다.
모바일 전환 시 거리뷰 안의 포커스는 현재 상세 제목으로 옮기고, 상세 안의 포커스는 유지한다.
상세 Overlay와 거리뷰는 Explorer의 같은 화면 폭 상태를 사용한다. 브라우저의 모바일 모달
자동 포커스가 마지막 PC 포커스 기록을 덮지 않도록 구분한다.

## API와 데이터 경계

| API | 사용 목적 |
| --- | --- |
| `GET /api/v1/complexes/{complexId}/street-view` | 실행 여부, 정책 버전, 검색 위치·시선 대상·시야 설정 |
| `GET /api/auth/csrf` | 이벤트 POST에 필요한 토큰과 헤더 이름 |
| `POST /api/v1/street-view/events` | 최초 초기화의 시작과 종료 결과; 성공은 빈 `204` |

`api.ts`는 응답을 런타임 검증하고 `no-store`로 요청한다. 활성 응답의 canonical `complexId`,
`policyRevision`, `initialization`과 FE의 이름표를 한 실행 시도에 고정한다. 상세 API 좌표를
대신 사용하거나 별도 주소 검색·좌표 저장·장기 캐시를 추가하지 않는다.
정책과 이벤트 필드, 오류 코드의 원본은 [BE 거리뷰 명세](../../backend/docs/features/STREET_VIEW.md)다.

## GL 지도와 iframe 분리

메인 앱은 기존 GL SDK를 유지하고, 동일 출처 `/street-view.html`에서 `panorama` SDK만
로드한다. 이 문서의 `entry.ts`는 메인 앱 진입점을 import하지 않는다. 부모는 화면·API·시간
제한·결과 보고를, 자식 `runtime.ts`는 SDK·초기 방향·핀·촬영일·크기 변경을 소유한다.
크기 관찰과 측정은 iframe 문서 루트를 기준으로 한다. SDK가 파노라마 컨테이너에 px 크기를
기록한 뒤에도 화면 폭 변경을 감지해 영상과 출처 표시의 크기를 갱신한다.

`protocol.ts`의 메시지 버전은 2다. 출처·현재 상대 window·메시지 형식을 검증하고,
`BOOT_READY` 이후 `INIT`에서 시도 ID를 한 번 연결한다. 이후 메시지는 시도 ID도 확인한다.
좌표는 URL에 넣지 않으며, 유효한 부모 초기화 없이 직접 열린 문서는 SDK를 실행하지 않는다.

Vite는 `index.html`과 `street-view.html`을 각각 빌드한다. 부모·자식은 같은 빌드로 제공하고
`dist/street-view.html`과 해시 자산을 모두 포함한다. [`nginx/app.conf`](../nginx/app.conf)는
거리뷰 HTML에 `no-store`, 동일 출처 iframe 제한을 적용하며, 파일이 없으면 SPA 대신 `404`를
반환한다. 혼합 버전은 성공으로 처리하지 않는다. 문서 준비 제한을 넘으면 기존
`DOCUMENT_TIMEOUT`을 사용하고 화면 새로고침을 안내한다. SDK에는 기존 공개 설정
`VITE_NAVER_MAPS_CLIENT_ID`를 사용한다.

## 초기 방향·출입구 핀·시간 제한

BE의 `searchPosition`으로 파노라마를 조회하고 `init`과 `pano_status: OK`를 모두 기다린다.
이벤트 순서는 가정하지 않는다. `fromCoordToPov(lookAtPosition)`의 유효한 `pan`과 BE의
`tilt`, `fov`를 최초 한 번 적용한다. 거리 계산이나 최소 거리 조건은 두지 않는다.
변환 정보가 늦으면 최대 1초만 기다리고, 계산할 수 없으면 SDK 기본 방향으로 표시한다.
이 경우 직접 화면을 움직여 주변을 확인하도록 안내하며, 이후 이동에는 자동 정렬하지 않는다.

출입구 핀은 `lookAtPosition`에 네이버 Marker 한 개를 연결한다. 이름표는 `단지명 · 출입구`다.
init·최초 OK 이후 방향 변환 성공 여부와 독립적으로 한 번 연결하며, 이동·회전·확대 중에는
같은 좌표와 마커를 유지한다. SDK 투영을 사용하므로 시야 밖에서는 보이지 않을 수 있다.
마커는 안내 요소이며 클릭·드래그·불필요한 Tab 정지점을 추가하지 않는다.

이름표는 `INIT.markerLabel`로 보내는 평문이며 공백이 아니고 최대 261 Unicode code point다.
DOM 요소의 `textContent`로 만들며 HTML 문자열에 단지명을 보간하지 않는다. 긴 이름은 시각적으로
두 줄 이내로 제한하되 접근 가능한 전체 이름을 유지한다. 타입 정의와 공식 Panorama 지원의
차이는 runtime SDK 경계의 작은 어댑터로 처리하고 전역 타입이나 검사 설정을 바꾸지 않는다.

`MARKER_STATUS`의 `ATTACHED`는 SDK 연결 성공이며 화면 내 노출이나 건물·정문 식별 성공이 아니다.
Marker 부재·생성·연결 예외는 `UNAVAILABLE`로 한 번 알리고 영상을 유지한다. 부모는
`출입구 위치 표시를 불러오지 못했어요. 거리뷰는 계속 둘러볼 수 있어요.`를 안내한다.
READY와 마커 상태의 도착 순서는 독립적이며, 핀 실패로 BE 초기화 결과를 변경하지 않는다.
정리 시 마커를 해제하고, 마커 해제 예외가 나머지 자원 정리를 중단하지 않게 한다.

SDK 준비는 15초, iframe 실행부터 최초 표시까지는 전체 30초로 제한한다.
방향 준비 대기도 전체 제한에 포함하며, 같은 단계의 통지가 반복되어도 기한을 늘리지 않는다.
문서·SDK·파노라마 실패를 구분하지만 파노라마 `ERROR`를 촬영 데이터 없음으로 단정하지 않는다.
재시도는 실행 정보 재조회, 새 시도 ID와 새 iframe으로 수행한다.

거리뷰 이동·회전·확대·축소와 확대 컨트롤을 제공하고 항공뷰 전환은 제외한다.
네이버 로고·출처를 유지한다. 촬영일은 위치 변경에 맞춰 갱신하며 없으면 `촬영일 미제공`으로
표시한다. 촬영일 누락 때문에 영상 표시를 지연하지 않는다.

## 관측과 제공 정책

`events.ts`는 실제 초기화마다 UUID를 생성해 `STARTED`와 최초 종료 결과 한 건만 보고한다.
종료는 `READY`, `FAILED`, 초기화 중 사용자의 종료·대상 변경에 따른 `CANCELLED` 중 하나다.
지도 보기·상세 X·검색 활성화·목록 열기는 `USER_CLOSED`, 다른 단지·공고 등 실제 대상 변경은
`TARGET_CHANGED`다. 같은 대상의 history 이동은 `USER_CLOSED`로 처리한다. 명시적 종료 뒤
URL 변경 감지가 중복 결과를 만들지 않는다. React effect 재등록은 새 시도나 취소가 아니다.
정상 표시 이후 탐색 오류·핀 오류·닫기는 초기화 결과를 바꾸지 않는다. 화면 폭 변경·페이지
이탈은 BE에 정의된 취소 사유가 없으므로 결과를 추정해 전송하지 않는다.

수집은 화면과 별도 수명주기로 실행하며 CSRF 응답의 `headerName`을 사용한다.
동시에 필요한 CSRF 준비 요청을 공유하고, 수집은 3초 제한 안에서 시도하되 자동 재전송하지 않는다.
수집 실패가 거리뷰 표시를 막지 않는다. SDK 오류 원문·URL·좌표·회원 정보는 전송하지 않는다.
종료 시 SDK 이벤트·타이머·크기 관찰자·마커·iframe을 정리한다.

BE 정책의 초기값은 OFF다. FE 배포만으로 제공을 활성화하지 않는다. 대상 환경의 SDK 인증,
영상·초기 방향·핀·실패 안내·종료 후 지도와 상세 유지 등을 확인한 뒤 별도 활성화한다.
API 허용·READY·핀 연결을 외관 식별 성공으로 대체하지 않는다. 실제 SDK·레이아웃은 브라우저에서
확인하고 자동 검사·빌드 결과와 구분한다. 검증 범위는 [품질 게이트](quality-gates.md)를 따른다.
