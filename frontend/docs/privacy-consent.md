# 개인정보 안내와 분석 선택

## 정책과 화면 경계

처리 목적·문의 창구·보유기간은 [운영 정책](../../docs/privacy-policy.md), 상태와 공개 안내 원문은
[백엔드 계약](../../backend/docs/features/PRIVACY.md)을 따른다. 화면에서 정책 원문을 복제하거나
메일 발송·자료 삭제가 완료되었다고 대신 판단하지 않는다. 개인정보처리방침 열람, 로그인,
회원 알림 신청에는 분석 동의 체크박스를 추가하지 않는다.

| 진입점 | 동작 |
|---|---|
| 지도 첫 방문 | 미선택·만료·재동의 상태에만 선택 카드를 표시한다. 거부와 허용을 같은 크기의 버튼으로 제공한다. |
| 정보 | 개인정보처리방침, 분석 설정, 개인정보 문의·삭제 요청으로 연결한다. |
| `/privacy` | 현재 공개 정책 원문을 표시한다. |
| `/privacy/:key/:version` | 해당 버전의 불변 원문을 표시한다. 회원 인증이 필요하지 않다. |
| `/privacy/settings` | 현재 적용 범위·상태와 허용·거부·철회 버튼을 제공한다. |
| 소셜 로그인 | 정책 조회와 무관하게 기존 OAuth 시작 URL을 제공한다. 정책 조회에 성공하면 표시한 정책 링크의 `policyVersion`을 선택적으로 전달하고, 조회 중·실패·버전 누락이면 `/privacy` 링크를 유지한다. |
| 알림 받기 | 저장 전에 신청 모달을 연다. `신청하기` 이후에만 업무 API를 호출하며 고지와 정책 링크를 버튼 아래에 표시한다. |

첫 방문 카드는 수집 목적과 직접 식별정보를 연결하지 않는다는 사실을 설명한다.

> 더 나은 서비스 경험을 위해 화면 조회·기능 사용 정보를 통계적으로 분석합니다.  
> **이름·이메일·회원 ID와 연결하지 않습니다.**

GA client ID와 PostHog distinct ID는 행동을 연결할 수 있다. 프로필을 끈 것만으로 완전히 익명인 집계가 되지 않으므로 “개인을 식별할 수 없는 익명 통계”라고 표시하지 않는다. 세부 항목·도구·저장소·철회는 서버의 현재 원문으로 안내한다. 현재 범위의 유효한 허용 후에만 수집하며 이전 범위의 허용은 자동 승계하지 않는다.

## 로그인과 가입 고지

정책 안내 API의 지연·실패는 소셜 로그인 버튼을 비활성화하거나 클릭을 취소하지 않는다.
실패 안내는 정책 조회 실패임을 밝히고 로그인을 계속할 수 있음을 설명하며, 정책 재조회 버튼을
별도로 제공한다. 버전을 받지 못하면 최신 버전을 추정하거나 하드코딩하지 않는다.

`policyVersion`은 로그인 화면에 제공한 고정 정책 링크의 버전이며 열람 완료나 동의의 증거가 아니다.
신규 가입 시 이 선택적 메타데이터를 보존하는 서버 계약을 사용하며, 버전 없는 기존 OAuth URL과
구버전 URL도 로그인할 수 있다. 기존 회원에게 정책 확인·동의를 매번 요구하지 않는다.
개인정보처리방침 변경과 분석 재동의는 각각 로그인 가능 여부와 독립적이다. 분석 거부·철회·미선택
상태에서도 로그인과 기본 서비스 이용이 가능하며 로그인 클릭으로 분석 동의를 생성하지 않는다.

OAuth 실패 복귀는 정책 변경으로 단정하지 않고 인증 취소·요청 만료 가능성과 아래 로그인 버튼으로
재시도하는 방법을 안내한다. OAuth 검증·만료·가입 고지 저장은
[서버 로그인 계약](../../backend/docs/features/USER.md)을 따른다. 로그인 버튼 클릭은 기존 분석 수집을 잠시 중지하고 인증 전환을 전파하지만,
분석 상태나 브라우저 저장 실패로 인증을 막지 않는다.

## 상태와 저장소

[ConsentStore](../src/privacy/consentStore.ts)가 앱의 분석 허용 여부를 소유한다. 로그인 회원은 서버의 계정 선택, 비회원은 동의 전용 HttpOnly 쿠키로 복원한 브라우저 선택을 적용한다. 두 선택은 합치거나 복사하지 않는다. 로그인·로그아웃·계정 전환이 시작되면 기존 수집 허용과 큐를 폐기하고 새 주체를 조회한다.

- 인증 전환은 계정정보 없는 nonce와 짧은 pending marker로 다른 탭에 전파한다. 전송 직전 및 상태 응답 반영 전에 nonce를 재검사하고 BroadcastChannel도 사용한다. OAuth는 앱 복귀 또는 10분 상한, 로그아웃은 완료 또는 60초 상한 뒤 다시 확인한다. 저장소·채널 실패가 로그인·로그아웃을 막지는 않는다. 두 통지 수단이 모두 차단되면 다른 탭은 기존 확인 유효기간(최대 60초) 안에서 중지된다.
- 상태 조회 결과의 주체, context, revision, 전환 세대와 요청 순서를 비교한다. 이전 계정·오래된 요청은 현재 화면이나 분석을 바꾸지 못한다.
- 보이는 화면에서 30초마다 확인하고, 포커스·온라인 복귀 때 즉시 재조회한다. 전송은 최대 60초의 서버 허용 수명과 실제 선택 만료 중 더 짧은 기간 안에서만 허용한다. 수명 측정은 단조 증가하는 `performance.now()`를 사용한다. 만료 타이머가 SDK 중지 콜백을 호출하므로 새 이벤트가 없어도 대기 큐와 재시도를 중단한다. 숨긴 탭은 수집하지 않는다.
- localStorage는 범위별 `toadzip.privacy.pending-stop:MEMBER:<id>` 또는 `...:GUEST`, 탭 통지, 계정 식별 정보가 없는 재선택 기준 시각에만 사용한다. 이메일·인증 토큰·분석 허용 원장은 저장하지 않는다.
- 거부·철회는 서버 응답 전에 즉시 중지한다. 실패하면 같은 주체·명령 ID·본문으로 재시도한다. 저장소에서 읽은 허용 명령은 자동 전송하지 않는다.
- marker 작성·조건부 삭제는 `privacy-stop:<범위>` Web Lock에서 직렬화한다. 새 허용의 늦은 응답은 자신이 시작할 때 본 marker만 제거하며, 이후 작성된 거부는 보존한다.
- 비회원 준비·선택·쿠키 재확인은 `privacy-guest-context` Web Lock으로 직렬화한다. Web Locks 미지원·쿠키 차단·저장 실패를 허용 성공으로 추정하지 않는다.
- 미처리 marker는 초기화·상태 갱신 때 모든 계정 범위를 검사하고 생성 후 180일이 지난 항목을 삭제한다. 삭제된 회원이나 다시 로그인하지 않는 회원도 포함한다. 기간 비교는 성공한 상태 응답의 서버 `checkedAt`을 사용하며, 명령 ID 비교·삭제는 범위 잠금 안에서 수행한다. 서버 확인이나 저장소 접근이 실패하면 정리 완료로 취급하지 않고 수집을 차단한다.
- 현재 주체의 서버 상태가 비허용이면 해당 만료 marker를 바로 정리한다. 다른 주체 또는 현재 허용 상태의 marker를 지우기 전에는 `toadzip.privacy.reselect-before`에 서버 기준 시각을 저장한다. 이 값은 계정 ID·명령 ID·요청 본문 없이 시각 하나만 가진다. 저장 실패 시 marker를 삭제하지 않는다.
- 재선택 기준 이하에 결정된 서버 허용은 모든 계정에서 차단하고 첫 화면에 재선택 카드를 표시한다. 기준 이후의 새로운 명시적 허용만 인정하므로 오래된 marker 삭제·새로고침·다른 계정 로그인으로 이전 허용이 되살아나지 않는다. 다른 계정에도 한 번의 재선택을 요구할 수 있는 보수적인 처리다.
- 재선택 기준은 방문으로 연장하지 않는다. 기준 시각으로부터 서버 기준 180일 후에는 그 이전 허용이 모두 만료되므로 기준 값 자체도 삭제한다. 정리 시점에 새 만료 marker가 있으면 그 정리를 보호할 새 기준을 기록한다. 닫힌 브라우저의 자료를 서버가 원격으로 삭제하지는 못하며 다음 성공한 상태 확인 때 정리한다.

명령의 과거 영수증이 허용이어도 응답의 `current`가 철회이면 수집하지 않는다. 409 충돌은 최신 상태를 확인한 뒤 사용자가 다시 선택하게 하며 새 명령 ID로 자동 우회하지 않는다.

## 분석과 업무 기록

[GA4](../src/analytics/googleAnalytics.ts), [PostHog](../src/analytics/productAnalytics.ts), [공고 조회](../src/public-housing/api/announcementViews.ts), [알림 노출](../src/public-housing/interest/NotificationInterest.tsx)은 공통 게이트를 검사한다. 허용 전 행동 큐·viewer UUID·알림 session/client UUID를 만들거나 전송하지 않는다. 알림 신청·취소는 계정 업무로 실행하므로 분석 거부와 독립적이다.

PostHog의 지속 저장·사람 프로필·세션 리플레이를 비활성화한다. 중지 시 앱 큐, 분석 저장소·쿠키, GA 대기 명령을 지우고 PostHog opt-out을 호출한다. 인증·CSRF 쿠키와 pending-stop은 지우지 않는다. PostHog opt-out만으로는 기존 배치·재시도 큐가 사라지지 않으므로 실제 전송 경계도 확인한다. SDK가 이미 실행된 환경의 실제 네트워크 중단은 브라우저에서 검증하며 테스트의 SDK mock을 그 증거로 사용하지 않는다. 이미 서버에 도착한 자료의 삭제는 별도 제공자 절차가 필요하다.

[알림 요청 계약](../../backend/docs/operations/NOTIFICATIONS.md)에 따라 주체·revision·고지 버전을 보내고 이메일·분석 식별자는 보내지 않는다. 신청 성공 표시에는 현재 대상 상태를 사용한다. 전체 해제는 성공 응답의 revision을 다음 요청에 넘긴다. 응답 유실이면 같은 명령 결과부터 확인하고 다음 대상의 변경을 보류한다. 409는 목록을 갱신하고 나머지 해제를 다시 확인한다.

도입 전 알림의 `noticeVersion`·`requestedAt`은 null일 수 있다. 이 값이 없다는 이유로 목록 전체를
오류 처리하지 않으며 기존 활성 설정을 표시·해제한다. 없는 과거 고지나 신청 시각을 프론트에서
생성하지 않는다. 배포 호환성과 전환 순서는 [DB 배포 계약](../../backend/docs/operations/PRIVACY.md)을 따른다.

회원 UI의 `/mypage/notifications`와 PC 중앙·모바일 하단 보관함은 받은 알림 준비 안내와 설정 목록을 분리한다.
이전 `/notifications` 경로는 지도 위 보관함으로 연결하며 비회원에게는 로그인 안내를 제공한다.

## SDK 설정과 운영 확인

- 로컬 Vite와 Docker 빌드는 루트 `.env`의 `VITE_GA_MEASUREMENT_ID`와 PostHog 공개 설정을 사용할 수 있다. GA는 루트 값이 없을 때 기존 frontend 설정을 유지한다. VITE 공개 설정만 브라우저에 포함하며 서버 비밀값을 넘기지 않는다.
- 로컬 GA는 `VITE_GA_DEBUG_MODE=true`가 추가로 필요하다. PostHog는 `VITE_ANALYTICS_ENV=dev` 및 `VITE_POSTHOG_LOCAL_ENABLED=true`일 때만 localhost 수집을 허용한다. 환경 설정이 유효해도 동의 전에는 SDK를 로드하지 않는다.
- GA는 `send_page_view:false`, Google Signals·광고 개인화 비활성화와 정제된 수동 이벤트를 사용한다. `ga-disable-*`는 전송 시점의 동의 상태를 읽고 중지 때 앱/gtag 대기 큐를 비운다. 다시 허용되면 새 이벤트를 보낼 수 있다.
- GA 데이터 스트림의 **향상된 측정은 관리자에서 별도로 꺼야 한다.** `send_page_view:false`만으로 스크롤·외부 링크·폼 등의 원격 자동 측정까지 비활성화되지는 않는다. 관리자의 Google tag 추가 목적지·자동 이벤트·개인정보 관련 설정도 운영 확인 대상이다.
- PostHog는 `opt_in_capturing({captureEventName:false})`로 명시적으로 허용하고, 원격 설정·자동 수집·리플레이·프로필·지속 저장·배치를 끈다. 중지 시 전송 경계를 닫고 진행 중 fetch를 abort한 뒤 SDK 큐를 폐기한다. 재허용 시 새 인스턴스를 사용한다.
- `posthogTransport.ts`는 **posthog-js 1.438.2**의 공식 no-external 번들과 내부 transport/queue 경계에 의존한다. 패키지 버전 변경 시 설치 SDK 통합 테스트와 실제 브라우저 중지·재허용을 반드시 재검증한다. 다른 번들의 내부 이름이 같다고 가정하지 않는다.
- HTTP 성공은 수집 엔드포인트 응답의 증거다. 제공자의 대시보드 반영, 보유·삭제 설정과 법적 고지 완결성을 대신하지 않는다.

## 검증 경계

상태 테스트는 미선택·거부·철회, 만료, 응답 유실 재시도, 늦은 응답, 계정 전환, 쿠키·Web Locks 실패, 새로운 marker 보존과 저장소 허용 위조를 검증한다. 컴포넌트 테스트는 확정 문구·굵기, 공개 정책 경로, 선택적 고지 버전 전달, 정책 조회 지연·실패·버전 누락과 분석 거부 시 로그인 링크 유지, OAuth 실패 재시도 안내, 신청 전 모달과 취소, 오류 안내를 검증한다.

실제 브라우저에서는 모바일·데스크톱 배치, 키보드 포커스, 두 탭의 잠금·storage 이벤트, 쿠키/localStorage 차단, 새로고침·뒤로가기·오프라인 복귀를 확인한다. 실제 SDK와 프로젝트 설정으로 미선택·거부 시 요청 없음, 허용 후 전송, 철회 후 새 전송·배치·재시도 중지, 재허용 후 새 행동의 전송을 검증한다. 네트워크 전송 성공과 대시보드 수신 확인을 구분한다. 운영 담당자 지정, 위탁사·메일·백업 파기, 외부 SDK 및 저장 국가 확인은 프론트 테스트로 대체하지 않는다.

## PostHog 브라우저 전송 호환성

`posthog-js/no-external`의 공식 브라우저 번들을 사용한다. 내부 CJS 파일을 직접 불러오면
native `fetch`의 receiver가 exports 객체가 되어 Chromium에서 `Illegal invocation`으로
전송이 실패할 수 있다. 전역 `window.fetch`를 교체하거나 SDK 원문을 수정하지 않는다.
고정 버전 `1.438.2`의 no-external 번들은 전송·재시도 guard가 사용하는 내부 이름을 보존하며,
외부 스크립트를 로드하지 않는다. SDK 갱신 시 native fetch 호출과 동의·철회·재시도 중단을
설치된 SDK 테스트 및 실제 브라우저에서 함께 검증한다.
