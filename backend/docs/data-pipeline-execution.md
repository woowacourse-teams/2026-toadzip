# 수집·정제 실행

수집·정제는 관리자 요청으로 시작한다. 서버 부팅·예약·장애 복구는 새 실행을 만들지 않는다.
진행 확인·중지·수동 복구는 [실행 제어](pipeline-operator-controls.md)를 따른다.

## 실행 유형

`POST /api/admin/ingest/pipelines/{type}`으로 시작한다. 관리자 세션과 CSRF 토큰이 필요하다.

| `type` | 작업 |
|---|---|
| `complex-sync` | 단지 수집 후 정제, 4단계 |
| `announcement-sync` | 공고 수집 후 정제, 6단계 |
| `complex-collection` / `complex-refinement` | 단지 수집 / 저장 원천 정제 |
| `announcement-collection` / `announcement-refinement` | 공고 수집 / 저장 원천 정제 |

## 결과

| 상태 | 의미 |
|---|---|
| `RUNNING` | 실행 중 |
| `COMPLETED` | 선택된 작업 완료 |
| `COMPLETED_WARNINGS` | 정제·보강의 행별 누락이 남음 |
| `COMPLETED_WITH_SKIPS` | 호출 제한으로 건너뛴 단계가 있음 |
| `FAILED` | 운영 실패 또는 예상하지 못한 오류 |
| `STOPPED` | 관리자 중지 완료 |

누락과 건너뜀이 함께 있으면 `COMPLETED_WARNINGS`로 기록하고 두 보고서를 보존한다.
작업 완료가 모든 공고의 최신성·정보 충족을 뜻하지는 않는다.

### 실패 처리

- 운영 부분 실패는 후속 수집 단계를 한 번씩 수행한 뒤 최초 실패를 남기고 `FAILED`로 끝낸다.
- 통합 실행은 수집 부분 실패·호출 제한에서 정제를 시작하지 않는다. 제한만 있으면 `COMPLETED_WITH_SKIPS`로 끝낸다.
- 예상하지 못한 오류는 즉시 이후 단계를 중단한다. 같은 실행에서 실패 단계 전체를 다시 실행하지 않는다.

호출 제한은 재시도하지 않고 전국 병렬 수집의 대기 요청도 취소한다.
지오코딩 API·좌표 변환·저장 오류는 운영 실패, 주소 불명·모호함·매칭 불가·원천값 오류는 행별 누락이다.
단지·공고 매칭 실패는 개별 이력에도 남지만 LH 주택형 누락은 단계 보고서의 건수로만 남는다.

## 실행 소유권

통합 실행 전체에 PostgreSQL advisory lock 하나를 사용한다. 단계별 결과와 단지·공고의 최신 실행은 DB에 보존한다.
쓰기 트랜잭션은 잠금 세션·실행 소유자·세대값을 확인하고 소유권 행의 공유 잠금을 커밋까지 유지한다.
커밋 직전에도 세션을 확인해 소유권을 잃은 쓰기를 롤백한다. 소유권 이전은 기존 쓰기가 끝날 때까지 기다린다.

### 서버 소실

30초마다 heartbeat를 갱신한다. 새 실행·상태 조회 시 잠금이 없고 2분 넘게 갱신되지 않은 `RUNNING`을 실패로 복구한다.
복구 직전 상태·heartbeat를 다시 확인하고 마지막 단계를 남긴다. 조회·새 실행이 없으면 자동 변경하지 않는다.

## 배포와 이력 보존

새 실행 유형·소유권·`STOPPED`를 모르는 이전 서버와 혼합 실행하지 않는다. 기존 작업을 끝내고 서버·관리자 화면을 함께 교체한다.
이전 서버는 enum을 읽지 못하거나 실패 이력을 삭제할 수 있다. 롤백 전 이력을 백업하고 호환 처리가 없으면 수집을 중지한 채 새 버전을 복구한다.
실행·실패 이력은 자동 삭제하지 않는다. 테이블 삭제는 백업과 별도 승인 후 진행한다.

스키마 적용은 [Flyway](flyway-adoption.md), 원천 이관·누락 버전·복구는 [수집 DB 전환](ingest-branch-db-upgrade.md)을 따른다.
