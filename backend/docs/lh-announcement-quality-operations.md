# LH 공고 품질 확인

`/admin/ingest`의 LH 품질 영역에서 수집 요청의 성공과 제품 정보의 충족을 구분해 확인한다.
API는 `GET /api/admin/ingest/quality/lh-announcements`이며 관리자 세션이 필요하다.

## 품질 지표

### 요청과 원천

| 지표 | 기준 |
|---|---|
| 공급·상세 요청 성공률 | 최근 수집 실행의 성공 요청 / (성공 요청 + 실제 요청 실패) |
| 원천 확보 | 현재 일반 수집 대상 중 현재 조회 조건의 성공 수집 시각이 있는 요청 수 |
| 원천 보존 | 빈 공급 응답·기존 행 감소로 교체를 막은 현재 실패 요청 수 |

요청 성공률은 재시도 호출 수나 합친 중복 요청을 세지 않는다. 원천 선택 충돌은 별도로 표시하고 분모에서 제외한다.
`failedRequestCount`는 충돌을 포함하므로 실제 요청 실패는 `failedRequestCount - selectionFailedRequestCount`다. 충돌만 있어도 실행은 실패다.

원천 확보는 활성 마이홈 원천의 현재 회차에서 충돌 없이 결정한 요청을 센다. 동일 요청은 한 번만 세고 원천 없는 요청도 분모에 포함한다.
`collectedRequests`에는 과거 성공도 포함된다. 최신성이나 이번 실행의 성공률은 아니며 `latestCollectedAt`은 확보 시각의 최댓값이다.

### 제품 정보

삭제되지 않은 LH 제품 공고·공급행을 기준으로 확인한다.

| 지표 | 기준 |
|---|---|
| 단지·주택형 연결 | 공급행의 연결 여부와 `matching_failure_reason`별 미연결 수 |
| 금액 확보 | 숫자 보증금·월세 쌍을 가진 대상이 하나 이상 있는 공급행 |
| 일정 검토 | 공고별 접수 일정 확인 여부와 실제 확인 일정 수 |
| 금액 보존 | 기존 LH 숫자 금액을 유지한 제품 공급대상 수 |

금액 보존은 미제공·매칭 실패·매핑 및 보강 보류를 구분한다. 같은 대상은 한 번만 세고 과거 원천의 정상 금액은 제외한다.
롤백된 작업은 현재 원천의 실패 이력과 공급행으로 집계한다. 정상 숫자로 갱신되고 실패가 해결되면 집계에서 빠진다.

## 확인할 데이터

### 미연결 공고

LH 목록과 현재 마이홈 요청·성공 연결의 불일치, 최근 변경 50건의 PAN_ID는 조사 대상이다.
과거 회차에만 연결된 공고도 포함되므로 신규 공고나 확정된 정정 건수로 해석하지 않는다.
LH 목록에만 있는 공고의 제품 등록과 제목만으로 한 정정 관계 확정은 제공하지 않는다.

API의 접수 일시는 공고문과 다를 수 있다. 금액 미제공·접수 조건·정정 여부는 공식 공고문에서 확인한다. `공고문 참조`를 숫자로 세거나 없는 금액을 추정하지 않는다.
일정·정정 정보는 [관리자 데이터 관리](admin-data-management.md)에서 수정한다.

## 확인된 공급 감소 반영

### 확인과 승인

1. 원본 공고문에서 철회·정정 범위, PAN_ID와 주택형을 확인한다.
2. 화면에서 보류 요청을 선택하고 마이홈 공고 ID, LH 공식 근거 URL과 확인 사유를 입력한다.
3. `POST /api/admin/ingest/lh/announcements/supplies/{pblancId}/verified-replacement`로 승인 후 재조회한다. 관리자 세션과 CSRF가 필요하다.

`proposedFingerprint`는 감소 응답의 식별값·면적·세대수·금액을 순서와 무관하게 해시한 값이다.
서버는 현재 연결·보류 실패·승인 지문을 확인하고, 같은 응답 지문일 때만 한 번 교체한다. 승인자·근거·사용 시각을 기록한다.
다른 감소 응답이나 재조회 실패는 기존 보호를 유지한다. 정상 응답이 오면 일반 재조회로 저장하고 미사용 승인은 폐기한다.

### 반영 결과

승인된 빈 공급 응답은 같은 조회 조건의 빈 기준으로 유지된다. 수집 버전이 바뀌어도 적용되며, 정상 공급을 다시 확보하면 그 공급을 기준으로 삼는다.
제품 보강은 현재 마이홈 공급행의 기존 LH 금액을 제거한다. 이전 PAN에서 유지하던 금액도 제거하지만 과거 회차·관리자 입력 금액은 보존한다.

원천 반영 후 공고를 재정제하고 제품 결과를 확인한다. 실제 취소 공고는 관리자 수정·휴지통 경로에서 처리한다.
