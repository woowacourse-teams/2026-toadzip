# LH 공고 데이터 정확성 운영

`/admin/ingest`의 LH 품질 영역은 최근 공고 수집 실행의 **요청 성공률**과 현재 LH 제품 공고의 **정보 충족률**을 구분한다.
백엔드 조회는 `GET /api/admin/ingest/quality/lh-announcements`다. 관리자 세션이 필요하다.

| 지표 | 분모와 판정 |
|---|---|
| LH 공급·상세 요청 성공률 | 최근 공고 수집 실행의 성공 요청 / (성공 요청 + 실제 요청 실패). 원천 선택 충돌은 별도 건수로 표시하고 분모에서 제외한다. 재시도 API 호출 수와 캐시로 건너뛴 요청도 분모가 아니다. |
| 단지·주택형 연결 | 삭제되지 않은 LH 제품 공고의 공급행. 미연결 사유는 `matching_failure_reason`별 공급행 수다. |
| 금액 확보 | 같은 공급행 중 숫자 보증금·월세 쌍을 가진 대상이 하나 이상 있는 행. 원천의 `공고문 참조`는 숫자로 세지 않는다. |
| 일정 검토 | 삭제되지 않은 LH 제품 공고 중 확인한 접수 일정 표시가 있는 공고. 실제 확인 일정이 하나 이상 있는 수는 별도 표시한다. |
| 최신성 | 활성 마이홈 공고의 현재 회차에서 충돌 없이 결정된 정기 재수집 대상 요청. 동일 요청은 한 번만 세고 성공 기록이 없는 요청도 분모에 넣는다. 각 요청의 실제 6/24시간 정책과 LH 목록 변경 시각을 함께 확인하며 과거 수집 버전·종료 후 제외된 요청은 세지 않는다. |
| 원천 보존 | 현재 LH 공급 실패 중 빈 응답·기존 행 감소로 교체를 막은 **요청 수**. 금액을 유지한 제품 공급행 수가 아니다. |
| 금액 보존 | LH 숫자 보증금·월세를 유지한 제품 공급대상 수. 금액·공급 미제공, 공급행 매칭 실패, 매핑·보강 전체 보류를 구분한다. 롤백된 작업은 현재 원천의 실패 이력과 해당 원천 그룹의 공급행으로 집계하고, 과거 원천의 정상 금액은 제외한다. 같은 대상은 한 번만 센다. 정상 숫자로 갱신되고 실패가 해결되면 집계에서 빠진다. |

LH 임대 목록에서 현재 활성 마이홈 원천의 최근 수집 회차에서 결정한 요청과 성공 연결 기록이 일치하지 않는 건수와 최근 변경 50건의 PAN_ID는 **조사 후보**다. 과거 회차의 연결 기록만 있는 공고도 후보에 포함한다. LH 단독 제품 공고나 확정된 정정 공고 수로 해석하지 않는다.
최초 LH 단독 제품 등록과 정정 관계 확인은 [독립 수집 계획](lh-announcement-collection-plan.md)에 남아 있다.

## 확인된 공급 감소 반영

1. 보류 요청의 원본 공고문에서 철회·정정 범위, PAN_ID, 주택형을 확인한다. 요청의 `proposedFingerprint`는 감소한 LH 응답의 식별값·면적·세대수·금액을 순서와 무관하게 해시한 값이다.
2. 화면에서 보류 요청을 선택하고 마이홈 공고 ID, LH 공식 근거 URL과 확인 사유를 입력한다. `POST /api/admin/ingest/lh/announcements/supplies/{pblancId}/verified-replacement`는 관리자 세션·CSRF가 필요하다.
3. 서버는 현재 마이홈 연결, 보류 중인 공급 감소 실패, 승인 지문을 확인하고 즉시 LH를 재조회한다. 같은 감소 응답 지문일 때만 1회 교체하며 승인자·근거·사용 시각을 기록한다. 다른 감소 응답이나 재조회 실패는 기존 보호를 유지한다. 감소하지 않은 정상 응답은 일반 재조회로 저장하고 사용하지 않은 승인은 폐기한다.
4. 승인된 빈 공급 응답은 수집 버전이 바뀌어도 동일 조회 조건의 빈 기준으로 유지된다. 이후 정상 공급이 수집되면 그 공급을 새 기준으로 삼는다. 제품 보강 시 현재 마이홈 공급행의 기존 LH 금액을 제거한다. 이전 PAN ID에서 보존하던 LH 금액도 제거하며 과거 회차의 공급행·금액과 관리자 입력 금액은 유지한다. 원천 반영 후 공고 정제 결과와 제품 공고를 다시 확인한다. 실제 취소 공고는 기존 공고 수정·휴지통 경로에서 확인한다.

승인 기록은 `V20260928_04__verified_lh_supply_replacements.sql`로 추가한다. 구버전 서버와 혼합 수집하지 않고 기존 실행을 끝낸 뒤 적용한다.

`failedRequestCount`는 기존 파이프라인 실패 판정을 위해 원천 선택 충돌을 포함한다. 화면의 실제 요청 실패는 `failedRequestCount - selectionFailedRequestCount`이며 충돌만 있어도 실행 자체는 실패로 유지한다.
