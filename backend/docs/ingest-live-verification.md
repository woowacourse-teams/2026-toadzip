# Ingest 실제 API·격리 DB 검증 — 2026-09-30

## 검증 범위

사용자가 승인한 실제 MyHome·LH API와 로컬 격리 PostgreSQL 조합으로 확인했다. 운영 DB와 배포 환경은 사용하지 않았다. 기존 API 키는 출력하지 않고 공공데이터 API 요청에만 사용했다.

- 실제 실행: 관리자 HTTP API → 실행 잠금 → 수집·원천 저장 → 정제·보강 → 이력 조회.
- DB: `compose.test.yaml`, 프로젝트 `codex-ingest-live-20260930`, 포트 `55444`·`55445`, tmpfs.
- 서버: `local` 프로필, Flyway 활성화·Hibernate `validate`, HTTP `18092`, 관리자 화면 `5177`.
- 새 DB에서 Flyway 18개 성공과 통합 실행 유형 제약을 확인했다. 전체 회귀는 별도 DB `55442`·`55443`을 사용했다.

## 실제 응답으로 발견한 문제와 수정

| 관측 | 원인 | 수정과 보존한 검증 |
|---|---|---|
| 최초 LH 상세 71회 중 12회 실패 | 060의 `ETC_FCTS`·`PAN_DTL_CTS`를 읽지 않고, 062의 빈 부가정보 행과 063의 빈 접수처 행을 잘못 거절 | 기타 내용을 보존한다. 확인된 필드 조합의 값이 모두 null·공백 문자열인 행만 생략한다. `{}`, 알 수 없는 필드, 객체·배열은 계속 거절한다. |
| 제주시 전체 수집 실패 | 같은 원천 키의 두 행에서 `styleNm`이 `C`·`C `로 반복 | 사용자 승인에 따라 기존 저장 정규화 후 내용이 같은 행만 합친다. 금액·주소·세대수 등이 다르면 지역 교체를 거절한다. |

제주 응답을 처음 설명할 때 비교 도구가 문자열 공백을 제거한 사실을 빠뜨렸다. 원문이 완전히 같은 것은 아니며, 기존 저장 규칙으로 정규화하면 같은 내용이다. 새 정규화 규칙은 추가하지 않았다.

중복 비교는 기존 raw 원천 키를 유지하고 저장 정규화 snapshot의 23개 필드를 비교한다. 페이지 완료 판정은 중복을 포함한 원본 행 수를 사용한다. 실제 제주 재수집은 API 2회, 응답 799행 → 저장 798행, 실패 0건이었다.

## 위치정보와 제품 데이터 품질

공식 `202607` 위치정보요약DB 전체분 ZIP을 로컬 업로드 경로로 처리했다. 텍스트 16개·6,422,078행에서 수집 주소 23,642개 중 23,613개를 매칭했고 29개는 매칭되지 않았다. 새 제주 주소까지 포함해 확인했다.

전국 단지 통합은 마이홈 원천 135,516행·LH 카탈로그 6,740행을 저장했다. 최종 DB에는 단지 3,507개·주택형 12,246개·공고 78개·공급행 267개·일정 664개·첨부 252개가 남았다. 성공 LH 체크포인트는 144개였다.

최종 실행의 행별 경고와 DB 실패 기록은 단위가 다르며 합산하지 않는다.

| 영역 | 실행 보고 | 최종 `PENDING` 기록의 주요 원인 |
|---|---|---|
| 단지 정제 | 실패 원천 행 174개 | 좌표 오류 80·필수값 누락 82·값 검증 실패 12 |
| 세대수 보강 | 실패 원천 단지 801개, 미연결 주택형 118개 | 단지 없음 786·중복 대상 6·원천 검증 실패 9 |

공고 정제의 값 검증 실패 29개는 직접 LH 보강에서 단지 연결 25개·주택형 연결 1개·새 금액 누락 3개가 거절된 결과다. 기존 공고별 트랜잭션은 이전 제품 데이터·금액을 보존한다. 뒤의 보강 보류 42개는 별도 원인 42개를 뜻하지 않는다. 과거 실패 이력이 영구 차단하는 구조는 아니며, 현재 데이터로 직접 보강을 다시 시도한다([기존 복구 규칙](lh-announcement-link-resolution.md)). 원인을 해결하지 않은 수동 반복만으로 연결 완료를 보장하지 않는다.

## 검증 한계

- `COMPLETED_WARNINGS`에는 연결되지 않은 단지·주택형, 주소 좌표 누락, 모호한 연결 등의 행별 실패가 남는다. 자동으로 추정해 연결하거나 삭제하지 않았다.
- 실행마다 실제 API 입력이 달라졌다. 마이홈 공고는 176 → 177 → 178행, LH 목록은 594 → 595행으로 바뀌었으므로 전후 소요 시간이나 호출 수를 성능 개선율로 비교하지 않는다.
- 이번 실제 호출에서는 quota가 발생하지 않았다. 호출 제한 뒤 정제 차단과 내용 충돌 시 원천 보존은 회귀 테스트로 확인한다.
- 공고문과 제품 일정의 의미 대조, 모든 원천의 최신성, 다중 서버 배포 환경은 이번 검증에 포함하지 않는다.
- 당시 실응답 수정 후 격리 PostgreSQL 전체 `check`는 백엔드 1,708개 테스트, 프론트엔드 `npm run check`는 885개 테스트·lint·build를 통과했다. 현재 작업 트리의 검사 결과를 뜻하지 않는다.
- 배포 호환 조건은 [파이프라인 실행](data-pipeline-execution.md)을 따른다. 통합 enum 이력을 읽지 못하는 구버전 ingest를 종료하고 서버·관리자 화면을 함께 배포해야 한다.

검증 후 로컬 서버와 두 격리 DB 프로젝트를 정리했다. 실행 JSON·최종 DB 집계·관리자 화면 캡처는 `/tmp/ingest-sync-live-*`와 `/tmp/ingest-admin-live-verification.png`에 보존했다. 원격 Git 변경과 배포는 수행하지 않았다.
