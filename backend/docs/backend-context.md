# Backend Context

## 서비스 목적

공공임대주택의 위치와 기본 정보, 모집 공고, 지원 판단 근거를 연결한다.
공식 출처를 대신하지 않고 사용자가 여러 서비스를 오가는 비용을 줄인다.

## 핵심 사용자 흐름

1. 지역과 조건으로 공공임대주택을 찾는다.
2. 주택의 위치, 임대 조건, 현재·과거 공고를 확인한다.
3. 공급 유형과 자격 조건을 비교한다.
4. 공식 공고 원문과 신청 일정을 확인한다.
5. 관심 조건의 새 공고를 추적한다.

## 도메인 용어

| 용어 | 의미 |
|---|---|
| 주택 단지 | 동일 위치와 사업 맥락으로 관리되는 주택 묶음 |
| 모집 공고 | 자격, 일정, 공급·임대 조건을 명시한 공식 문서 |
| 공급 유형 | 행복주택, 국민임대 등 공고가 구분하는 제도 |
| 공고 상태 | 원문 일정으로 계산한 예정·모집 중·마감 표시 |
| 출처 기준 시각 | 원문이 유효하다고 표시한 날짜와 시간 |
| 수집 시각 | 시스템이 원문을 가져온 날짜와 시간 |

## 백엔드 기능 경계

| 기능 | 책임 |
|---|---|
| `housing` | 주택 위치와 기본 정보 |
| `notice` | 공고, 일정, 원문과 주택 연결 |
| `eligibility` | 공급 유형과 자격 판단 보조 |
| `interest` | 관심 조건 저장과 알림 요청 |

## 신뢰성 원칙

- 출처 URL, 출처 기준 시각, 수집 시각을 함께 보존한다.
- 자격 판단에는 근거, 적용 시점, 한계를 표시한다.
- 불확실하거나 파싱하지 못한 값을 추정해 성공 데이터로 만들지 않는다.
- 입주 자격, 당첨, 계약 가능성을 법적으로 보증하지 않는다.
- 공식 공고 원문으로 이동할 수 있는 식별자를 유지한다.

## 기술 제약

- Java 25, Spring Boot 4, Gradle을 사용한다.
- 서버 시각과 도메인 시각은 명시적으로 구분한다.
- 개인정보와 인증정보는 최소 수집하며 로그에 기록하지 않는다.
