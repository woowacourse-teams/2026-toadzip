# 거리뷰 백엔드 설계 및 동작 명세

거리뷰는 사용자가 단지 상세에서 실제 외관과 주변 환경을 확인하는 기능이다. 기존 GL 지도를 유지하고, PC에서는 서비스 내부 팝업으로 제공한다. 팝업을 닫으면 기존 지도와 단지 상세를 계속 이용할 수 있어야 한다.

팝업 내부의 별도 동일 출처 iframe에서 거리뷰 SDK를 실행하도록 구성한다. 지도와 거리뷰의 SDK 실행 환경을 분리하기 위한 결정이다. 브라우저에서는 촬영일과 로딩·실패 상태를 표시하고, 거리뷰의 이동·회전·확대·축소를 제공한다. iframe에서의 SDK 인증·렌더링과 기존 GL 지도와의 동시 동작은 실제 브라우저 연동으로 검증해야 한다.

**BE는 거리뷰 제공 정책과 초기 실행 정보를 관리하고, 브라우저에서 발생한 초기화 결과를 수집한다.** 촬영 지점 조회와 영상 표시는 브라우저의 네이버 SDK가 담당한다. BE가 네이버 영상이나 타일을 중계하지는 않는다.

전체 흐름은 다음과 같다.

1. FE가 선택한 단지의 거리뷰 실행 정보를 요청한다.
2. BE가 전체 제공 정책과 단지 좌표를 확인해 실행 허용 여부와 초기 입력을 반환한다.
3. FE가 실행을 시작하고, 네이버 SDK로 기준 좌표 주변의 촬영 지점을 조회한다.
4. 실제 촬영 위치를 기준으로 단지 출입구를 바라보도록 초기 방향을 설정한다.
5. FE가 초기화 결과를 보고하면 BE가 지표와 로그에 반영한다.

거리뷰 관련 API는 다음과 같다.

| API | 역할 | 접근 조건 |
|---|---|---|
| `GET /api/v1/complexes/{complexId}/street-view` | 단지의 실행 허용 여부와 초기 입력 조회 | 익명 허용 |
| `GET /api/admin/street-view-policy` | 전체 제공 정책 조회 | ADMIN |
| `PUT /api/admin/street-view-policy` | 전체 제공 정책 변경 | ADMIN·CSRF |
| `GET /api/admin/street-view-policy/changes?page=0` | 정책 변경 이력 조회 | ADMIN |
| `POST /api/v1/street-view/events` | 브라우저 초기화 결과 수집 | 익명 허용·CSRF |

데이터를 반환하는 API는 기존 `{data: ...}` 응답 형식을 사용한다. 오류는 공통 `code`, `message`, `traceId` 형식을 따른다. 필드별 검증 조건과 응답 스키마는 OpenAPI 정의를 기준으로 한다.

**초기 위치에는 DB에 저장된 단지 출입구 좌표를 사용한다.** 좌표계는 WGS84이며 위도·경도 모두 도 단위다. 실행 정보 응답은 다음 의미를 가진다.

| 필드 | 의미 |
|---|---|
| `complexId` | alias를 해석한 실제 단지 ID |
| `provider` | 거리뷰 공급자. `NAVER` |
| `enabled` | 서비스 정책과 좌표 유효성에 따른 실행 허용 여부 |
| `disabledReason` | 실행을 허용하지 않는 사유 |
| `policyRevision` | 응답에 적용한 전체 정책의 버전 |
| `initialization` | 검색 위치, 시선 대상, 초기 시야 설정. 비활성이면 `null` |

`initialization`의 위치는 검색 기준과 시선 대상으로 나눈다.

| 필드 | 역할 | 초기값 |
|---|---|---|
| `searchPosition` | 주변 촬영 지점을 찾는 기준 | 단지 출입구 좌표 |
| `lookAtPosition` | 처음 바라볼 대상 | 단지 출입구 좌표 |
| `tilt` | 위아래 시선 각도 | `0` |
| `fov` | 시야각 | `90` |

두 위치는 같은 좌표를 사용하지만 역할이 다르므로 별도 필드로 제공한다. 네이버 SDK가 선택한 **실제 촬영 위치는 출입구 좌표와 다를 수 있다.** 따라서 좌우 방향인 `pan`은 BE에서 미리 정하지 않고, FE가 실제 촬영 위치에서 `lookAtPosition`을 바라보도록 계산한다.

실행 허용 여부는 다음 규칙으로 결정한다.

- 전체 정책이 꺼져 있으면 `enabled=false`, `disabledReason=POLICY_DISABLED`를 반환한다.
- 정책이 켜져 있어도 좌표가 없거나 범위를 벗어나거나 `(0, 0)`이면 `INVALID_COORDINATES`를 반환한다.
- 단지가 없거나 관리자 삭제 상태이면 `404 COMPLEX_NOT_FOUND`를 반환한다.
- 정책 행이 없으면 `503 STREET_VIEW_POLICY_UNAVAILABLE`을 반환한다.

`enabled=true`는 초기화를 시도할 수 있다는 의미다. 해당 위치에 촬영 데이터가 있는지, 선택된 영상에서 외관이 잘 보이는지는 브라우저 조회 이후에 확인할 수 있다. 또한 `policyRevision`은 전체 제공 정책의 버전이며 단지 좌표나 촬영 데이터의 버전을 나타내지 않는다.

**전체 제공 정책은 배포 없이 거리뷰의 신규 실행을 중단하거나 재개하기 위해 DB에 저장한다.** `street_view_policies`에는 서비스 전체에 적용할 정책 한 건을 유지한다.

| 컬럼 | 저장 내용 |
|---|---|
| `id` | 고정값 `1`. 단일 정책을 보장하는 기본키와 제약조건 |
| `enabled` | 전체 제공 여부 |
| `version` | 정책 수정 버전. JPA `@Version` 적용 |
| `change_reason` | 변경 사유 |
| `updated_by` | 변경한 관리자 |
| `updated_at` | 변경 시각 |

마이그레이션으로 `enabled=false`, `version=0`인 초기 정책을 생성한다. 단지 좌표는 기존 단지 데이터를 조회하며 정책 테이블에 복제하지 않는다.

관리자는 현재 조회한 `version`과 변경할 `enabled`, `reason`을 전송한다. 변경자는 인증된 관리자 정보에서 가져온다. 사유는 앞뒤 공백을 제거한 뒤 1~500자로 검증한다.

변경 시 정책 행을 잠그고 요청 버전을 확인한다. 다른 관리자가 먼저 수정했다면 `409 ADMIN_DATA_CONFLICT`를 반환한다. 클라이언트는 정책을 다시 조회한 뒤 변경 여부를 판단해야 한다.

버전이 일치하고 제공 여부와 정규화한 사유가 모두 같으면 버전과 이력을 변경하지 않는다. 사유만 달라져도 정책 변경으로 처리한다.

변경 전후 값은 기존 `admin_data_changes`에 저장한다. 정책 수정과 감사 이력 저장은 같은 트랜잭션으로 처리하므로 감사 저장에 실패하면 정책 변경도 롤백한다. 이력 조회는 최신순으로 페이지당 20건을 반환한다.

정책은 실행 정보 요청마다 DB에서 읽고, 공개 실행 정보 응답에 `Cache-Control: no-store`를 적용한다. 비활성화는 이후 정책을 조회해 시작하는 거리뷰에 적용되며, 이미 열린 거리뷰를 강제로 종료하지는 않는다.

**브라우저 결과 수집은 BE API 응답만으로 확인할 수 없는 SDK 초기화 구간을 관측하기 위해 둔다.** 수집 단위는 거리뷰를 여는 최초 초기화 시도다.

FE는 실행 정보가 활성 상태일 때 새 UUID `attemptId`를 생성한다. 이벤트에는 단지 ID, 적용한 `policyRevision`, 이벤트 종류, 진행 단계, 사유 코드와 시작 이후 경과 시간 `durationMs`를 함께 보낸다.

| 이벤트 | 의미 |
|---|---|
| `STARTED` | 초기화 시작. `DOCUMENT` 단계, 경과 시간 `0` |
| `READY` | SDK 초기화·파노라마 조회 성공 보고 |
| `FAILED` | 문서 준비, SDK 로딩·인증, 파노라마 조회 또는 초기화 시간 초과 |
| `CANCELLED` | 초기화가 끝나기 전 사용자가 닫거나 대상 단지를 변경함 |

`READY`는 외관을 제대로 식별했다는 의미까지 포함하지 않는다. 실패는 `DOCUMENT`, `SDK`, `PANORAMA` 단계와 정해진 사유 코드로 구분하며, 파노라마 조회 실패를 촬영 데이터 부재로 단정하지 않는다.

시도별 최초 시작 한 건과 최초 종료 한 건만 집계한다. 종료가 시작보다 먼저 도착하는 것도 허용한다. 같은 시도의 재전송이나 다른 종료 결과가 나중에 도착하면 최초 결과를 유지하고 `204`로 응답한다. 같은 `attemptId`에 다른 단지나 정책 버전이 들어오면 `409`로 거부한다.

정책이 변경되거나 비활성화된 뒤에도 이미 시작된 시도의 결과는 수집한다. 정상 초기화 이후의 이동·회전·확대·일반적인 닫기는 초기화 결과에 포함하지 않는다.

이벤트 POST에는 기존 `GET /api/auth/csrf`에서 받은 토큰과 `headerName`을 사용한다. **이벤트 전송 실패가 거리뷰 표시를 막아서는 안 되며, FE는 자동 재전송하지 않는다.**

이벤트는 영구 DB 테이블에 저장하지 않고 Micrometer 지표와 구조화 로그로 관측한다.

- 지표에는 시작·성공·실패·취소 횟수, 초기화 시간, 중복과 수집 거절을 기록한다.
- 최초 실패 로그에는 시도 ID, 단지 ID, 정책 버전, 단계, 분류된 사유와 소요 시간을 기록한다.
- 지표 label에는 종류·단계·사유처럼 값의 종류가 제한된 항목만 사용한다.
- SDK 오류 원문, 키, URL, 좌표와 회원 정보는 이벤트 요청과 로그에 포함하지 않는다.

공개 수집 API가 서버 자원을 과도하게 사용하지 않도록 다음 상한을 적용한다.

| 대상 | 상한 | 초과 응답 |
|---|---|---|
| 요청 본문 | 4 KiB | `413` |
| 요청량 | 프로세스당 초당 20건, 순간 허용량 100건 | `429` |
| 중복 판별 정보 | 최초 수신부터 10분, 최대 10,000개 시도 | 신규 시도 수용 불가 시 `503` |

중복 판별과 요청 제한은 프로세스 단위다. 재시작, 다중 인스턴스, 보관 기간 만료에 따른 중복 집계가 가능하다. 브라우저 종료나 네트워크 문제로 이벤트가 누락될 수도 있으므로 결과가 오지 않은 시도를 성공이나 실패로 추정하지 않는다. 이 지표를 정확한 과금 집계나 자동 기능 차단의 근거로 사용하지 않는다.

**장애는 실행 정보 조회, 브라우저 초기화, 이벤트 수집을 구분해 확인한다.**

| 장애 구간 | 확인할 근거와 대응 |
|---|---|
| 실행 정보 조회 실패 | HTTP 오류와 `traceId` 확인. 정책 누락이면 마이그레이션과 정책 행 확인 |
| SDK 초기화·조회 실패 | 실패 이벤트의 단계·사유와 구조화 로그 확인 |
| 이벤트 수집 실패 | 수집 거절 지표와 제한 상태 확인. 거리뷰 표시는 독립적으로 유지 |

거리뷰 제공을 중단하거나 재개할 때는 관리자 API로 현재 정책과 버전을 조회한 뒤 사유를 포함해 변경한다. 변경 후에는 공개 실행 정보와 감사 이력으로 적용 결과를 확인한다.

최초 활성화 전에는 대상 환경에서 SDK 인증, 실제 영상 표시, 초기 방향, 실패 안내, 팝업 종료 후 기존 지도·상세 유지가 확인되어야 한다. 정책을 활성화하는 API의 성공과 실제 거리뷰의 정상 표시는 각각 확인한다.
