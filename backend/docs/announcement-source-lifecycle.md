# Announcement Source Lifecycle

## 정책

- 마이홈 공고 수집 한 번에 UUID 형식의 `runId`를 하나 발급한다.
- 조회된 원천은 `lastSeenRunId`와 기존 `collectedAt`을 마지막 확인 실행과 시각으로 기록한다.
- 모든 공급유형의 전체 페이지가 성공한 실행만 미조회 횟수를 증가시킨다.
- 한 번 미조회된 원천은 활성 상태를 유지하고, 두 번 연속 미조회되면 비활성화한다.
- 비활성 원천이 다시 조회되면 활성화하고 미조회 횟수를 0으로 초기화한다.
- 비활성화는 원천과 정제 공고를 삭제하지 않으며 과거 공고 상세 조회를 유지한다.
- LH 상세·공급의 성공 원천은 마지막 실제 수집 성공 시각을 보관한다. 일반 수집은 대상 요청을 매 실행 실제 조회한다. 종료 후 30일을 초과한 공고는 제외하고, 날짜가 없거나 해석되지 않으면 포함한다. 공고별 재조회는 오래된 종료 공고도 조회한다.
- 같은 실행의 공유 요청은 한 번 조회하며 공고별 연결을 저장한다. 연결만 추가하는 작업은 실제 원천 수집 시각과 성공 수집 기록의 시각을 연장하지 않는다.
- 조회 조건이 바뀌면 새 요청으로 수집하고, 성공 후 공고별 LH 연결을 갱신한다.
- 실패한 공유 요청은 같은 실행에서 반복하지 않고 다음 실행에서 다시 조회한다. 기존 성공 원천과 연결은 보존한다.
- 원천 행과 성공 수집 기록은 같은 트랜잭션에 저장하고, 공고별 LH 링크는 성공 원천이 확보된 뒤 기록한다. 링크 기록 실패 시 성공 원천은 보존하며 다음 실행에서 다시 수집하고 연결을 복구한다.

매핑·보강의 연결 일치 기준과 기존 데이터 전환은 [LH 공고 연결·복구](lh-announcement-link-resolution.md)를 따른다.
비활성 원천과 공통값 선택은 2026-09-26 이후 현재 원천 선택 로직이 변경됐다. 현재 판단과 운영 재검증의 한계는 [ingest 전체 흐름 재검토](ingest-flow-review.md)를 따른다.

## 스키마 배포

현행 원천의 생명주기 컬럼과 완료 실행 테이블은
`V20261004_06__source_import_metadata_and_announcement_lifecycle.sql`이 생성한다.
대상은 `myhome_announcement_source_rows`의 `last_seen_run_id`,
`consecutive_miss_count`, `active`와
`myhome_announcement_lifecycle_runs(execution_id, completed_at)`다.

구 원천 폐기와 ID 보존, 낮은 버전 누락 보충은
[수집 저장 구조 전환 절차](ingest-branch-db-upgrade.md)를 따른다.
구 원천 테이블을 삭제한 뒤에는 이전 앱만 재배포할 수 없다.
복구는 쓰기를 차단한 상태에서 새 버전의 수정 배포 또는 백업 DB 복원과 해당 앱의 재기동으로 진행한다.
