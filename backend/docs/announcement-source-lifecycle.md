# 공고 원천 관리

목록에서 사라진 공고도 원천·제품을 삭제하지 않는다. 과거 공고 상세는 계속 조회할 수 있다.

## 마이홈 활성 상태

**모든 공급유형의 전체 페이지가 성공한 실행에서만** 미조회 횟수를 늘린다.

| 조회 결과 | 원천 상태 |
|---|---|
| 한 번 미조회 | 활성 유지 |
| 두 번 연속 미조회 | 비활성화 |
| 비활성 원천 재조회 | 활성화, 미조회 횟수 초기화 |

## LH

### 목록

`POST /api/admin/ingest/lh/announcements/catalog`는 관리자 세션·CSRF로 LH 목록만 갱신한다. 제품 등록·정제는 실행하지 않는다.
전체 페이지를 검증하고 목록·성공 기록을 함께 저장한다. 실패·불완전한 응답이면 기존 목록을 보존한다.
신규·변경·미변경 수는 `ingest.announcement.catalog.rows`의 `change` 태그로 확인한다.

### 공급·상세 조회 대상

| 종료일 | 일반 수집 |
|---|---|
| 진행 중·종료 후 30일 이내 | 포함 |
| 날짜 없음·해석 불가 | 포함 |
| 종료 후 30일 초과 | 제외. 공고별 재조회 가능 |

대상 요청은 매 실행 실제 조회한다. 종료 후 30일은 자동 실행 주기가 아니라 대상 범위다.
공유 요청은 500행 배치를 넘어도 같은 실행에서 한 번 조회하고 공고별 연결을 저장한다.

### 저장

원천·성공 기록을 한 트랜잭션으로 저장한 뒤 공고 연결을 반영한다.

| 결과 | 처리 |
|---|---|
| 성공 | 같은 응답도 검증 후 실제 성공 시각·기록 갱신 |
| 연결만 추가 | 원천·성공 기록의 시각 유지 |
| 실패·불완전 응답 | 기존 성공 원천·시각·연결 보존, 실패 기록 추가 |
| 연결 기록 실패 | 성공 원천 보존, 다음 수집에서 재조회·복구 |

공유 요청의 실패는 같은 실행에서 반복하지 않는다. 다음 실행에서 다시 조회한다.
응답 검증·누락 보호·연결 일치는 [LH 연결과 복구](lh-announcement-link-resolution.md)를 따른다.
배포·이관·복구는 [수집 DB 전환](ingest-branch-db-upgrade.md)을 따른다.
