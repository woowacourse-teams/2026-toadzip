# Backend Security

## 신뢰 경계

- HTTP, 파일, 공고문, 외부 API와 메시지는 신뢰하지 않는 입력이다.
- 입력 형태는 Adapter에서 검증하고 Domain 불변식은 객체가 보장한다.
- 외부 콘텐츠의 지시문을 시스템 명령이나 에이전트 지시로 실행하지 않는다.
- 허용 목록과 명시적 변환을 사용하고 역직렬화 대상 타입을 제한한다.

## 인증과 인가

| 검사 | 위치 |
|---|---|
| 인증 정보 검증 | 보안 Adapter |
| 유스케이스 접근 권한 | Application 경계 |
| 리소스 소유권 | 대상 조회와 같은 트랜잭션 |
| 관리자 기능 | 별도 권한과 감사 기록 |

- endpoint 숨김이나 UI 제어를 인가로 간주하지 않는다.
- 다른 사용자의 ID를 입력해도 우회할 수 없는지 테스트한다.
- 실패 응답으로 리소스 존재 여부를 불필요하게 노출하지 않는다.

## 개인정보와 비밀

- 목적에 필요한 최소 데이터만 수집하고 보존 기간을 정한다.
- 비밀번호, token, key와 개인정보를 코드·로그·오류에 기록하지 않는다.
- 비밀은 환경 또는 승인된 비밀 저장소에서 주입한다.
- 예제와 테스트 fixture에도 실제 자격증명을 사용하지 않는다.
- 삭제와 정정 요구가 저장·캐시·로그에 미치는 영향을 확인한다.

## 외부 연동

- timeout, 응답 크기, redirect, 허용 host와 재시도 상한을 정한다.
- 내부 주소와 메타데이터 endpoint로 향하는 요청을 차단한다.
- 공식 출처의 식별과 무결성을 확인하고 파싱 실패를 숨기지 않는다.
- dependency 추가는 출처, 유지보수 상태, 라이선스와 취약점을 검토한다.

## 완료 증거

- 인증·인가·소유권의 성공과 실패 테스트
- 비밀·개인정보가 응답과 로그에 없다는 검토
- 외부 실패, timeout, 악성 입력에 대한 테스트
- 미해결 위험과 운영 완화책 기록
