# 테스트와 검증

변경한 동작의 정상·실패 경로와 회귀를 검증한다. 구현 세부사항만 그대로 따라가는 테스트는 추가하지 않는다.

## 테스트 선택

| 변경 | 검증 |
|---|---|
| 도메인 규칙 | 행위·불변식·경계값의 단위 테스트 |
| 유스케이스 | 상태 변화·실패 전파·외부 효과 |
| HTTP 계약 | 입력·권한·상태·오류 응답 |
| 쿼리·트랜잭션 | 실제 PostgreSQL의 매핑·제약·동시성 |
| 외부 연동 | 요청·응답·타임아웃·파싱 실패 |

버그는 가능하면 실제 증상을 먼저 재현한다. 시간·ID·외부 시스템은 제어 가능한 경계로 두되 실제 DB 동작을 mock으로 대신하지 않는다.
이름·단일 동작·Given-When-Then 기준은 [코드 컨벤션](../CODE_CONVENTION.md)을 따른다.

## 실행과 완료

가까운 테스트와 영향 기능을 먼저 확인하고, 백엔드 코드 변경 시 [기여 규칙](../../CONTRIBUTING.md#테스트-및-검증)의 전체 검사를 실행한다.
테스트 PostgreSQL은 검사 실패 여부와 관계없이 정리한다.

Gradle `check`에는 Java 스타일·계층 전용 검사기가 없다. 해당 변경은 컨벤션과 의존 방향을 직접 검토한다.
최종 diff에서 요청 범위·호환성·비밀 노출을 확인하고 `git diff --check`를 실행한다.
flaky test는 재실행 성공만으로 통과시키지 않는다.

실행한 명령·결과와 미검증 항목·이유를 보고한다. 환경 때문에 실행하지 못한 검사는 통과로 표시하지 않는다.
