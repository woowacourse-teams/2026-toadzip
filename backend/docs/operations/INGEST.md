# 수집 운영

`/admin/ingest`에서 수집·정제를 시작하고 진행·실패·이력을 확인한다.
서버 부팅·예약·장애 복구는 새 실행을 만들지 않는다. 시작·중지에는 관리자 세션과 CSRF 토큰이 필요하다.

## 실행

### 유형

`POST /api/admin/ingest/pipelines/{type}`으로 시작한다.

| `type` | 작업 |
|---|---|
| `complex-sync` | 단지 수집 후 정제, 4단계 |
| `announcement-sync` | 공고 수집 후 정제, 6단계 |
| `complex-collection` / `complex-refinement` | 단지 수집 / 저장 원천 정제 |
| `announcement-collection` / `announcement-refinement` | 공고 수집 / 저장 원천 정제 |

### 수집 인증키

수집·통합 유형은 선택 본문 `{ "serviceKey": "..." }`를 받는다. 생략하면 서버 설정키를 쓴다.
입력키는 이번 실행과 병렬 작업에만 사용하며 저장·응답·로그에 남기거나 다음 실행에 재사용하지 않는다.

- 본문이 있으면 키가 필수다. 공백뿐인 값과 4096자 초과는 400이다.
- 양끝 공백을 제거하며 원문·URL 인코딩 키를 모두 지원한다.
- 정제 유형에 키 본문을 보내면 `400 INVALID_INGEST_REQUEST`다.

### 진행량

진행률은 현재 수집 범위의 완료 대상 / 전체 대상이다. 실패 확정 대상도 완료로 세며 재시도는 중복 집계하지 않는다.
LH 공급·상세는 최대 500개 원천 행 묶음의 고유 요청 수를 센다. 전체 파이프라인의 진행률이 아니다.

`externalRequestCount`에는 실패·재시도가 포함된다. 최근 활동은 `lastRequestDescription`·`lastProgressAt`으로 확인한다.
총건수 불명·표본 부족·지연·중지 상태에서는 남은 시간을 표시하지 않는다.

### 중지

`POST /api/admin/ingest/pipelines/executions/{executionId}/stop`은 202와 상태를 반환한다.
`RUNNING + stopRequested=true`는 중지 대기다.

- 수집은 다음 요청·재시도 전에 중지를 확인한다. 진행 중 응답·저장은 마치고 병렬 작업 종료 후 잠금을 해제한다.
- 정제는 현재 단계를 마친 뒤 다음 단계를 막는다. 저장 원천·완료 보고서는 남기고 미저장 수집 버퍼는 버린다.
- 중복 요청은 같은 상태를 반환한다. 종료 결과는 바꾸지 않으며 실제 오류가 발생하면 `FAILED`로 남을 수 있다.

중지한 수집은 정제를 시작하지 않는다. 재실행은 새 실행이며 기존 작업이 끝나야 다른 수집·정제를 시작할 수 있다.

## 결과와 복구

### 상태

| 상태 | 의미 |
|---|---|
| `RUNNING` | 실행 중 |
| `COMPLETED` | 선택 작업 완료 |
| `COMPLETED_WARNINGS` | 정제·보강의 행별 누락이 남음 |
| `COMPLETED_WITH_SKIPS` | 호출 제한으로 건너뛴 단계가 있음 |
| `FAILED` | 운영 실패 또는 예상하지 못한 오류 |
| `STOPPED` | 관리자 중지 완료 |

누락과 건너뜀이 함께 있으면 `COMPLETED_WARNINGS`이며 두 보고서를 보존한다.
완료 상태가 모든 공고의 최신성·정보 충족을 뜻하지는 않는다.

### 실패 처리

운영 부분 실패는 후속 수집 단계를 한 번씩 수행한 뒤 최초 실패를 남기고 `FAILED`로 끝낸다.
예상하지 못한 오류는 즉시 중단한다. 같은 실행에서 실패 단계 전체를 다시 실행하지 않는다.

통합 실행은 수집 부분 실패·호출 제한에서 정제를 시작하지 않는다. 제한만 있으면 `COMPLETED_WITH_SKIPS`다.
호출 제한은 재시도하지 않으며 전국 병렬 수집의 대기 요청도 취소한다.

지오코딩 API·좌표 변환·저장 오류는 운영 실패다. 주소 불명·모호함·매칭 불가·원천값 오류는 행별 누락이다.
단지·공고 매칭 실패는 개별 이력에도 남지만 LH 주택형 누락은 단계 보고서의 건수로만 남는다.

### 실패 조회와 재실행

수집 실패는 요청 단위, 정제·보강 실패는 원천 행 단위다.
목록은 선택 분류 전체의 미해결 항목·이력이며 특정 실행의 실패만 모은 결과는 아니다.
단지·공고 매핑과 LH 공고 보강의 `/failures/page`, `/failures/history`는 `page=0`, `size=100`이 기본이며 최대 200이다.

결과의 **저장된 원천으로 단지/공고 정제 실행**은 새 정제 실행을 만든다.
이전 원천도 포함될 수 있으므로 수집 결과를 먼저 확인한다. 원래 실패 결과는 남는다.
단지 좌표는 [좌표 적재](HOUSING.md#단지-좌표), 공고 연결·금액은 [LH 복구](ANNOUNCEMENT_COLLECTION.md#복구)를 따른다.

### 서버 소실과 배포

heartbeat는 30초마다 갱신한다. 새 실행·상태 조회 시 잠금이 없고 2분 넘게 갱신되지 않은 `RUNNING`을 실패로 복구한다.
조회·새 실행이 없으면 자동 변경하지 않는다. 실행 소유권을 잃은 쓰기는 롤백하며 기존 쓰기가 끝나야 소유권을 이전한다.

새 실행 유형·소유권·`STOPPED`를 모르는 이전 서버와 혼합 실행하지 않는다. 기존 작업을 끝내고 서버·관리자 화면을 함께 교체한다.
이전 서버는 상태를 읽지 못하거나 실패 이력을 삭제할 수 있다. 롤백 전 이력을 백업하고 호환 처리가 없으면 수집을 중지한 채 새 버전을 복구한다.
실행·실패 이력은 자동 삭제하지 않는다. DB 전환은 [DB 운영](DATABASE.md)을 따른다.

### 실행 이력

`GET /api/admin/ingest/pipelines/history?page=0&size=20`은 관리자 세션으로 조회한다.
`page`는 0부터, `size`는 기본 20·최대 100이다.

## 원천 조회

### 요청

`GET /api/admin/ingest/sources`는 저장 행을 조회하며 데이터 변경·외부 호출은 하지 않는다.
관리자 세션이 필요하다.

| 쿼리 | 계약 |
|---|---|
| `category` | `MYHOME_COMPLEX`, `LH_LEASE_CATALOG`, `MYHOME_ANNOUNCEMENT`, `LH_ANNOUNCEMENT_CATALOG`, `LH_ANNOUNCEMENT_DETAIL`, `LH_ANNOUNCEMENT_SUPPLY` 중 하나, 필수 |
| `page`, `size` | 0부터, 기본 0·20. size는 1~100 |
| `keyword` | 이름·원천 식별자의 부분 검색, 최대 200자, 양끝 공백 제거 |

현행 원천의 활성·비활성 행을 모두 보여 주며 정제용 중복 제거는 적용하지 않는다.
수집 시각 내림차순 → ID 내림차순 → 원천 키 오름차순이며 미기록 시각은 마지막이다.
잘못된 쿼리는 `400 VALIDATION_FAILED`다.

### 응답

`data`에 `items`, `page`, `totalElements`, `totalPages`, `hasNext`를 담는다. 빈 목록·범위 밖 페이지도 전체 개수를 유지한다.

| 항목 | 의미 |
|---|---|
| `id`, `sourceKey`, `name` | 저장 행 ID·원천 식별자·이름. ID 중복은 원천 키와 함께 구분 |
| `sourceUrl`, `originalUrl` | 인증정보·query·fragment를 뺀 API 주소 / 공식 공고 원문, 없으면 null |
| `collectedAt`, `sourceUpdatedAt` | UTC 수집 시각 / LH 목록 변경 감지 시각. 미기록·해당 없음은 null |
| `raw` | 저장된 원천 항목. 수집 응답 전체가 아님 |

LH 목록의 `raw`는 저장한 `rawPayload`, 나머지는 저장 행의 snake_case 객체다.
LH 상세·공급의 `pan_id`·`request_hash`는 요청 묶음에서 보완한다. 상세의 첨부 URL은 `raw.url`이며 공고 원문으로 표시하지 않는다.
마이홈 원문 선택 순서는 `url` → `pc_url` → `mobile_url`이다.

`raw`의 소수와 JavaScript 안전 정수 범위(±9,007,199,254,740,991) 밖 정수는 중첩 값까지 문자열로 전달한다.
안전 범위 정수와 목록 DTO의 ID·페이지·개수는 숫자다.
