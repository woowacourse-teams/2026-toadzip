# 회원 알림 설정

회원은 단지·공고·지역 알림 설정을 이메일 입력 없이 저장한다. 현재 새 공고 알림 생성·전달과 FCM은 제공하지 않으며 프론트엔드에서 준비 중으로 안내한다.

- `GET /api/v1/notification-subscriptions/me`: 인증된 회원의 유효 설정 조회. 대상에 `targetType`, `targetId`, `targetName`을 제공한다. 지역 이름은 프론트 지역 카탈로그에서 해석하며 삭제된 대상 이름은 null일 수 있다.
- `POST /api/v1/notification-subscriptions/me`: 인증과 CSRF가 필요한 설정 변경. 기존 이벤트 요청 구조를 사용하며 `CONFIRMED`(저장)와 `CANCELLED`(해제)만 허용한다. 회원 ID는 인증 정보에서 얻는다.
- 변경 응답은 `200`과 `eventId`, `targetType`, `targetId`, `outcome`, `occurredAt`이다. 새 활성화는 `ACTIVATED`, 이미 활성 상태는 `ALREADY_ACTIVE`, 실제 해제는 `CANCELLED`, 해제할 설정이 없으면 `UNCHANGED`다. 같은 이벤트 재시도는 원래 결과와 시각을 반환하며 상태 변경을 반복하지 않는다.
- 이메일 없는 `CONFIRMED`는 설정만 저장하며 이메일 수신 동의나 푸시 권한으로 해석하지 않는다. 기존 이메일을 동반한 요청은 호환성을 유지한다.
- 기존 구독 테이블과 대상별 12개월 만료를 재사용한다. 별도 마이그레이션은 없다. 재시도는 같은 이벤트 ID를 사용한다.
- 삭제되거나 카탈로그에서 제외된 대상도 기존 설정을 해제할 수 있다.
- 기존 비회원 이메일 신청 API는 과거 신청의 호환성을 위해 남겨두지만 새 UI에서는 호출하지 않는다.

회원 UI는 `/mypage/notifications`에서 종류별 조회·해제, 알림 보관함은 PC 중앙 모달·모바일 하단 모달로 제공한다. 기존 `/notifications` 주소는 지도 위 보관함 모달로 연결한다. 비회원 직접 접근은 로그인 안내를 제공하고 목록을 표시하지 않는다.

알림 관리의 `전체 해제`는 조회한 단지·공고·지역 설정을 순서대로 해제한다. 처리 중에는 중복 요청을 막고, 실패한 설정은 목록에 남겨 재시도할 수 있다. 탭을 떠나면 남은 요청을 중단하고 복귀 시 현재 계정의 설정을 다시 조회한다.

모바일 하단은 회원 `단지 · 공고 · 알림 · 마이` 4칸, 비회원 `단지 · 공고 · 로그인` 3칸으로 균등 배치한다. 모바일 마이 메뉴에는 알림 관리·제보/의견 보내기·로그아웃을 제공한다.

보관함은 `받은 알림`과 `알림 설정` 탭을 구분한다. 받은 알림은 준비 안내 한 문장만 표시하고, 알림 설정에서는 등록 대상 조회·개별 해제·전체 해제를 제공한다. 마이 메뉴의 알림 관리는 설정 탭을 바로 연다.

## 개인정보 저장소 도입에 따른 파기 경계

개인정보 기능의 보유기간 배치는 신규 `privacy_` 자료만 처리한다. 기존 알림·이메일·취소 요청·행동 기록을 삭제하던 `NotificationRetentionService`는 제거한다. 기존 자료는 별도 운영 정책을 확정하기 전까지 소급 삭제하지 않는다. 사용자가 요청한 구독 취소는 기존 업무 API로 유지한다.
