# 백엔드 코드 컨벤션

`backend/src/main/java`와 `backend/src/test/java`의 Java 코드에 적용한다.
Google Java Style을 기본으로 사용하고 아래 프로젝트 규칙을 함께 따른다.

## 코드 스타일

### 표기와 들여쓰기

[Google Java Style Guide](https://google.github.io/styleguide/javaguide.html)를 따르되 다음 값을 사용한다.

| 항목 | 프로젝트 기준 |
|---|---|
| 블록 들여쓰기 | 스페이스 4칸 |
| 한 줄 길이 | 최대 120자 |
| 줄바꿈 들여쓰기 | 기존 줄보다 스페이스 8칸 이상 |

사용하지 않는 import와 삼항 연산자는 사용하지 않는다.
배열보다 컬렉션을 우선한다. `byte[]`, 가변 인자와 외부 API 연동은 예외다.

### 이름

역할을 알 수 있는 이름을 쓰고 축약하지 않는다.
`API`, `URL`, `ID`, `DTO`, `JPA`처럼 의미가 명확한 기술 용어는 허용한다.

## 객체 설계

객체지향 생활체조는 도메인·비즈니스 코드의 기본 설계 원칙으로 사용한다.
DTO, JPA, 프레임워크 연동과 테스트 준비에는 유연하게 적용한다. 예외 이유가 명확하지 않으면 PR에 근거를 적는다.

### 제어 흐름

- 메서드당 들여쓰기는 한 단계로 작성한다. 중첩 조건·반복은 빠른 반환과 메서드 추출로 줄인다.
- `else` 대신 빠른 반환, 예외 처리나 다형성을 사용한다.

### 값과 컬렉션

도메인 의미·검증 규칙이 있는 이름·제목·금액은 값 객체로 표현한다.
반복문 인덱스, 계산용 지역 변수와 DTO 값은 제외할 수 있다.
도메인 규칙·행위가 있는 컬렉션은 별도 클래스로 감싸고 컬렉션 외 상태를 두지 않는다.

### 객체의 책임

- 메서드는 한 가지 일, 클래스는 하나의 책임을 가진다. 메서드 10줄·클래스 50줄을 넘으면 분리를 검토한다.
- 도메인 인스턴스 변수는 두 개 이하를 지향한다. JPA Entity, Aggregate Root, DTO와 설정 객체는 예외로 할 수 있다.
- 한 줄에서 객체 내부를 연속 탐색하지 않고 행위를 요청한다. Stream, 빌더, 테스트와 프레임워크 DSL은 예외다.
- 무분별한 getter·setter 대신 객체에 행위를 요청한다. DTO, record, 직렬화와 JPA 연동은 예외다.

## 계층별 책임

| 계층 | 책임 |
|---|---|
| Controller | 요청 검증과 응답 변환 |
| Service | 유스케이스 흐름과 트랜잭션 |
| Repository | 데이터 접근 |

의존성은 생성자로 주입한다. Entity를 API 응답으로 직접 반환하지 않는다.
패키지와 허용 의존성은 [아키텍처](docs/architecture.md)을 따른다.

## 테스트

검증할 동작이 이름에 드러나게 작성하고, 한 테스트는 한 동작을 검증한다.
Given-When-Then 구조를 권장한다. 테스트 준비에는 객체지향 생활체조를 유연하게 적용할 수 있다.
